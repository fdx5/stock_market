# 직접 걷기: 동별 자전거와 외관 개선 (2026-10-28)

> 후속 작업: 차량·시점·조명과 최신 검증은 `walk-vehicles-lighting-2026-10-29.md`를 참조한다.
> 아래 건물 외관 설명은 당시 작업 기록이며 이후 건물 담당 세션의 구현으로 대체됐다.

현재 개발 중인 `frontend/src/walkmode`에 적용했다. 기존 `/walk` 진입·실내 탐험·개발 진입 제한은 유지했다. 운영 배포는 수행하지 않았다.

## 자전거

- 실내의 현관문/나가기/Esc를 통해 실외로 돌아오면 **그 동의 공동현관 앞**에 1대를 준비한다. 평형 선택 취소만으로는 공급하지 않는다. 동 이름을 키로 같은 대여 자전거를 재사용해 반복 방문 시 중복 생성하지 않는다.
- 건물 앞에 차량·나무가 있으면 출입구 주변의 비어 있는 위치를 찾는다. 빈 곳이 없으면 안전한 공간을 다시 확인한다.
- 단지 출구 쪽에는 공용 자전거를 3대씩, 최대 두 접근 지점에 배치한다. 출입구 POI 자료는 없어 **실측 도로와 아파트 동군의 외곽 범위가 만나는 지점을 출구 후보로 추정**한다. 실제 현장 출입구 위치를 검증한 것은 아니다. 장애물이 있는 칸은 비워 두므로 검증 장면에서는 총 3~6대였다.
- 가까이서 E 또는 타기 버튼으로 탑승한다. W/↑ 가속, A/D 또는 ←/→ 조향, S/↓/Space 제동, E/내리기 버튼으로 하차, V 시점 전환. 모바일은 왼쪽 스틱과 누르는 동안 작동하는 브레이크 버튼을 쓴다.
- 최고 60km/h(16.6667m/s), 단계적 가속, 타력 주행, 제동. 120Hz 이하의 이동 간격으로 건물·기둥·나무·움직이는/주차된 차량·다른 자전거와 충돌을 확인한다. 최고속에서도 충돌 검사 사이 이동은 14cm 이하이다. 물·미로딩 지면·현재의 500m 탐험 경계로 진입하지 않는다.
- 하차 위치도 검사한다. 막힌 곳에서는 즉시 정지하고 안전한 위치를 찾을 때까지 탑승을 유지한다. 내린 자전거는 해당 위치에서 다시 탈 수 있다. 원래 동을 다시 탐험하고 나오면 그 동 자전거를 출입구에 재배치한다.
- 탭 숨김/포커스 이탈/실내 전환 시 입력과 속도를 초기화한다. 타기·내리기·실내 복귀가 중복 렌더 루프를 만들지 않는다.
- 주행 중 바퀴·페달·다리가 실제 이동 거리에 맞춰 움직이고 조향 시 차체가 기운다. 속도계는 최대 10Hz로 변경된 숫자만 UI에 전달한다.

## 아파트·사용자 외관

- 걷기 화면의 아파트에 전용 **2048px PBR 색/법선/거칠기·금속성·차폐/야간 점등** 텍스처를 적용했다. 이 텍스처는 코드로 만든 원본 건축 자재·창호 표현이며 건물 사진을 덮지 않는다.
- 외벽의 무채색 편중을 줄이고 차분한 도장 색 구획·층간 줄눈·창 하부 풍화·알루미늄 창틀·커튼·유리의 다른 재질 반응을 추가했다. 도장 색은 가상 표현이며 현장의 실제 외벽 색을 수집·복원한 것은 아니다.
- 실측 외곽선·높이·층수를 유지한다. 근거리에는 돌출된 창틀·창대, 석재 하부, 모서리와 지붕 가장자리를 추가한다. 실제 도로·단지 URL·시세 데이터와 기존 드라이브 테마는 변경하지 않는다.
- 사용자 아바타에 눈·홍채·동공·눈꺼풀·눈썹·입술·귀·손가락을 추가하고, 의복의 섬유 법선·거칠기와 피부·머리카락의 반사를 조정했다. 기존 앉기/눕기/걷기와 자전거 전용 관절 자세를 함께 지원한다. 실사 인물 스캔 모델은 아니다.
- 벽 앞에서 3인칭 카메라 거리를 줄여 자전거 탑승 시 건물 내부를 보던 문제를 해결했다. UI 버튼 조작이 포인터 잠금을 다시 걸지 않게 했으며 속도계 갱신이 마우스 입력 초기화를 반복하지 않게 했다.

## 자원·검증

- 주차 자전거는 공용 지오메트리/재질의 인스턴싱 1회, 동시에 그리는 수는 가까운 64대 이내이다. 탑승 자전거의 이동 부품만 별도로 그린다.
- 외벽 보강은 공용 지오메트리와 인스턴싱을 사용한다. 하부/테두리 각 2048개, 근거리 창호 최대 4096개, 근거리 동 최대 32개로 GPU 자원을 제한한다. 화면 해상도나 기존 DPR 정책을 낮추지 않았다.
- 종료 시 자전거·외벽 텍스처·메시·재질·입력 리스너·애니메이션 루프를 해제한다. 회원·운영 DB의 저장·수정 기능을 추가하지 않았다. 검증은 새 브라우저 컨텍스트에서 진행했고 기존 DB나 저장 데이터를 삭제하지 않았다.
- `node frontend/scripts/test-walk-bicycle.mjs`: 속도 상한, FPS 독립 이동, 제동 우선, 충돌 간격, 입력 오류, 동별 중복 방지, 승하차·재탑승, 자원 한도, 출구 후보 검사 **10개 통과**.
- `frontend/scripts/check-walk-bicycle.py`: 실제 은마 단지에서 실내 진입 → 나가기 → 해당 동 자전거 탑승 → 이동/제동 → 하차 → 같은 동 반복 복귀를 검증했다. 모바일은 CDP의 실제 두 손가락 터치 입력으로 스틱 이동과 브레이크를 함께 확인했다. 페이지/셰이더 오류 0건.
- TypeScript 및 Vite 전체 빌드 통과. 결과는 `docs/walk-bicycle-measurements-20261028.json`에 기록한다.

성능은 Windows/Chrome headless WebGL2, RTX 3070(ANGLE D3D11)에서 가속·충돌 정지를 포함한 10초 구간을 측정했다. 휴대폰은 실제 기기 대신 같은 PC의 모바일 에뮬레이션이다. 이 결과로 모든 지역·기기나 기존 CPU 4배 감속의 50fps 미달까지 해결했다고 주장하지 않는다.
