# 직접 걷기(/walk) 1차 구현 — 2026-10-28

개발 프롬프트 `output/walk-mode-dev-prompt.md`(v2)를 기준으로 했다. 실외 걷기, 건물 진입, 실내 엔진과 상호작용을 하나의 흐름으로 동작하게 만들었고, 로컬에서 검증했다. 배포와 `?devwalk=1` 공개 해제는 사용자 승인 후 진행한다.

## 적용 내용

### 진입 (spec §3)
- `components/walkEntry.ts`: `developmentWalkEnabled`, `walkEntryUrl(id, at, hour, weather, back)`
- `ComplexHologram.tsx`: `.re-holo-flight-buttons`에 「🚶 직접 걷기」 버튼과 진입 함수만 추가했다. `?devwalk=1`일 때만 보이고, `sceneReady` 전에는 "준비 중"으로 표시된다.
- `App.tsx`: `/walk` 라우트(lazy)를 추가했다. BGM은 `/drive`처럼 유지하지 않는다.

### 실외 (`walkmode/game/WalkGame.ts`)
- 드라이브 게임의 타일 월드(`drivegame/world`)를 그대로 쓴다. 재질, 교통(IDM), 지형, 도로, IndexedDB 원자료 캐시를 공유하고, 렌더러는 페이지가 소유한다.
- 교통은 걷는 사람을 차체로 인식해 정지한다(`Traffic.setPlayer`).
- 공동현관은 타일 원자료(`drivegame` IndexedDB `raw`)에서 찾는다. 대상은 공동주택 6층 이상이면서 동 번호가 있는 건물이다. 남향 판상형의 북측 긴 변 중앙에 캐노피, 유리 양여닫이문, 인터폰, 동 번호 사인을 둔다.
- 공동현관 3m 이내에 들어서면 "○○아파트 29동에 들어가시겠습니까?"를 띄운다. 단지명과 동 번호는 VWorld 실데이터다.

### 진입 시 실시간 데이터 다운로드
- 연속지적도(LP_PA_CBND_BUBUN)에서 동의 PNU를 얻는다(JSONP, `walkmode/game/pnu.ts`).

  - 대장이 없으면 실거래 평형을, K-apt에서 세대수를 가져온다.
  - DB에는 쓰지 않는다. 메모리 TTL(1주, 실패 10분)만 사용한다.

### 성능 조치
- 해상도는 진입 시 한 번 정해 유지한다(DPR 최대 2, 드라이브 게임과 같은 정책). 동적 해상도는 쓰지 않는다.
- 셰이더:
  - 면광원 수를 28개로 고정해 평면과 무관한 프로그램을 만든다. 평형을 고르는 동안 1×1 대체 텍스처로 미리 컴파일한다(`prewarmInterior`).
  - 면광원 루프를 펼치지 않는 패치를 모든 조명 재질에 적용했다. 펼친 루프의 D3D 컴파일이 프로그램당 수 초 걸렸다. 실내 컴파일은 16.9초에서 0.5초가 됐다.
  - 컴파일 대상을 실제 그리는 선형 HalfFloat 타깃으로 맞췄다. 이전에는 화면용 변형을 헛컴파일했다.
- 해 그림자 맵은 문, 커튼, 냉장고 문이 움직일 때만 다시 그린다.
- 램프 재질은 방별 복제 대신 공유 재질과 셰이더 유니폼으로 처리한다. 커튼은 창당 원단별 메시 1개로, 문짝과 고양이 관절은 재질별 병합으로 줄였다. 드로우 수는 207에서 117이 됐다.
- 거울 반사, 방별 첫 프레임, 그림자와 AO 패스는 로딩 화면 뒤에서 미리 그린다.

## 2차 품질·성능 개선 (같은 날)

### 화질
- 간접광: 방(조명 구역)마다 램프와 창이 넣는 빛 Φ를 그 방의 표면적 S로 나눠 반사율 ρ로 되튕긴 양(Φ/S·ρ/(1−ρ), 일반 0.5, 욕실 0.65)을 셰이더 간접 조도에 더한다(`lightZones.ts` `zoneBounce`, 아래를 향한 면일수록 크게). 스위치·커튼·TV에 따라 매 프레임 갱신. 천장이 칙칙하던 문제 해결.
- 반사 프로브를 창 낮빛을 켠 뒤 촬영(이전에는 창 조명 0인 상태로 촬영됐다).
- 욕실 램프 목표 조도 0.5→0.3: 타일 과노출 해소.
- 거실 바닥(floorMain)에 박스 투영 반사(`boxProjected`): 창과 가구가 제자리에 비친다.
- 소파 쿠션·등받이·쿠션, 침구(이불·접힌 끝·러너·베개)를 상자에서 부푼 봉제 형상(`models.ts` `puff`, 솔기 꼬집힘·주름)으로 교체.
- 데모 창밖: 발코니 유리 띠와 슬래브 선이 있는 한국 아파트 입면, 동마다 다른 점등 패턴, 밤 점등 밝기 낮춤·밤 안개 어둡게.

### 성능 (CPU 4배 감속, 패스별 측정)
- 양면 반투명 재질(유리, 속커튼, 실외 마커)은 three가 앞뒤 두 번 그리며 매번 `needsUpdate`로 프로그램을 다시 고른다 → `forceSinglePass`. 프레임당 키 재계산 12회→0.
- GTAO가 장면을 법선 패스로 한 번 더 그리던 것을 본 패스 깊이 텍스처 재사용(법선은 깊이에서 복원)으로 교체: 3.0→0.46ms(4×). three r185 `GTAOPass`는 생성자에 depthTexture를 주면 `setGBuffer`에서 없는 타깃을 읽어 실패하므로, 만든 뒤 `setGBuffer`로 바꾸고 쓰지 않는 타깃을 해제한다.
- 불투명 정렬을 프로그램 기준으로 묶음(`setOpaqueSort`, 나갈 때 해제): 프로그램 전환마다 면광원 28개 유니폼을 다시 올리기 때문.
- 결과: 렌더 CPU 14.5→8.4ms(4×).

## 1차 측정 (Chrome headful, `--mute-audio`, Windows 11, RTX 3070, ANGLE D3D11, three WebGLRenderer(WebGL2), 화면 59Hz)

`scripts/measure-walk.py`가 84㎡ 모던 화이트 평면에서 모든 방을 키보드로 걷는다. 걷는 동안 스위치, TV, 커튼, 수전, 에어컨, 로봇청소기를 조작하며 약 190초 걸린다. 수치는 로딩을 제외한 걷기 구간만이다.

| 조건 | 출력 해상도(DPR) | 평균 fps | 최저 1초 fps | p95 / p99 (ms) | 최대 멈춤 (ms) | 로딩(실내) |
|---|---|---|---|---|---|---|
| 데스크톱 1600×900 | 1585×900 (1) | 56.9 | 56.05 | 18.1 / 18.5 | 18.9 | 2.3 s |
| 데스크톱, 같은 조건 이전 실행 | 1585×900 (1) | 56.7 | **17.1** | 18.2 / 18.6 | **76.9** | 2.3 s |
| 모바일 에뮬레이션 390×844 DPR3 | 780×1688 (2) | 56.9 | 56.1 | 18.1 / 18.5 | 19.4 | 2.6 s |
| 데스크톱 CPU 4배 감속 | 1585×900 (1) | 43.6 | **19.2** | 35.8 / 36.4 | 70.9 | 5.5 s |

- 59Hz 화면이라 상한은 약 57fps다(빈 페이지 rAF 17.6ms).
- 데스크톱 1×의 첫 실행에서 원인 미상의 한 구간 저하(최저 1초 17fps)가 있었다. 동작별 단독 재현과 재실행에서는 재현되지 않았다. 이후 긴 프레임을 위치와 방과 함께 기록하도록 했다(`stats().long`).
- **CPU 4배 감속에서는 50fps 기준 미달이다.** 렌더 CPU 11.4ms/프레임(4×)이 남은 병목이며, 드로우 수보다 패스당·프로그램당 고정 비용이 크다. 다음 과제로 남긴다.
- 실제 폰(Fold8, iPad)은 측정하지 않았다. 측정하지 않은 기기는 달성으로 보고하지 않는다.
- 실외 걷기는 측정 스크립트가 없다. 로딩 시간만 확인했다(은마 7~9초, 개포 5~6초, 첫 방문).

## 3차: 소리·물·냉장고·반려견·미니맵·TV·노트북 (같은 날, 사용자 요청 순)

- 실제 녹음 소리(BigSoundBank CC0, `public/3d/walk/sfx`, 출처 `public/3d/walk/SOURCES.md`): 변기 물내림, 세면대 수전(흐름 루프와 잠글 때 배수 꼴깍 소리), 주방 싱크, 욕조와 샤워(같은 녹음의 피치·필터 변형), 고양이 야옹 7종과 골골송, 개 짖음 6종(스피츠, 시바용으로 피치 낮춤)과 헥헥거림. 루프는 앞뒤 0.15초 패딩으로 디코더 지연과 무관하게 이어진다. 녹음이 오기 전이나 실패하면 기존 합성음을 쓴다. `Sound.running()`은 수전 종류별 채널이다.
- 변기 물내림 6.8초: 림 아래에서 내려오는 물막(`washMaterial`), 소용돌이와 거품, 사이펀으로 수위가 내려갔다가 다시 차오름. 세면대 등의 수전: 보이는 물줄기(명암·반짝임), 물보라(`splashMaterial`), 잠그면 배수 소용돌이.
- 카메라 튐 수정: 앉기·눕기·일어서기·시점 전환은 0.6~0.9초에 걸쳐 시선과 위치를 보간한다. 포인터 잠금 직후 두 번의 마우스 이동과 비정상적으로 큰 이동은 버린다(Windows Chrome 문제). 3인칭 카메라는 벽 앞에서는 빨리 당기고 천천히 놓는다.
- 냉장고(`interior/pantry.ts`): 유리 선반 3단, 도어 포켓 4칸, 통풍구, LED, 야채칸이 있다. 우유·콜라·사이다·맥주·케첩·사과·오렌지·바나나·후랑크소시지·케이크·계란 16개를 실물 크기로 만들었다. 각 물건은 메시 하나에 공용 재질 하나(정점색과 라벨 아틀라스)다. 냉장고 칸과 장바구니(식탁 끝, 식탁이 없으면 주방 바닥)에서 꺼내 손에 들고 원하는 칸에 넣는다. 도어 포켓에는 길쭉한 것만 들어간다. 위치는 `localStorage['walk.fridge.v1']`에 저장되고 다른 집 냉장고에서도 같은 자리에 보인다.
- 미니맵(`MiniMap.tsx`, M으로 숨김, 클릭하면 확대): 마스터룸, 서브룸1·2, 거실, 주방, 화장실1(공용)·2(안방), 드레스룸, 다용도실, 현관, 복도, 문과 창, 내 위치와 시야, 반려동물 위치를 표시한다.
- 반려동물: 시바견이 기본이고 평형 선택 화면에서 고양이로 바꿀 수 있다(`localStorage['walk.pet']`). 시바견은 셸 털(`interior/fur.ts`, 정점별 두 색 혼합, 알파 커버리지)로 그린다. 머리는 하나의 조각 메시(두개골·스톱·주둥이·볼)이고, 우라지로 무늬, 흰자가 보이는 눈, 무릎 관절이 있는 앉기, 등 위로 말린 꼬리를 넣었다. 사용자 참고 사진(카보스)에 맞춰 여러 차례 다듬었다. 짖기·헥헥거림·꼬리 흔들기, 달리면 따라오기도 넣었다.
- TV: 켜면 TV 화면 위에 유튜브 앱이 그대로 나온다(3D 화면 네 모서리에 CSS 호모그래피로 맞춤, 벽에 가리거나 뒤를 보면 숨김). 목록은 사이트의 `/api/editorial/videos`(국내·해외 각 20개)이고, 재생은 youtube-nocookie 임베드다(youtube.com 자체는 iframe을 거부). "확대"는 카메라가 TV 앞으로 다가가고, "전체화면"은 브라우저 전체화면이다. 자동재생 음소거 대비로 플레이어 API에 음소거 해제·볼륨 100을 보내고, 소리 버튼을 따로 뒀다. 방 TV에는 재생 중인 영상 썸네일이 비친다.
- 노트북: 작은 방 책상 위에 맥북 형태(실버 유니바디, 검은 키보드, 트랙패드, 사과 아이콘)를 덮어 둔다. 열면 덮개가 열리며 사과에 불이 들어오고, 화면에 `https://cattower.code404.app/?debug=1&playShopKey=1`이 실행된다. TV와 같은 2단계(확대 → 전체화면)이고, 확대하면 키보드 입력이 게임으로 간다.
- 개발 서버 프록시에 `/api/editorial`(`EDITORIAL_API_TARGET`)을 추가했다. 운영은 같은 출처라 영향이 없다.
- 평면도: 공개 자료에 평면도가 없어 모든 단지가 면적 기반 추정 평면이다. 평면도가 있는 단지를 평면도대로 만드는 기능은 없다(`source: "licensed_plan"` 자리만 있다).
- 남은 일: 실외(밝기, 위성사진·실측 기반의 동네 디테일)는 이번에 하지 않았다. CPU 4배 감속 50fps 미달 상태는 그대로이고, 시바견 근처는 41~43fps다.
- TV 검색: `GET /api/editorial/youtube/search?q=`(`services/youtube_search.py`). 서버에 `YOUTUBE_DATA_API_KEY`가 있으면 Data API를 쓰고, 없으면 youtube.com 공개 검색 페이지를 읽는다. 메모리 캐시는 10분(실패 1분)이고, DB에는 쓰지 않으며 키와 URL을 로그에 남기지 않는다. 테스트는 `tests/test_youtube_search.py`. 운영(클라우드 IP)에서 공개 페이지 경로가 막히는지는 배포 후 확인한다.
- 강아지: 쓰다듬으면 5분간 짖음과 헥헥거림을 멈춘다. 짖음은 최소 10초 간격이다. Z(모바일은 버튼)로 앉아서 카메라를 보는 강아지를 가까이 볼 수 있다.

## 4차 (10-28 밤 ~ 10-29 새벽): 실외 극사실화·교통·실내 다양화

미커밋·미배포. 검증 스크립트는 세션 scratchpad(od2h.py, stream.py, perf1.py, han2.py, flats.py, styles.py, gait.py, npc.py, tvmenu.py)에 있다.

### 근본 원인 수정
- 건물이 하얗게 뜨던 원인: 환경맵을 만드는 하늘 셰이더에 태양 원반(하늘의 19000배)이 들어가 그늘진 벽의 간접광이 1.0을 넘었다. 태양 원반을 뺀 하늘과 지면 반사 원판으로 환경맵을 만들고, 해:그늘 약 4:1로 조명을 다시 맞췄다(WalkGame.setupSky).
- 차가 한 대도 없던 원인: `traffic.update(..., () => true)` — "시야 안"을 늘 참으로 넘겨 생성이 막혔다. 카메라 frustum 판정으로 바꾸고 로딩 뒤에 25초 사전 시뮬, 70대, 정체 해소 옵션(`Traffic.unstick`, 걷기만 20초)을 넣었다. 60초 동안 움직이는 차 51→11대로 굳던 것이 42대까지 회복된다.
- 인도가 솟구치던 원인: 도로변 보도 띠에 항공 지면과 드라이브 인도가 두 높이로 겹쳤다. 패치 안 드라이브 인도는 셰이더로 잘라내고(GroundStream.maskInPatches), 보도는 도로 높이+12cm에서 6m에 걸쳐 지형으로 잇는다(높이차 3m 넘으면 교량으로 보고 제외).
- 강 위에 아스팔트가 깔리던 원인: 항공사진 분류가 어두운 수면을 아스팔트로 읽었다. `World.wetAt` 칸은 지면 패치에서 뺀다.
