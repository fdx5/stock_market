사용자가 확인한 워크스페이스 월 누계 29 GB와 위 서비스 지표의 차이는 확정하지 않았다.
기존 Uvicorn 로그에는 응답 바이트가 없으므로 과거 누계의 경로별 비율을 확정할 수 없다.
정적 파일이 전체 29 GB를 차지했다고 주장하지 않는다.

## 확인된 낭비

1. 기존 CDN 스크립트는 일부 폴더의 8 KiB 이상 파일만 포함했다. 작은 JSON·이미지,
   네온 테마 파일, 후원 QR 등이 누락됐으며, `/assets` StaticFiles 마운트는 CDN 로직을
   아예 거치지 않았다. 00:30 UTC 로그 표본에서도 페이지 재진입과 JS·CSS 재요청을 확인했다.
2. JSON ETag 미들웨어가 GZip 미들웨어 바깥에 있었다. 압축된 바이트를 JSON으로 읽지
   못하고 gzip 헤더의 시각까지 해시해 동일한 데이터의 검증값이 계속 달라졌다.
   운영 `/api/investor/indices`를 gzip으로 2초 간격 조회했을 때 압축 해제한 본문이 같아도
   ETag가 다르고 조건부 요청이 200으로 다시 전체 본문을 반환했다.
3. 시세 티커·지수·종목 화면·최근 종목 등은 5초마다 요청했다. 조사 시 티커 응답은
   gzip 약 37 KB였다. 이 크기를 매번 다시 받는 경우 활성 탭 하나만으로도 시간당
   약 26.8 MB가 된다(720회 × 37,160바이트; 실제 시간별 수치는 데이터에 따라 다름).
4. standard 인스턴스는 절전되지 않는데도 CI가 30분마다 전체 맵과 기본 종목 등을
   자동 호출했다. 주요 원인으로 단정하지 않지만 불필요한 상시 전송이다.

유튜브 음악은 `deskBgmStore.ts`에서 `youtube.com/embed`를 직접 사용한다.
음원 스트리밍은 브라우저와 유튜브 사이의 트래픽이며 Render를 중계하지 않는다.
`/bgm/*.json` 이퀄라이저 보조 데이터는 별도의 정적 파일로 이번 이관에 포함한다.

## 반영

- GitHub Pages 자산 대상 1,157개 → 4,821개, 약 354.17 MiB.
  JS·CSS·WASM·공개 이미지·영상·오디오·JSON·테마 파일을 포함한다.
- 기존 파일을 제거하거나 덮어쓰지 않는 콘텐츠 주소/빌드별 경로로 게시한다.
  운영 서버는 로컬 파일 해시가 게시 명세와 일치할 때만 CDN으로 보낸다.
- ES 모듈의 상대 의존성 경로를 같은 빌드 폴더에 보존한다.
  24개 Worker는 같은 출처의 작은 import 진입점으로 시작하고 구현은 GitHub에서 받는다.
  공개 문서의 상대 링크는 원래 사이트를 기준으로 유지한다. Canvas 이미지에 CORS를 설정한다.
- 압축 전에 원본 JSON으로 ETag를 만든다. 변경 없음은 304, 실제 데이터 변경은 200이다.
  공개 JSON은 재사용 전 검증하며 관리자·인증·쿠키 설정·private 응답은 공개 검증 대상에서 제외한다.
- 기존 5초 API 갱신을 공통 10초 상수로 변경한다. 첫 조회는 즉시 수행한다.
  관리 아틀라스 기본값도 10초로 변경한다. 관리자 작업 패널은 숨겨진 탭에서 주기 호출을 쉰다.
- 정기 keep-alive/cache warmup CI를 중지하고 수동 실행만 유지한다.
- 압축 후 HTTP 본문 바이트와 WebSocket 전송 바이트를 메모리에서 제한된 경로 단위로 집계한다.
  60초 요약 로그와 관리자 아틀라스 snapshot에 제공한다. 쿼리·본문·IP·인증정보는 기록하지 않는다.
  HTTP 헤더와 서버가 시작한 외부 통신은 이 계측에 포함되지 않아 Render 총계와 같지 않다.
- Docker가 lockfile 기반 `npm ci`를 사용해 게시 파일과 운영 빌드의 의존성을 맞춘다.

## 게시 순서

1. `frontend`에서 `npm ci` 및 `npm run build`.
2. `python scripts/publish_static_assets.py <kospimap-assets checkout>`.
3. 자산 저장소 push 후 GitHub Pages 응답 및 명세의 SHA-256/CORS 확인.
4. 앱과 CDN 명세를 함께 push해 운영 배포. 명세와 다른 파일은 원래 서버에서 제공한다.
5. 운영 응답의 CDN 경로, 조건부 304, health, egress-window 로그 확인.

DB 및 저장 데이터의 삭제·초기화·직접 정리는 수행하지 않는다.
변경 전후 방문량이 다르므로 배포 직후 짧은 관측으로 월 절감률을 확정하지 않는다.
