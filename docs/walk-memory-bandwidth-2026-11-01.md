# 내부 탐험·원본 도면·가전 개선 검증

## 변경

- 영천동이 서울 영천동으로 먼저 해석돼 동탄 단지를 놓치는 검색을 재현했다. 단지명 단독 재검색과 실제 법정동·위치 확인을 추가했다. 행정코드 차이는 공급자의 좌표·법정동 근거가 있을 때만 인정하고 아파트/A02 오피스텔 목록을 구분한다.
- 엔진 `orthogonal-area-10`: 흰 욕조/위생기구 구간을 이웃 방으로 잘못 분류해 욕실 안에 가짜 문을 만들던 원인을 수정했다. 원본 벽·바닥 검증을 통과했으나 치수와 면적 계산만 충돌한 경우 원본 픽셀 구획을 보존한 단일 전용면적 축척을 적용하고 추정임을 표시한다. 평균 도면을 사용하지 않는다.
- 가까운 면적의 A/B/C형 선택이 비동기 분석 중 되돌아가지 않도록 이전 분석 응답을 차단하고 실제 선택 주택형과 분석 주택형을 대조한다.
- 평형 선택은 전체 시군구의 20년 거래 이력을 읽거나 추가 수집을 요청하지 않는다. 기존 거래 상세 화면의 이력 조회는 유지한다.
- 공통 캐시의 보유 값은 128MiB, 최근 거래 캐시는 압축 24MiB, 과거 거래는 압축 16MiB로 제한한다. 주변 지리 16MiB, 건물/세대 자료 각 8MiB 제한도 적용한다. 지역 자료는 4개씩 읽고 큰 지도 구성은 한 번에 하나만 실행한다. 저장 DB를 변경하는 작업이 아니다.
- 도면 분석은 한 건씩 별도 프로세스에서 실행·종료한다. 두 판독 후보의 큰 이미지 버퍼가 재귀 호출로 동시에 살아 있지 않게 했다. 런타임 native allocator/연산 스레드 수도 제한한다.
- 브라우저의 실패·취소·퇴장 시 ImageBitmap을 명시적으로 회수한다. 원본 출력 해상도·픽셀 비율은 유지한다.
- GitHub Pages에 8KiB 이상 정적 자산 1,156개, 약 310.9MiB를 연결한다. 새 파일은 내용별 객체 주소로 보관하고 기존 공개 파일도 보존한다. 로컬 바이트가 manifest와 일치하는 경우만 GitHub로 전달한다. 공개 파일 3개의 SHA-256·CORS·HTTP 200을 확인했다.
- 에어컨은 스탠드/벽걸이/천장형 각 4종, 실제 형상 12종으로 확대했다. 설치 점유 크기와 창/통로를 확인하고 벽걸이 공간이 부족하면 천장형을 쓴다. 기존 64개 구성 선택에 별도의 `가구·가전 랜덤 변경`을 추가한다.

독립 재현은 Windows/psutil이며 캐시는 합성 공개 스키마 자료, 분석은 동일한 실제 원본 2개를 사용했다. 운영 전체 메모리의 감소율과 동일한 수치라고 주장하지 않는다. 운영 이전 지표는 2GiB 제한 중 약 2.116GB까지 접근했고, 배포 직전 20분 최고는 2,011,316,200B였다. 운영 배포 후 관측과 전송량은 후속 기록으로 추가한다.

백엔드 135개 검증, TypeScript와 운영 빌드, 텍스처 생명주기, 에어컨 12종 형상·범위, 원본 재시도/가까운 면적 수동 선택 6개 브라우저 검증을 통과했다. 실제 원본 API를 쓰는 로컬 동탄 6개 주택형 진입과 랜덤 가구 구성 적용 후 세 단지 진입을 확인했다. Chrome 음소거·RTX 3070·DPR 1 조건이며 FPS/원본 정확도를 전국·전체 장비로 일반화하지 않는다.
