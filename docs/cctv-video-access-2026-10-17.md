# CCTV 영상 재생에 필요한 신청과 확인 결과

DATA.GO.KR 가입, 다른 API의 인증키 보유, CCTV 영상 이용 승인은 별개다.
사용자가 제공한 ITS 키는 메모리에서만 사용하여 실제 조회와 영상 재생을 검증했다.
운영 서버의 비밀 설정에 등록한 것은 아니다. 운영 중인 a5133d1에는 CCTV
API가 아직 포함되지 않았다. 개발 기능을 운영 영상 재생 완료로 보고하지 않는다.

## 필요한 신청

| 범위 | 신청처 | 신청 항목 |
|---|---|---|
| 도심·지자체 공개 교통 CCTV | [UTIC 개방데이터 신청](https://www.utic.go.kr/guide/newUtisDataWrite.do) | CCTV 데이터 |
| 고속도로·국도 CCTV | [ITS 오픈데이터](https://its.go.kr/opendata/opendataList?service=cctv) | CCTV 화상자료 인증키 |

[DATA.GO.KR 경찰청_교통 CCTV 영상 정보](https://www.data.go.kr/data/15148511/openapi.do)는
기관 자체 UTIC 신청을 안내하는 LINK 유형이다. 위치·설치 정보만 제공하는
[전국CCTV표준데이터](https://www.data.go.kr/data/15013094/standard.do)와 구분한다.
카메라 위치가 공개되어 있어도 그 영상이 공개된다는 뜻은 아니다.

신청 목적 예시:

> kospimap.com 웹서비스의 전국 지도와 3D 드론뷰에서 공개 교통 CCTV의
> 위치·명칭과 실시간 영상을 연동하여 교통상황을 안내하고, 클릭 팝업으로
> 영상을 재생하며 제공기관 출처를 표시합니다.

UTIC는 신청 IP 인증을 사용한다. Render 서비스의 Connect → Outbound에 표시된
서버 발신 IP 범위를 확인해야 한다. 사용자의 PC IP나 웹사이트 수신 IP로 대체할
수 없다. 여러 범위의 허용 여부는 UTIC에 확인해야 하며, 미확인 IP를 추측해
신청 정보로 제공하지 않는다. [Render 공식 문서](https://render.com/docs/outbound-ip-addresses)

사용자가 확인한 Render 발신 범위는 `74.220.48.0/24`, `74.220.56.0/24`다.
두 대역 모두 허용 등록이 필요한지 UTIC 담당자에게 문의한다. 신청 폼 한 칸의
복수 CIDR 입력 문법은 확인되지 않았다. Render Dedicated IP도 세 IP 중 하나가
발신하므로, 단일 IP만 허용하는 조건의 해결책으로 단정하지 않는다.

키 원문은 채팅, 소스, 브라우저 환경 변수에 넣지 않고 호스팅 비밀 설정으로
등록한다. ITS 어댑터는 ITS_CCTV_API_KEY(또는 ITS_API_KEY)를 읽는다.
UTIC는 승인된 제공 URL·자료 형식·IP 조건을 받은 후 실제 어댑터를 연결해야 한다.

## 이번 재조사와 수정

- 공개 ITS `test` 샘플의 영상 2곳은 401이었다. 이는 실제 승인 키를 사용한
  운영 API 검사 결과가 아니므로, 모든 CCTV 영상이 고장이라고 일반화하지 않는다.
- 영상 없는 위치 정보 수백 건 때문에 실제 영상 카메라가 목록/모델 제한에서
  사라지는 버그를 재현하고 수정했다. 영상이 있는 카메라를 먼저 유지한다.
- 팝업을 열거나 재연결할 때 서버의 5분 캐시까지 갱신하여 짧게 유효한
  영상 주소를 다시 받도록 수정했다.
- 키 미설정, 공개 샘플 키 사용, 제공기관 401/403을 빈 목록 성공과 구분했다.
- 격리된 백엔드 테스트 17개와 프런트엔드의 영상 우선순위·서버 재연결 검사가
  통과했다. 이 테스트는 실제 영상 재생 성공의 증거로 사용하지 않는다.

## 승인 ITS 키로 실제 재생 확인

- 성남 주변에서 실제 HTTPS HLS 카메라 25곳을 조회했다. 일부 도로 유형 조회가
  실패한 `partial` 상태였으며, 서울 조회의 빈 결과까지 전국 성공으로 일반화하지 않는다.
- 실제 제공 영상은 `cctvsec.ktict.co.kr`의 HTTPS 8082 포트로 리다이렉트한다.
  기존 중계 코드가 이를 거절하여 영상이 막혔다. 이 호스트의 HTTPS 8082만
  추가 허용하고, 임의 호스트의 해당 포트는 계속 거절한다.
- 실제 HLS 목록과 약 804 KB 영상 조각이 HTTP 200으로 중계됐다.
- 음소거 Chrome, 1920×1080 화면 / 3840×2160 high 렌더링에서
  `[용인서울선]고등IC 램프` 영상을 기존 작은 팝업으로 재생했다.
  재생 시간 0.89→8.43초, 디코딩 프레임 31→257, 영상 720×480이었다.
  팝업 종료 시 video 요소 제거 및 앱 JS 오류 0건을 확인했다.
- 이 검증은 로컬 UI와 독립된 읽기 전용 테스트 서버에서 실제 제공 영상을
  사용했다. 운영 HTTPS 도메인 재생이나 배포 완료를 의미하지 않는다.

## UTIC 원본 플레이어 팝업 검증

사용자 요청에 따라 서버 영상 중계 대신 UTIC 원본의 영상 부분을 iframe으로
넣는 방식도 실제 Chrome에서 검사했다. 공개 지도에서 사용하는
`/jsp/map/cctvStream.jsp` 형식의 페이지를 외부 사이트 프레임으로 열면
`비정상적인 접근입니다.` 경고가 발생하고 video 요소가 없었다.
주소만 복사하면 인증 없이 재생된다고 보고하거나, 이 제한을 우회하지 않는다.
공식 홈페이지 전체를 별도 창에서 여는 것과 특정 CCTV 영상만 재생하는 것은
검증 결과가 다르다. UTIC 도시 영상에는 승인된 외부 재생 URL/키/IP 조건의
확인이 남아 있다. [공식 영상 레퍼런스](https://www.utic.go.kr/guide/utisRefCctv.do)
