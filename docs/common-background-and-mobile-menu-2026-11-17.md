# 공통 배경 최적화와 휴대폰 메뉴

## 변경 범위

- 공통 TYPE 1(네온 구조물)·TYPE 2(실크 흐름)를 지원 브라우저에서 OffscreenCanvas
  워커로 렌더링한다. GPU 컨텍스트 생성·셰이더 준비·그리기를 UI 스레드에서 분리한다.
  미지원 또는 워커 초기화 실패 시 같은 해상도의 브라우저 렌더러로 전환한다.
- TYPE 1은 기존 정점·인덱스·그리는 순서를 유지한 배치와 VAO를 사용한다.
  그리기 호출은 평상시 22→5회, 스크롤 효과 최대 70→17회다.
  32비트 인덱스 미지원 경로는 기존 개별 배치를 유지한다.
- TYPE 2는 프레임마다 동일한 시간 기반 계산을 입자별로 반복하지 않도록 공통 값을
  전달한다. 사용하지 않는 작은 밉 레벨만 생략한다. 정지 모드의 동일한 240회 준비를
  GPU fence로 나눠 실행하고, 탭 복귀만으로 이 준비를 반복하지 않는다.
- 두 배경 모두 셰이더 완료를 지원 확장에서 비동기로 확인하며 불필요한 DOM 속성
  갱신을 없앤다. 선택한 배경의 UI·스타일만 지연 로드한다.
- 화면 크기·DPR·포인터·스크롤·가시성을 워커와 동기화하고, 숨김/전체 화면 덮임/
  메뉴 열림 시 배경을 멈춘다. 종료 시 GL 자원과 워커·이벤트를 해제한다.

## 품질과 측정 조건

해상도·DPR·입자 수·구조물·발광 폭을 낮추지 않았다. 네온 구조물 4개, 결합 25,500개,
내부 섬유 32개와 실크 balanced 65,536/full 98,304개 입자를 유지한다.

실제 Chrome/ANGLE D3D11, RTX 3070에서 1440×900 CSS 픽셀, DPR 1·2로 배경별 정지 및
스크롤 구간을 측정했다. DPR 2의 실제 출력은 2880×1800이다. 전후 모두 약 59.98fps였고,
측정한 완전한 1초 구간의 최저는 60fps였다. 최적화의 주된 의미는 같은 화면을 유지하면서
그리기 호출과 UI 스레드 작업을 줄이는 것이다. 모든 기기에서 FPS가 상승했다고 주장하지 않는다.

동일한 장면의 이미지 비교에서 평균 RGB 차이는 구조물 0.00013/255, 실크 0.00434/255였다.
실크의 5단계 초과 차이 픽셀은 약 0.01%로, 공통 수식의 계산 위치 변경에 따른 미세한
부동소수점 차이다. 형태·색·입자 수·출력 크기를 유지했다.

독립 렌더러 5초 A/B의 실크 GPU 평균 시간은 DPR 2 정지 2.846→1.063ms,
스크롤 3.328→1.277ms였다. GPU 클럭과 동시 부하에 영향을 받는 단일 장비 측정치이며,
모바일 실기기의 보편적 수치로 해석하지 않는다. 워커 경로의 별도 5초 측정에서는 두 배경
모두 약 60fps, 배경 초기화에 의한 메인 스레드 long task 0건, 숨김 정지 및 종료 후 워커
0개를 확인했다.

## 휴대폰 메뉴

- 767px 이하 화면에서 좌측 상단에 44px 햄버거 버튼을 제공한다. 넓은 폴드형·PC 화면은
  기존 구성을 유지한다.
- 국내·미국 증시, 시장 지도, ETF, 뉴스·분석, 순위, 자산, 커뮤니티 등 주요 페이지를
  기존 정식 URL과 한·영문 이름으로 연결한다. 분류별 접기/펼치기, 현재 위치 표시,
  한·영문/띄어쓰기 무관 검색, 자주 찾는 페이지 바로가기를 제공한다.
- 최소 44px 조작 영역, 16px 검색 입력, 기존 sans 글꼴과 다크/화이트 토큰을 사용한다.
  언어·테마·효과 설정을 메뉴 안에서 조작할 수 있다.
- Escape·닫기·배경 클릭·페이지 이동으로 메뉴가 닫히고 키보드 포커스를 복원한다.
  스크롤 잠금과 포커스 순환을 유지한다.

데이터/API/DB·회원 저장·마이그레이션을 변경하지 않는다.

참고: [Khronos 비동기 셰이더 확인](https://registry.khronos.org/webgl/extensions/KHR_parallel_shader_compile/),
[Chrome OffscreenCanvas 안내](https://web.dev/articles/offscreen-canvas).
