# 철도·역 깜빡임 및 도로 지형 관통 수정

비교 기준: 운영 `c3cbce8e4b3118babbefc32de613fd3727ad20cc`.
공통 드론 장면 및 Native WebGPU 렌더러 수정이며, 지역별 예외 좌표는 추가하지 않았다.

## 원인과 수정

1. 선로 갱신 시 이전 그룹을 제거한 뒤 새 메시를 등록했다. 프레임별 GPU 등록 한도가 있어 이전 구조물이 먼저 사라질 수 있었다. 이제 선로 그룹, 메시, 재질을 재사용하며 교체 지오메트리의 등록을 기다리는 동안 이전 GPU 형상을 유지한다.
2. 원본 Three 지오메트리의 `dispose` 이벤트가 Native 렌더러의 이전 버퍼까지 즉시 해제했다. Native 어댑터는 실제로 그리는 메시의 소유권을 확인한 뒤 버퍼를 회수한다. 다른 독립 렌더러의 즉시 해제 동작은 유지한다.
3. 양방향 선로가 공유하는 역 시설을 소유자 추가·제거마다 해제·재생성했다. 역 입력값이 같으면 모델을 유지하고, 높이가 바뀌어도 메시와 재질을 재사용한다. 마지막 소유자만 역 모델을 해제한다. 역 범위 판정을 시설 중심점으로 통일하고 진입/이탈 반경을 분리했다. 선로도 이미 적재된 구간에만 유지 반경을 적용한다.
4. 재사용하는 교각·전차선 지지대의 인스턴스 경계 구가 Native 메시에 갱신되지 않아 잘못 컬링될 수 있었다. 현재 원본 경계를 반영한다.
5. 스트리밍 도로는 DEM을 쌍선형 보간했지만 화면의 지형은 두 삼각 평면으로 그렸다. 도로 꼭짓점이 지면보다 높아도 삼각형 내부가 지형에 파묻혔다. 실제 지형의 대각선/격자 경계로 위험한 도로 삼각형만 분할하고 전체 겹치는 영역에서 지면 위 높이를 보장한다. 차선 표시와 차량 경로도 수정된 도로 면을 따른다. 이미 안전한 평지·교량의 원본 버퍼는 그대로 유지한다.

## 검증 방법

- 애플리케이션 DB를 사용하지 않는 순수 메모리 회귀 검사 198개 통과. TypeScript 검사 및 새로운 독립 경로의 운영 빌드 통과.
- 실제 Chrome에서 의정부 드론 장면을 고도 120m, 속도 200km/h로 북쪽 1km 이동·복귀하며 66초 측정한다. 같은 지형 갱신 경로를 4회 강제로 재현한다. 원본/교체 메시의 실제 GPU 버퍼 및 컬러 파이프라인 준비 상태를 검사한다.
- 이미 다른 갱신으로 교체되거나 정상 거리 이탈로 회수된 모델은 이후 공백 집계에서 제외한다. GPU 공백 수는 모델별 프레임 수의 합으로, 화면 전체가 꺼진 프레임 수 또는 픽셀 깜빡임 횟수가 아니다.
- 렌더링된 지형 버텍스와 도로 삼각형의 내부 지점을 직접 비교한다. 단순 DEM 샘플러나 꼭짓점만으로 통과 판정하지 않는다.
- 모든 브라우저 검증은 음소거, IndexedDB 비활성화, 읽기 전용 API 스냅샷으로 진행한다. 종료 후 선로·역의 Native 메시/버퍼 회수도 확인한다.
- 화면 품질과 해상도를 낮추지 않는다. Ryzen 7 3700X / RTX 3070, Chrome 154.0.8037.98, Native WebGPU, high, 2520×1750, DPR 1.75에서 평균/최저 1초 FPS 및 p95/p99/최대 프레임 시간을 기록한다.
