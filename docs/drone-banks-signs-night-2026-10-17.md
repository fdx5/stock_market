# 교량 접속·도로 지형·푯말·야간 조명 수정 (2026-10-17)

## 반영 내용

- 일반 도로에 높이 차이만으로 옹벽을 생성하던 코드를 삭제했다. 일반 도로에 이웃 교량의 높이를 전파하던 처리도 제거했다. 지형을 따르는 도로의 공통 끝점은 같은 지형 높이를 사용한다.
- 확인된 교량은 진입부를 포함한 전체 연결선을 사용하고 같은 교각으로 지지한다. 교량에 일반 도로용 지형 삼각형 보정을 적용하지 않는다. 거친 DEM에서 얻은 진입부 기울기가 상판을 물 아래나 과도한 높이로 끌어가는 현상은 지지점 사이의 단조 보간으로 제한했다.
- 교량 끝이 일반 도로 중간에 닿거나 6m보다 짧은 연결 구간을 만드는 경우도 실제 접속점에서 나눈다. 최초 표시 범위 밖에 놓인 교량 양안에는 최대 6개 작은 구역의 도로·구조 속성·DEM만 추가 조회한다. 이 도로들은 자신의 지형 프로파일을 사용한다.
- 동작대교의 분리된 상·하행 3차로를 유지하고, 한강대교처럼 동일 상판을 공유하는 방향별 링크는 하나의 양방향 상판으로 정리했다. 서로 다른 높이의 교량과 분리 차로는 합치지 않는다. 일방통행 도로의 차량·차선 배치도 같은 방향을 따른다.
- 드론 교통망에서 짧은 연결 차로를 버리지 않는다. Float32 중복 좌표를 제거하고 충분한 길이에서 방향을 계산한다. 확인된 교량 접속점에서만 차로 수가 줄어드는 합류를 허용하며 높이가 다른 도로는 계속 배제한다. 교량 아래 겹쳐 남아 잘못된 경로를 만들던 평행 원본 도로 조각도 그 교량의 범위에서만 제외한다.
- 주요 교량 이름 푯말을 기존 단일 캔버스 라벨에 추가했다. 공개 지도에서 확인한 30개 이름/위치 기준점을 실제 교량 형상과 대조하며, 건물 카드 조회를 일으키지 않는다. 이동 타일이 사라지면 해당 라벨도 메모리에서 회수한다.
- 야간 창문은 건물의 고정 식별값을 바탕으로 밝기·색온도·점등 비율을 달리하고 층별·구역별 패턴을 섞었다. 업무용 빌딩은 더 밝은 범위를 사용한다. 프레임마다 바뀌는 난수, 추가 조명 객체, 텍스처나 드로 콜은 사용하지 않는다.

## 검증

- 도로·교량·교통·외관 관련 회귀 검사 **207개 통과**, TypeScript 빌드 및 Vite 운영 번들 생성 완료. 원격 `029b4bd`의 로딩 분할 변경을 통합한 뒤 다시 검사했다. 생성한 번들을 실제 Chrome에서 실행했다.
- 저장된 공개 GIS 응답으로 실제 직렬화 도로 워커를 재생했다. 한강 교량 주변 **32개 구역, 24,464개 상판 표본**, 누락 0 / 경로 단절 0 / 정밀도 경계 오류 0. 방향별 중복 프로파일 대신 최종 생성한 상판과 차량 높이를 대상으로 삼았다. 모든 구역의 표본 수가 0보다 큼을 확인했다.
- 실제 Chrome(WebGPU, 음소거)에서 동작대교 상·하행에 각각 차량이 존재하고 양 끝에 일반 도로 노드가 연결됨을 확인했다. 960개 실제 상판 표본의 누락은 0, 약 3m 간격 최대 높이 변화는 각각 0.162m / 0.291m였다.
- 한강쌍용 화면의 한강대교는 8차로 양방향 상판 한 개로 표시된다. 양방향 차량과 양 끝의 일반 도로 접속을 확인했다. 366개 실제 상판 표본의 누락은 0, 최대 높이 변화 0.096m였다.
- 두 화면에서 교량 푯말, 야간 점등 변화, 차량 이동을 확인했다. 페이지 오류 0, 네이티브 셰이더 실패 없음. 실제 상판 검사는 도로 높이/소유 프로파일을 대조하므로 겹친 다른 도로나 구조물을 이 상판의 높이로 오인하지 않는다.

근거는 작업 폴더 `tmp/resume-qa/`의 `canonical-all-summary.json`, `directed-lane-final.json`, `tests-integrated-final.log`, `build-merged-final.log`, `deploy/integrated-flight/` 등에 보관한다. DB나 백엔드를 테스트에 사용하지 않았다. 공개 조회 API만 사용하는 미리보기와 독립 Chrome 컨텍스트를 사용했다.

차량의 바퀴 높이는 소유 정보가 일치하는 실제 아스팔트 삼각형에서 직접 계산한다. 해당 소유 정보나 삼각형이 없으면 기존 높이 계산으로 돌아가며, 다른 도로나 위아래 교량을 대신 선택하지 않는다. 지형을 중복 계산하는 비용을 줄이는 변경이다. 일방통행 3차로를 도로 중심에 맞춰 배치한 것과 같은 오프셋을 충돌 검사에도 적용했다. 3개 차로 모두 장애물을 놓치지 않는 회귀 검사를 추가했다.

원격 저장소의 도로 생성/노멀 계산 분할, 교차로 후보 공간 인덱스, 지형 절단 워커 및 로딩 준비 변경을 통합했다. 성능 변경 전의 수정된 교통망을 고정된 기준 커밋 `bc732af`로 삼아 접속점·노면 표시의 비트 단위 동등성도 검사한다. 이전 버전의 잘못된 일방통행 표시를 기준으로 되돌리지 않는다.

## 성능 및 범위

출력 해상도와 품질을 낮추지 않았다. CSS 1920×1080, 고정 픽셀 비율 2, high 품질로 검사했다. 실제 출력은 드론 3840×2160, 건물뷰의 화면 영역 3840×1610이다. 실제 네이티브 렌더 프레임을 측정했다.

| 동작대교 접근 | 59.97 | 60 | 16.8 / 16.8 / 20.3 |
| 동작대교 횡단 | 54.33 | 40 | 33.4 / 33.5 / 100.1 |

이 비행에서 960개 상판 표본 누락 0, 양쪽 분리 상판의 일반 도로 접속 유지, 차량 462대 중 443대가 3초 동안 이동, 페이지 오류 0, 셰이더 실패 없음도 다시 확인했다. 최초 화면 이후 전체 측정의 평균은 57.44fps, 최저 1초는 35fps였다. 접근 구간 하나만의 통과를 전체 통과로 취급하지 않는다.

전 구간 최저 50fps는 아직 달성하지 못했다. 위 검사는 전국·모든 장비의 무결성을 증명하지 않으며, 교량 높이는 측량된 상판 Z가 아닌 공개 DEM의 양안 지형으로부터 계산한 값이다.
