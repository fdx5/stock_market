# 드론 Overpass·횡단보도 API 오류 검토 — 2026-10-09

외부 장애에 대응할 여지가 있다. 현재 요청 폭증·즉시 재시도·비정상 응답 처리에도 개선할 부분을 확인했다.
사용자가 본 운영 `/api/realestate/crossings` 500의 정확한 예외는 운영 오류 로그가 없어 확정하지 못했다.
수정 코드는 검증 결과 안내 후 사용자 요청에 따라 배포 대상에 포함했다. 실제 운영 API의 500이 해결됐다고 보고하지 않는다.

## 확인한 사실

- 기존 `_overpass`는 외부 HTTP 500을 `BuildingsError`로 바꾸며, crossings 조회가 이를 받아 `source: null`로 반환한다.
  외부 500이 그대로 내부 HTTP 500으로 전달되는 구조는 아니다.
- 하지만 HTTP 200의 JSON이 배열이면 기존 코드에서 `AttributeError`, `elements: null`이면 이후 파서에서
  `TypeError`, 좌표 누락이면 `KeyError`가 날 수 있었다. 응답 `{}`는 검증된 빈 데이터처럼 취급될 수 있었다.
  앱·DB를 불러오지 않고 기존 함수의 AST와 모의 응답만 사용해 앞의 두 예외 및 빈 데이터 오판을 재현했다.
- 드론은 초기 약 80개 타일의 water/crossings를 미리 요청하고, 도로 워커도 crossings를 다시 요청한다.
  같은 캐시 키의 요청은 서버에서 합쳐지지만 서로 다른 타일의 전경 요청에는 전체 동시 호출 제한이 없었다.
  기존 제한 2개는 백그라운드 조사에만 적용됐다. 실패 서버를 다음 조회에서 바로 재호출할 수 있었다.
- 도로 워커는 2초 뒤 crossings 요청을 포기하지만 서버 전경 조회의 목표 시간은 4초다.
  긴 초기 요청에서는 횡단보도 정보가 첫 화면에 반영되지 않을 수 있다. 이번 수정으로 이 워커 시간 설정을 바꾸지는 않았다.
- `overpass.kumi.systems`는 `overpass.private.coffee`의 이전 이름이다. 독립적인 세 번째 제공자로 취급하는 것은
  적절하지 않다. OSM 문서는 공개 서버 과부하와 캐시·호출 제한, 406/429 뒤 최소 30초 대기를 안내한다.
  [OSM Overpass 문서](https://wiki.openstreetmap.org/wiki/Overpass_API).

## 읽기 전용 외부 확인의 범위

로컬 네트워크에서 상태 조회를 각각 한 번 수행했다. `overpass-api.de/api/status`는 406,
`overpass.kumi.systems/api/status`는 429였고, 공개 crossings GET 한 건은 12초 읽기 시간 초과였다.
상태 조회는 실제 interpreter 질의와 다르며 운영 서버의 출발 IP도 다르다.
이 결과만으로 사용자가 본 500을 재현했다고 하거나 원인을 확정하지 않는다. 반복 부하 질의는 하지 않았다.
원본: `I:\ai_root\stock_market\output\drone-perf-20261009\overpass-readonly-probes.json`.

## 준비한 코드 변경

- 중복 별칭을 제외하고 de/private.coffee 두 제공자를 유지했다.
- 전경·백그라운드 모두 **프로세스당 동시 Overpass 요청 2개**를 공유한다. 전경은 최대 0.25초,
  긴 조회는 최대 5초까지 슬롯을 기다린다. 대기와 경과 시간을 다음 요청의 시간 예산 계산에 반영한다.
  여러 서버 프로세스 전체를 아우르는 분산 호출 제한은 아니다.
- HTTP 실패·네트워크 실패·잘못된 응답 뒤 해당 서버를 최소 30초 쉬게 하고, `Retry-After`가 더 길면
  숫자 초 또는 HTTP 날짜를 존중한다. 대기 후 요청을 다시 허용한다.
- JSON 객체/요소 배열/태그/geometry/member/좌표 유효성을 검증한다. 시간 초과를 담은 200 응답도 실패로
  분류한다. 정상적인 `elements: []`와 실패를 구분하며, 실패를 검증된 빈 조사로 저장하지 않는다.
- crossings 파싱의 누락 좌표·잘못된 타입 예외도 기존의 `source: null` 응답으로 처리한다.
  정상 다리 층, 신호 위치·방향과 좌표 변환은 유지한다. 실시간 신호 상태를 만들어내지 않는다.
- 로그에는 고정 서버 호스트/HTTP 상태 또는 예외 종류만 남긴다. 원문 질의·응답·토큰은 남기지 않는다.

기존 지리 캐시의 키·테이블·보존 로직은 변경하지 않았다. 데이터 삭제·초기화·마이그레이션이나 DB 실행도 하지 않았다.
Requests의 연결/읽기 timeout은 비활동 시간 제한이므로 절대적인 전체 응답 시간 보장이라고 주장하지 않는다.
공개 제공자 장애 자체를 없애는 변경도 아니다.

## 검증과 로컬 미리보기의 범위

`backend/tests/test_overpass_resilience_isolated.py`의 10개 테스트가 통과했다.
실행은 `python -m unittest discover -s backend/tests -p test_overpass_resilience_isolated.py -v`이며,
AST로 선택한 순수 함수만 실행한다. 앱 패키지·환경 설정·기존 DB를 불러오지 않는다.
500/429/406, Retry-After, 대기 후 재개, 비정상 JSON, 좌표 누락, 정상 빈 응답, 신호/층/투영,
예외 후 슬롯 반환과 실제 스레드 2개 제한을 확인한다.

공개 지도 조회는 운영 API로 프록시하므로 로컬 검증 당시 위 **백엔드 개선은 이 주소에서 실행되지 않았다**.
운영 오류의 정확한 분류와 효과 확인에는 배포 전 격리 환경의 서버 통합 검사 및 운영 예외 로그 확인이 남아 있다.
