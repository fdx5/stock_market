# 고속도로 CCTV 국내 출발 중계

## 확인된 상태

- 기존 운영 서버는 미국 Render이며, 고속도로 ITS는 코드에서 중지되어 있었다. 운영 ITS 키는 설정되어 있다.
- 작업 PC의 외부망 국가는 KR로 확인했다. 키 없는 ITS API 요청은 연결되어 401을 반환했다. 이는 API 인증 전의 연결 검사이며 영상 재생 성공을 뜻하지 않는다.
- 국내망으로 옮겼을 때의 운영 키 인증 및 실제 영상 성공 여부는 배포 후 검증한다. 해외 IP 차단이라고 사전에 단정하지 않는다.

## 구성

- 국내 중계기는 Render 서비스의 `/api/realestate/cctv/gateway`로 WSS 연결을 먼저 맺는다. 국내 장비에 인터넷 수신 포트나 범용 프록시를 열지 않는다.
- 서버에는 Ed25519 공개키만 등록한다. 국내 중계기의 개인키는 소스·DB 밖의 보호된 파일에 두며 nonce 서명을 검증한다. 재사용된 서명이나 다른 키, 브라우저 Origin 연결은 거절한다.
- 고속도로 목록 API와 모든 CCTV 영상·HLS 하위 조각·키 요청을 국내망으로 보낸다. UTIC 목록과 플레이어 인증 페이지만 IP 등록이 된 Render 서버에서 조회한다. 제공기관 iframe이 있으면 그 이후부터 국내망을 사용한다.
- API는 `openapi.its.go.kr:9443/cctvInfo`만 허용한다. ITS 영상은 ITS/KTICT/도로공사 호스트와 지정 포트로 제한한다. UTIC 도시 영상은 공식 플레이어/그 HLS가 지정한 공개 서버만 불투명 참조로 등록한다. 도시별 숫자 IP와 고유 포트를 지원하는 `city_media` 작업은 인증된 서버만 생성하며 사용자 URL 입력 API는 없다. 도시 경로는 호스트 고정 목록을 쓰지 않으므로 신뢰 경계는 UTIC 응답과 인증된 서버다. 양쪽에서 URL 형식·서비스 포트를 검증하고, 국내 연결/리다이렉트마다 공개 DNS를 확인하여 해당 IP에 고정한다. 사설/로컬/메타데이터 IP는 차단한다.
- 동시 요청·응답 크기·응답 대기를 제한한다. 중계기가 없으면 해외 경로로 조용히 되돌리지 않고 연결 지연을 보고한다.
- 운영 비밀키·제공기관 영상 URL은 브라우저·로그에 전달하지 않는다. 영상 응답은 기존 불투명 토큰 경로로 제공한다. 저장 데이터·DB·스키마 변경은 없다.

## 운영 설정

- `CCTV_GATEWAY_PUBLIC_KEY`: 국내 중계기에서 생성한 공개키(Base64).
- `CCTV_HIGHWAY_GATEWAY=required`: 기존 환경변수 이름을 유지하며 고속도로 API와 일반/고속도로 CCTV 영상 모두 국내 중계가 필요함.
- `HIGHWAY_CCTV_ENABLED=true`: 소유자가 다시 요청한 고속도로 기능 활성화.
- 기존 ITS 키 설정은 서버에서 유지한다.
- 현재 `WEB_CONCURRENCY=1` 및 Render 인스턴스 1개에서 사용한다. 연결 상태와 요청 대기는 인메모리이므로 여러 프로세스로 늘릴 때 별도 라우팅 설계가 필요하다.

중계기 의존성: `cryptography`, `websockets`, `requests`, `urllib3`.

```powershell
python backend/scripts/run_cctv_gateway.py --key-file <소스 밖의 개인키 파일> --init-key
python backend/scripts/run_cctv_gateway.py --key-file <소스 밖의 개인키 파일>
```

처음 명령은 새 파일만 생성하고 기존 개인키를 덮어쓰지 않는다. 출력되는 것은 공개키뿐이다. Windows에서는 개인키 폴더의 상속 권한을 제한한 후 생성한다.

국내 장비는 실행 중이어야 한다. PC 임시 검증과 상시 서버 운영은 구분하며, 국내 VPS/NAS로 이전할 때도 동일한 중계기를 사용할 수 있다. 기본 클라이언트는 국내망 여부를 확인하고, 연결 중단 시 제한된 지수 백오프로 재접속한다.

## 검증

- 앱 기동·DB 연결 없는 격리 테스트 44개 통과: 기존 CCTV 어댑터, 서명·재전송 거부, 활성 중계기 교체 거부, 타깃·응답 크기 제한, 국내 연결 실패 시 해외 폴백 방지, HLS 하위 요청 경로 보존, 사설 DNS 거절.
- 독립 로컬 WebSocket 서버와 실제 중계기 프로세스로 국내 ITS 서버 왕복 확인(키 없는 요청 401). 이 테스트 서버는 운영 앱이나 DB를 기동하지 않는다.
- 실제 운영 재생은 배포된 키를 서버 메모리에서 사용하여 별도로 검증해야 한다.

## 1차 운영 검증 및 프런트 보완

- Render 커밋 `93dfe61685f4ebbede62d7566d382744d03c25d4`, 배포 `dep-dbn7s75g1s2s73b1g3og` live 후 국내 중계 연결을 확인했다.
- 성남 고등IC 주변 조회에서 ITS 24곳을 받았다. 국도(`its`) 조회의 `invalid_response`는 별도 이슈로 남고, 고속도로(`ex`)의 카메라와 영상은 정상 제공된다. 전국·모든 카메라 성공으로 일반화하지 않는다.
- 실제 `[용인서울선] 고등IC 서울`을 운영 HTTPS 중계로 받아 기존 팝업 컴포넌트에서 음소거 Chrome으로 재생했다. 720×480 영상의 재생 시간 1.999→72.0049초, 디코딩 프레임 31→2125를 확인했다. 팝업 종료 시 video 요소 제거, 페이지 JS 오류 0건.
- 운영 드론 화면에서 ITS와 UTIC의 동일 카메라가 중복될 때 UTIC 경로가 먼저 선택되는 것을 확인했다. 같은 이름·위치의 중복에만 국내 중계를 쓰는 ITS를 우선하고, 다른 방향의 카메라는 유지한다.
- 팝업은 고속도로 카메라를 열거나 재연결할 때 선택한 ID의 새 영상 참조를 조회한다. 목록만 갱신한 뒤 선택된 팝업이 옛 주소를 계속 쓰는 경로를 제거했다. 종료/재연결 처리에도 고속도로 카메라를 포함하며 재시도는 제한한다.
- 국내 중계기는 현재 작업 PC에서 별도 숨김 프로세스로 임시 실행 중이다. PC의 전원·망 연결이 필요하며 재부팅 자동 시작이나 상시 서버 이전이 완료됐다고 보고하지 않는다.

참고: [Render WebSockets](https://render.com/docs/websocket), [ITS CCTV API](https://www.its.go.kr/opendata/opendataList?service=cctv).

## 공통 영상 경로 보완

- 종전 국내 경로는 ITS 영상에만 적용됐고 UTIC는 브라우저 직접 접속/Render 출발 요청을 사용했다. 일반 CCTV에도 국내 중계를 적용하며, 플레이어는 반환된 원본 직접 주소를 사용하지 않는다.
- UTIC 재연결은 `fresh=true`로 5분 주소 캐시를 건너뛴다. HLS의 재생 목록·영상 조각·암호화 키까지 도시 국내 경로를 보존한다. 20초 이상 멈춘 재생은 횟수를 제한해 다시 연결한다.
- 도시 목록이 성공해도 고속도로 중계가 실패하면 전체 결과를 `partial`로 표시하고, 연결 실패 목록을 프런트 캐시에 정상 결과로 저장하지 않는다.
- 실제 원본 서버 오류가 국내망에서도 발생하면 별도로 표시해야 한다. 국내 중계를 구성했다는 이유로 모든 제공기관 영상 성공을 단정하지 않는다.
- 반계IC 실측에서 국내 중계는 `.ts` 영상 1,028,736바이트를 HTTP 200으로 받았지만 원본 MIME이 `text/vnd.trolltech.linguist`여서 서버 검증이 거부했다. MPEG-TS 188바이트 패킷의 동기 바이트 3개를 확인한 데이터만 `video/mp2t`로 바로잡는다. 확장자만 보고 HTML/오류 응답을 영상으로 취급하지 않는다.
