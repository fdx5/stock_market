# Fold8 GPU 작업량 감소

실단말 기준은 내부 가로 화면 1866×1408, 해상도와 품질 유지다. 사용자 측정은
14.7fps / GPU 57ms이며 shadow 7.6, scene 21.2, plants 13.6, water 0.7,
post 11.2, other 1.1ms다. CPU render 최고 9ms 미만이므로 GPU 비용을 우선한다.
직전 운영 86266f63은 진단 HUD 배포이며 실단말 60fps 달성 배포가 아니다.

## 변경

- 닫힌 사면체 잎의 네 면을 네 꼭짓점과 대응시킨다. 각 삼각형의 인덱스를 순환해
  첫 꼭짓점이 원래 면 법선을 공급하도록 하고 WGSL flat 보간을 사용한다.
  잎 하나의 정점 처리는 12개에서 4개로 줄지만 모든 삼각형, 감김 방향, 위치,
  UV, 색상과 면 법선은 보존한다. 기존 그림자 위치 전용 경로도 유지한다.
  GPU 버퍼는 원래 지오메트리 수명과 버전 변경을 따른다.
- 나무 블록 구 검사 뒤 보수적인 변환 AABB를 검사한다. 모든 나무를 포함하는
  경계와 1m 여유를 유지한다. 블록 크기는 기존 85m를 유지한다.
- 전 픽셀을 덮어쓰는 AO, 블러, TAA, 블룸 다운샘플, 최종 출력은 이전 첨부물을
  load하지 않는다. 가산 블룸의 바탕은 계속 load한다. 출력 크기와 모든 필터는 같다.
- 지면/벽의 기존 세부 표현 가중치가 정확히 0인 경우에만 무효 노이즈 계산을 생략한다.
  주간 건물 발광이 0이면 방별 발광 난수를 계산하지 않는다. 반사 전환이 끝났으면
  가중치 0인 반사 큐브 읽기를 생략한다. 재질 AO가 1이면 결과가 정확히 1인
  specular AO의 pow/exp2 계산을 생략한다.
- TAA에서 이전 화면 밖으로 벗어난 픽셀은 기존과 같이 현재 색을 반환하되,
  사용하지 않을 9개 이웃의 통계를 계산하기 전에 판정한다.
- 컴파일한 파이프라인을 재사용할 때 불필요한 셰이더 모듈 재생성을 피한다.

해상도, 프리셋, 나무 수, 잎 수, 그림자 해상도/필터/주기, 반사 품질을 낮추지 않는다.
수면 노이즈 캐시와 성능이 나빠진 깊이 선행 패스/그림자 범위/compute TAA 실험은 제외한다.

## 검증

- 관련 Node 회귀 검사 102개 통과. TypeScript와 Vite 프로덕션 빌드 통과.
- 실제 5종 나무/기존 LOD/인스턴스 변환/직접 그리기·번들/시점 조합 GPU 비교
  128개: 출력 차이 0. 비어 있지 않은 픽셀도 확인했다.
- 지면 세부 표현 64개, 건물 주야간 발광·창문 표현 45개, TAA 6개 GPU 비교: 출력 차이 0.
- 1866×1408 실제 도시의 잎/컬링/후처리 변경 3쌍 비교: 31,527,936개 채널 차이 0.
- 4096그루 정점 처리 단독 비교: 9,437,184 → 3,145,728 정점.
  GPU 약 3.87~3.93ms → 1.18~1.25ms. 이 수치는 전체 나무 패스나 실단말 FPS가 아니다.

비행은 별도 Chrome 프로필, 음소거, Android UA, CSS 933×704/DPR 2.625,
실제 캔버스 1866×1408/high/WebGPU, RTX 3070 그래픽 405MHz에서 측정한다.
CPU 배속 제한은 1배다. 이전 2배 제한 실험과 직접 개선율을 비교하지 않는다.
이 환경은 Fold8의 타일 GPU, 드라이버, 메모리 대역폭과 발열을 재현하지 못한다.
데스크톱 측정을 실단말 50/60fps 보장으로 바꾸어 보고하지 않는다.

최종 180초 비행: 평균 59.41fps, 1초 간격 표본 최저 52fps, 모든 프레임 끝점의
1초 구간 최저 51fps, p95 19.8ms / p99 25.4ms / 최대 간격 69.7ms, 오류 0.
시뮬레이션의 요청 최저 48fps 기준은 충족하지만 모든 프레임 60fps라는 뜻은 아니다.
비행 최종 수치는 같은 폴더의 JSON에 기록한다. `min1s`는 1초 간격 표본이고
`minimumSliding1s`는 모든 렌더 프레임을 끝점으로 검사한 1초 구간 최저다.
평균만으로 지속 성능 달성을 판단하지 않는다. 실단말 새 측정은 별도로 필요하다.
