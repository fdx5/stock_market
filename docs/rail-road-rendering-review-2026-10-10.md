# 철도·역사·도로 공통 렌더링 개선 - 로컬 검토

작성일: 2026-10-10. 현재 반영 위치는 `feature/surface-rail-20261010` 작업 공간의 기존 서비스 3D 드론 화면이다. 이번 변경은 운영에 배포하지 않았다.

## 결과와 정확도 범위

특정 교량이나 역의 좌표만 보정하는 대신, 선로 형상과 차량 자세, 건물 통과 공간, 도로 포장과 경계 계산을 공통 로직에서 수정했다. 창동·의정부·청담의 실제 앱 장면을 새 브라우저에서 로딩하고, 열차를 따라 카메라를 이동한 뒤 수동 비행 입력을 확인했다. 런타임 오류와 확인 시점의 드론 타일 실패는 0건이다. 타일과 건물 통과 공간 계산은 이동 후에도 순차적으로 로딩되므로, 로딩 중의 미완성 화면을 완성 상태로 간주하지 않는다.

전국 공개 지도에서 추출한 경로를 수치 검사했지만, 전국의 모든 도로·역사를 현장 실측 및 육안으로 검수했다는 뜻은 아니다. 평면 좌표와 건물·승강장 윤곽은 공개 지도 자료를 사용한다. 실측 높이가 없는 고가 선로, 역 지붕, 교각과 차량 외형은 대표적인 추정 모델이다. 열차 위치·배차·정차는 시뮬레이션이며 실시간 운행 정보가 아니다.

## 1. 철도와 차량

| 발견한 원인 | 공통 수정 | 기대 효과 |
|---|---|---|
| 곡선 선로를 각 구간별로 넓히면서 모서리가 달라짐 | 인접 구간이 동일한 절점 방향과 모서리를 공유 | 선로·도상·안내궤도 연결부의 작은 틈 방지 |
| 같은 원본 절점의 선로가 반대 방향으로 나뉨 | 동일 노선의 분기 없는 원본 절점에서만 방향을 맞춰 연결 | 지도상 연결된 선로의 중간 단절 보완 |
| 열차 전체를 한 지점의 기울기와 방향으로 배치 | 차량별 앞뒤 주행장치 위치에서 방향·경사를 계산 | 곡선·오르막에서 차체가 선로를 벗어나 보이는 현상 개선 |
| 표시 범위보다 선로 생성 범위가 좁음 | 전체 편성 길이와 다음 재생성 거리까지 포함 | 이동 중 열차만 먼저 나타나는 현상 방지 |
| 지형이 추가 로딩되어도 선로 높이는 초기 값 유지 | 지형 변화 감지 후 캐시에서 선로와 차량 경로를 함께 재생성 | 지면에 묻히는 선로·차량 높이 불일치 보완 |
| 원본 절점 사이의 지형 굴곡을 놓침 | 5 m 간격의 지형 높이도 선로 아래 여유에 반영 | 긴 직선 구간의 지면 관통 보완 |
| 중첩 고가 선로를 같은 높이로 표시 | 원본 layer 순서를 유지하는 높이 프로필 | 창동 같은 다층 교차의 상하 순서 보존 |
| 차륜과 주행면 높이를 동일하게 취급 | 일반 철도·고무차륜 AGT·모노레일의 접촉 높이 분리 | 차륜이 떠 있거나 주행면을 파고드는 표현 개선 |

의정부 경전철은 운영사 자료의 VAL208 고무차륜 AGT·2량 편성을 사용한다. 빔을 감싸는 모노레일과 구분하여 콘크리트 주행면·측방 안내·고무바퀴를 표현한다.

## 2. 역사와 건물 충돌

- 공개 OSM의 역사 건물·승강장 폴리곤을 추가하여 실제 평면 윤곽을 따른다. 지하·음수 layer 시설은 제외한다.
- 선로를 덮는 역사는 개방형 통과 공간, 지붕과 기둥으로 표현한다. 별도 역 건물은 기존 건물 자료를 유지하여 인접 고가 선로 높이로 중복 건물을 띄우지 않는다.
- 승강장 면·노란 가장자리·기둥 하단은 해당 위치의 선로 높이를 사용한다. 인접한 낮은 선로 높이를 역 전체에 적용하지 않는다.
- 선로와 겹치는 기존 건물 및 역 기둥은 차량 통과 부피와 교차하는 삼각형만 잘라 표시한다. 옆 부분과 상층부는 유지하고, 원래 건물 형상과 좌표는 메모리에 보존한다.
- 통과 공간은 건물 렌더링의 파생 형상에만 적용한다. 건물 등록 데이터·DB·원본 GIS 응답을 변경하거나 삭제하지 않는다. 별도 작업 스레드에서 계산한다.
- 좌표가 잘못된 일반 건물도 선로와 겹치면 같은 통과 공간 보정을 받는다. 이것은 정확한 역사 설계도에 따른 재건축이 아니라 서로 다른 지도 자료의 충돌을 완화하는 표시 규칙이다. 건물 내부 벽·설비·실제 역 층 구성은 추가 실측 모델이 필요하다.

## 3. 도로·고가·포장·추가 로딩

| 발견한 원인 | 수정 |
|---|---|
| 초기 장면과 이동 중 도로의 포장 높이가 각각 0.08 m / 0.30 m | 공통 포장 높이 0.08 m, 차선 높이 0.16 m로 통일 |
| 타일 내부의 절점만 보존해 경계를 가로지르는 선분 소실 | 경계에서 선분을 정확히 자르고 높이·모서리 방향을 보간 |
| 차선 끝의 방향이 이전 절점 기준으로 달라짐 | 포장과 차선이 공유하는 모서리 방향을 사용 |
| 폭이 넓은 도로를 중앙 높이 한 평면으로 만듦 | 폭 방향 3 m 간격으로 나누어 지형 높이를 적용 |
| 이동 중 고가 높이에 임의의 7~8 m 추가 | 공식 도로 링크 전체의 양 끝 지형 높이 프로필과 초기 장면 계산을 맞춤 |
| 물 위라는 이유만으로 고가로 분류 | 물만으로 교량을 생성하지 않고 실제 도로 구조 정보로 분류 |
| 가까운 평행 도로·교차 도로의 구조 종류를 잘못 빌림 | 진행 방향 검증, 겹치는 상반 구조는 추론 보류 |
| 다른 높이의 고가·지상 교차점을 포장 연결 | 높이 차가 있는 교차를 분리하고 지상 접합면은 지형에 맞춤 |
| 짧은 구조 구간을 일괄 제외 | 실제 짧은 교량·진입부의 구조 정보 유지 |
| 실패한 GIS 요청을 빈 도로로 완료 처리 | 페이지별 재시도, 실패 타일은 기존 backoff 경로로 다시 로딩 |
| 초기·외곽 도로 포장 색과 표면 표현 차이 | 동일 아스팔트 질감 사용 |

차량의 차선 높이는 해당 차선 아래 포장면을 따른다. 외곽 도로를 만들 때 중복되던 물 조회를 줄였다. 고가 구조물의 세부 단면·교각 간격·실측 Z 값은 이번 공통 규칙 변경만으로 확보되는 정보가 아니다.

## 4. 데이터와 성능

- 사용 버전: `frontend/public/rail/20261010-v7`. 과거 버전과 공개 원본 파일은 보존했다.
- 원본 선로 2,785개 → 렌더링 경로 378개, 공간 인덱스 415개 셀.
- 노선별 지상 정차 이름 357개, 연결된 역사·승강장 원본 폴리곤 946개. 서로 다른 노선의 같은 역은 별도로 집계될 수 있으며, 공식 운영 역 총수와 다르다.
- 현재 버전의 경로 JSON 합계 1,857,668 bytes, 가장 큰 단일 경로 64,096 bytes. 31개 차량 노선 프로필이다.
- 실제 브라우저는 가까운 경로만 읽는다. 선로 동시 요청 최대 2개, 경로 메모리 캐시 최대 48개, 화면 열차 최대 40편성이다. 먼 차량은 단순 모델을 사용한다.
- 선로와 건물 통과 공간은 Worker에서 생성한다. 지형 변화에 따른 재생성은 다운로드한 메모리 캐시를 사용한다. 앱 실행 중 Overpass 전체 조회와 DB 접근은 없다.
- 최종 빌드의 선로 모듈은 25.34 kB / gzip 10.00 kB이다. 기존 큰 앱 청크 경고는 남아 있다. 테스트 장비의 특정 프레임·작업 시간은 모든 장비의 성능 보장이 아니다.

## 6. 로컬 최종 점검

기존 드론 화면: http://127.0.0.1:5173/drone-explore

창동 직접 접속: http://127.0.0.1:5173/drone-explore?complex=11320%3A%EC%B0%BD%EB%8F%99%3A333%3A%EC%B0%BD%EB%8F%99%EB%8F%99%EC%95%84%EC%B2%AD%EC%86%94&hour=12

로컬 API는 `http://127.0.0.1:8003`에서 공개 스냅샷과 정적 지리 자료를 제공한다. 기본 지도 목록은 공개 의정부 아파트 2건의 샘플이며, 전국 실거래 DB를 복제하지 않았다. 유효한 단지 직접 접속은 브라우저가 공개 GIS 건물·도로 자료를 요청한다. 기존 3D 렌더러·드론 조작은 앱 그대로 사용한다.

점검 순서: 창동의 1·4호선 상하 분리와 역사 출입부 → 의정부의 경전철 주행면과 승강장 → 도로를 따라 이동하면서 타일 경계·차선·고가 접합 확인. 지하 구간에는 열차를 새로 만들지 않으므로, 지하철만 있는 곳은 지상 열차가 보이지 않을 수 있다. 조작은 W/S 전진·후진, A/D 좌우, Q/E 회전, Space/Shift 상승·하강이다.

운영 DB·테이블·백업·회원 정보·비밀 환경 변수에 접근하거나 변경하지 않았다. `app.main`을 실행하지 않았고, 수집·보존 기간 정리 작업을 시작하지 않았다. 변경은 로컬 검토 상태이며 운영 영향 0%를 보증하는 배포 검증으로 제시하지 않는다.

## 7. 후속 개선 우선순위

1. **높음 - 실측 높이·역사 도면 보강:** 다층 환승역과 고가 진입부의 실제 Z·층 구성을 확보해 추정 높이를 대체한다. 자료가 없는 역을 모두 정확하게 복원했다고 주장하지 않는다.
2. **높음 - 원본 지도 단절 및 충돌:** 공통 원본 절점이 없는 선로, 오래된 건물 윤곽과 새 철도의 충돌은 공개 지도·공식 자료 대조가 필요하다. 단순 근접 연결은 분기나 서로 다른 층을 잘못 연결할 수 있어 적용하지 않았다.
3. **중간 - 전국 대표 구간 시각 검수 확대:** 대구 모노레일, 부산 경전철, 인천·용인·김포, 급곡선과 복층 도로를 같은 실제 드론 화면에서 추가 확인한다.
4. **중간 - 전용 실측 차량·역사 모델 및 큰 앱 청크 분리:** 현재 대표 모델을 실제 상세 자산으로 보강하고 장비별 프레임·메모리 예산을 계측한다.

## 9. 해안 타일 경계·색상·파도

해운대 실제 드론 화면에서 수면의 각진 색 경계, 육지 색이 드러나는 가는 틈, 해안 가까이에서 길게 뒤틀리는 물결을 재현했다.

| 원인 | 공통 수정 |
|---|---|
| 초기 바다와 외곽 바다를 삼각형 중심점으로 잘라 연결 | 로딩된 지역 바다가 가까운 바다까지 연속으로 표시. 겹치는 가까운 바다만 정확한 경계로 잘라 파생 형상으로 보관 |
| 서로 다른 해안 DEM 값이 각 수면 높이에 영향을 줌 | 절대 해수면 0 m를 같은 로컬 좌표 높이로 변환. 하천의 기존 수위 계산 유지 |
| 큰 해안 래스터의 건조 판정으로 실제 바다 삼각형 누락 | 바다는 실제 해안·섬 윤곽의 삼각 분할을 유지하며 래스터 중심점으로 버리지 않음 |
| 얕은 바다의 색이 지면 타일·수직 가장자리 명암을 반영 | 추정 해저 색을 연속된 조명과 수심 전환으로 계산. 해안선 바로 옆의 부드러운 경계 혼합은 유지 |
| 지면 아래 수직 치마면이 표면 법선에 섞임 | 지면 격자만으로 법선을 재계산하여 타일 가장자리 명암 오염 방지 |
| 해안 방향이 바뀔 때 큰 월드 좌표의 물결 프레임도 회전 | 모든 바다가 동일한 물결 좌표를 사용. 해안 거리로 부서지는 파도의 방향 전환 표현 |
| 약해진 잔물결·거품과 길게 늘어나는 무늬 | 잔물결을 보강하고 기존 파면 샘플을 재사용해 약 36 m 내 부서지는 파도·밀려오는 거품·잔포말 표현 (아래 재검수 내용으로 추가 보완) |

초기 지형의 바깥 면을 타일 끝으로 접는 대신 정확하게 절단한다. 원래 지형은 보관하고 드론 종료 시 복구한다. 바다로 판정된 초기·배경 지형을 같은 해수면 아래로 내려 해안의 가는 검은 틈과 바다 위 육지 색 사각형을 줄였다.

실제 해안·섬 절점을 보존하면서 해안 격자는 16 m, 충분히 먼 바다는 최대 96 m로 줄였다. 같은 해안 시점의 지역 수면은 초기 수정판 약 365,554개에서 약 104,606개 삼각형으로 줄었다. 디테일은 픽셀 셰이더의 기존 파면 샘플을 사용한다. **사용자가 보고한 10 FPS 이상 감소의 회복은 미확정**이다. 단회 계측은 일관되지 않았으므로 삼각형 감소를 프레임 향상으로 제시하지 않는다. 사용자 실제 비행 프레임을 확인한 뒤 배포를 판단한다.

원본 해안·섬·방파제 자료를 삭제하지 않는다. 일반 하천 삼각형은 지역 바다 교체 대상에서 제외하며, 드론에서 나오면 원래 수면 형상과 표시 상태를 복구한다. 색상·수심·파고·조위는 실제 관측값이 아니라 자연스러운 표시를 위한 추정이다.

해안 순수 형상·수위 검사 14개 통과. 로컬 검수용 API의 바다 응답을 운영과 같은 `ring/kind/islands` 구조로 맞췄다. DB 연결 없이 번들 해안 데이터만 사용하며, 운영 API 코드는 변경하지 않았다. 화면·성능 검수 결과는 최종 PDF에 기록한다.

## 10. 광안대교와 일반 교량 접속부

- 광안대교 상판·차선·차량 경로를 동일한 단면과 선형 높이 보간으로 생성한다. 원본 곡선 절점을 유지하며 상부 4차선과 하부 4차선의 주행 방향을 분리했다.
- 바다로만 구성된 타일에서도 교량의 차량 경로를 생성한다. 초기 장면의 잘못된 낮은 차량 경로는 해당 교량의 정확한 방향·폭 범위에서 전용 경로로 대체하며 드론 종료 시 복구한다.
- 차량이 타일 경계·교차로에서 다음 경로를 선택할 때 높이 차이를 검사한다. 상·하부 도로로 잘못 넘어가거나 과한 높이 점프를 만드는 연결을 차단한다.
- 일반 교량의 진입부 높이·횡경사 보정 함수를 초기 장면과 추가 타일 Worker에서 공유한다. 두 실제 원본 끝점과 공식 구조 속성이 접속을 뒷받침하는 경우에만 적용하며 내부 교차나 평행 도로를 임의 연결하지 않는다.
- 포장·차선·차량이 같은 단면 높이를 사용한다. 초기 장면의 차량에도 포장 높이 8 cm를 반영했다. 긴 도로 중간의 차량이 정지하던 끝점 기반 거리 판정은 경로 전체 범위로 교체했다.
- 교량 순수 검사 9개와 추가 실제 Worker 진입부 검사 1개 통과. 실장면 차량 178대는 상판 높이 허용 오차를 넘지 않았고 모두 이동 중이었다. 해안·교량 4개 시점의 검수판에서 런타임·GPU 오류는 없었다. 그 이후의 공통 Worker 추가 수정은 자동 검사로 확인했으며 사용자 비행 점검이 남아 있다.

광안대교의 기존 44 m/7.5 m 대표 높이는 실측 Z가 아니다. 하부 진출입 램프 전체와 IC 상세, 일반 교량의 실측 상판·단면 확보는 높음 우선순위의 후속 과제다. 이번 수정은 표시 형상·차선·차량의 일관성 개선이며 모든 교량을 현장 실측 복원했다고 주장하지 않는다.

## 11. 해안선·포말 품질 재검수 (사용자 피드백 반영)

사용자가 지적한 뭉개진 거품, 모자이크처럼 각진 해안선, 물과 모래의 접점에 보이는 녹색 표현을 해운대 실제 장면에서 재현했다.

| 원인 | 이번 수정 |
|---|---|
| 넓은 지역 격자의 해안 거리·물 판정 | 실제 해안선·섬 경계를 인덱싱해 선분 거리와 다각형 포함 여부를 계산. 격자 간격보다 작은 경계에서도 연속적인 결과 |
| 큰 삼각형의 곡선 거리 보간 | 25 cm를 넘는 거리 보간 오차가 있는 해안 곡선만 최대 4 m로 세분화. 직선 해안 16 m / 먼 바다 96 m는 유지 |
| 물 가장자리에서 잔디 바닥색 재혼합 | 바다 접점은 조명을 받는 젖은 모래 추정색으로 연결. 지적도에서 녹색으로 칠해진 접점 4 m 안쪽도 모래색으로 보정 |
| 화면 반사의 얕은 육지 오인식 | 포말 구간 36 m 안쪽은 하늘 반사를 유지하고 육지 화면 반사를 배제. 36-80 m 구간에서 육지 반사를 연속 복원. 강과 바깥 바다의 기존 반사 유지 |
| 거품을 저주파 물결 무늬로만 표현 | WebGPU에서 한 번 만든 256 px 기포 벽 무늬와 부드러운 밀도 변화를 사용. WebGL은 128 px 무늬를 한 번 생성. 36 m 해안 구간에만 추가 샘플 1회. 얇은 포말 머리·남는 거품·밀려오는 거품을 분리 |
| 모래 띠를 사각 격자 조각으로 생성 | 해안선 원본 절점을 따라 연속된 띠로 생성. 조회 사각형 가장자리는 모래 띠에서 제외 |

해안 검사 14개, 전체 순수 형상·가져오기 검사 142개가 통과했다. TypeScript와 프런트엔드 전체 빌드도 통과했다. WebGPU 해운대 55 m / 근접 7 m / 광안리 해안 3개 시점 및 WebGL 폴백 3개 시점에서 기록한 런타임·GPU 오류는 없었다. 검수 중 로딩 상태는 계속 변할 수 있으므로 서로 다른 시점의 타이머 값을 FPS 비교로 사용하지 않는다.

일괄 4 m로 해안을 촘촘하게 만드는 시험은 해운대 지역 수면 약 49.1만 삼각형을 만들었다. 곡선의 오차에 따라 필요한 곳만 세분화한 최종 방식은 같은 검수 위치에서 약 12.7만 삼각형이다. 이전 16 m 수정판 약 10.5만보다 약 2.2만이 추가되는 품질 보완이다. 프레임 회복 여부는 사용자 실제 비행에서 다시 확인해야 하며, FPS 향상을 단정하지 않는다.
