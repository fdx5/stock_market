## 3. 성능 2차 (0b6af9c)

- **BC7 텍스처**
  - 외벽·바닥 색상맵과 창문 발광맵은 업로드할 때 GPU 컴퓨트 셰이더로 BC7(mode 6) 압축합니다(`bc7Encode.js`).
  - 나무 아틀라스는 미리 압축해 둔 `public/3d/plants.bc7.gz`를 씁니다. 원본을 바꾸면 `frontend/scripts/plants-bc7.py`를 다시 실행해야 합니다.
  - 노멀·거칠기 합친 텍스처는 오차가 커서 압축하지 않았습니다.
  - BC를 지원하지 않는 기기는 기존 방식을 씁니다.
  - 결과: 건물·바닥·나무 텍스처 114→55MB, GPU 텍스처 전체 214→128MB. 근접 비교에서 차이가 보이지 않음(외벽 PSNR 46dB).
- **나무:** 교차 카드가 시선과 나란해질수록 잎이 사라지게 해서, 위에서 보이던 육각형(별) 틀과 옆에서 보이던 판 모양을 없앴습니다(WebGPU와 WebGL 모두).
- **데이터 대기 멈춤:** 건물 자료 요청에 20/30/45초 제한 시간과 자동 재요청을 두고, 마지막까지 실패하면 "다시 시도" 버튼을 보여 줍니다. 원인은 서버의 첫 조회(OpenStreetMap 재시도)가 수 분 걸릴 수 있는데 브라우저가 무제한으로 기다린 것입니다.
- **로딩 렉**
  - 모델이 뜨기 전에는 유휴 속도(30fps)로 렌더링합니다.
  - 새 파이프라인은 프레임당 3개까지만 만듭니다(`MeshRenderer.pipelinesPerFrame`).
  - 결과: 로딩 중 긴 작업 1건(70ms대) → 0건.

## 4. 남은 과제와 참고

- **전체 보기 닫은 뒤 마우스 렉:** 로컬(헤드리스와 일반 창 모두, 6회 반복)에서 재현되지 않았습니다. 저사양 GPU나 고해상도 모니터 환경의 GPU 부하로 추정합니다. 재현 환경 정보가 필요합니다.
- **남은 큰 메모리**
  - 그림자맵 50MB
  - 합친 노멀·거칠기 텍스처 약 28MB
  - 주변 건물 텍스처 캔버스 42MB(단지 간 공유라 해제하지 않음)
- **성능 측정 방법:** 로딩 시간 비교는 `vite build` 후 `vite preview`로 띄운 빌드로 해야 합니다. dev 서버는 워커 로딩 비용을 크게 과장합니다. 실제 사용 흐름인 "지도에서 단지 클릭" 시나리오로도 측정해야 합니다.
- 이 기록은 `docs/realestate-3d-optimization.md`(이전 최적화 기록)를 이어서 봐 주세요.

## 5. 추가 (22:30 배포, f3fce00): 나무 모양 개선

- 확대하면 나무 둘레에 보이던 눈 결정체(6갈래) 모양을 없앴습니다. 원인은 비스듬히 내려다볼 때 세로 카드가 납작하게 눌려 보이는 것이었습니다. 이제 가파르게 내려다볼수록 세로 카드가 흐려지고 윗면(수관) 카드로 넘어갑니다.
- 카드 가장자리를 부드럽게 처리했습니다. 세로 카드는 좌우와 윗변, 수관 카드는 원형으로 흐려서, 수관과 그림자가 직선 다각형으로 잘려 보이던 문제를 없앴습니다.
- 그림자 패스에서는 태양 방향과 나란한 카드를 더 빨리 흐려서, 가느다란 직선 띠 그림자를 없앴습니다.
- **열기구 시점 간헐 멈춤(미해결):** 이 PC에서는 조작을 섞어도 끊김이 0건이었습니다. CPU를 4배 느리게 제한하면 50ms 끊김이 20초에 21회 발생하고, 긴 작업은 50~60ms입니다. 원인은 메인 스레드 부하입니다(보행자·교통 갱신과 렌더 제출로 추정). 다음 작업 과제로 남깁니다.
