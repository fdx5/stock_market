# 제자리 360도 자동 회전

2026-10-11 사용자 요청: 건물 개선 배포 후, 상승/하강 버튼 아래에 회전 버튼 하나를 추가한다.

- 회전 버튼을 누르면 현재 드론 위치에서 약 90초에 한 바퀴씩 계속 회전한다.
- 현재 시야 기울기를 유지한다. 다시 누르면 마지막 방향에서 정지한다.
- 키보드, 스틱, 상승/하강, 휠, 화면 드래그로 직접 조작하면 즉시 수동으로 돌아온다.
- 제자리 회전과 오토 파일럿은 동시에 켜지지 않는다. 회전을 시작하면 잔류 속도를 없애 제자리에서 시작한다.
- 기존 지면/지붕 높이 안전 검사는 유지한다. 뒤늦게 지면 또는 지붕 정보가 도착한 경우 안전 높이만 보정할 수 있다.
- 착륙과 위치 재설정 시 회전을 해제한다. 별도 타이머, 작업자, 이미지 또는 프레임 루프를 추가하지 않는다.
- 회전 버튼의 켜짐 색상, `aria-pressed`, 시작/정지 이름을 제공한다.

## 확인

비행/회전/오토 파일럿 테스트 15개와 TypeScript 검사, Vite 빌드가 통과했다.
음소거 Chrome 154.0.8037.98의 해운대 직접 비행에서 실제 버튼을 눌러 94초 측정했다.
좌표 세 값과 기울기는 시작/끝이 동일했고 방향은 한 바퀴 이상 계속 변했다.
다시 눌러 정지, 키보드 입력으로 수동 전환을 확인했다. 런타임/WGSL 오류 0건이다.

이 구간 평균 59.35fps, 최저 1초 51.98fps, 실제 출력 2520x1750 / 픽셀 비율 1.75 / high였다.
1440x1000, 390x844, 844x390 화면에서 버튼이 하강 버튼 아래에 있는지 확인했다.
이는 한 지역의 회전 구간 검사이며 전국 비행 최소 50fps 달성을 의미하지 않는다.
건물 상세 로딩 일부 대기와 일반 이동/복귀의 프레임 미달은 이전 배포 기록에 남아 있다.

근거: `tmp/drone-performance-20261010/auto-rotate-v1-chrome/report.json`과 화면.
로컬 API는 보존 공개 스냅샷만 읽고 테스트 브라우저는 음소거로 실행했다.

## 오전 중단 후 이어서 확인

최종 배치·터치 입력·종료 검증과 추가 로딩 수정은
`docs/drone-resume-loading-20261011.md`에 기록했다. 회전 94초 검사는 평균 59.87fps,
최저 1초 실제 렌더 FPS 56.98을 확인했으며 출력 해상도를 유지했다.
일반 이동·복귀의 전 구간 50fps 조건은 여전히 미달한다.
