# 검색 이동의 영화적인 워프 연출

부동산 지도 → 3D 건물뷰 → 드론플레이와 드론 탐험의 검색 이동에 같은 연출을 적용한다. 기존의 짧은 CSS 광선 대신 600개 별의 원근 투영과 가속 궤적, 18개 터널 깊이층, 30개 에너지 곡선, 푸른색·보라색 성운, 렌즈 확장과 수평 광선을 절차적으로 그린다. 영화의 영상이나 로고를 사용하지 않는다. 도착지 이름과 취소/실패 시 재시도는 유지한다.

최소 5초 연출과 실제 목적지 드론 렌더 프레임 확인이 모두 충족되면 600ms 섬광/페이드로 목적지를 보여준다. 목적지가 늦으면 워프 화면을 유지한다. 백그라운드 장면을 멈추지 않는다. 늦게 도착한 콜백과 취소/재시도는 기존 이동 ID로 분리하며 도착 타이머도 해제한다.

별 화면은 고정 크기의 Float32Array와 하나의 2D canvas를 사용하고 최대 30회/초 그린다. 추가 3D context, 다운로드, worker는 만들지 않는다. 3D 출력 해상도/DPR/품질은 변경하지 않으며 2D canvas도 실제 화면 DPR로 생성한다. native dialog가 열리기 전의 0 크기를 ResizeObserver로 보정한다. 종료하면 RAF/observer/listener와 canvas backing buffer를 해제한다. 움직임 감소 설정에서는 정적인 별 배경을 사용하고 회전·가속·섬광을 생략한다.

검증: TypeScript와 V3 production build 통과. 음소거 Chrome 154에서 1440×1000, 390×844, 844×390을 확인했다. 공개 읽기 전용 스냅샷 API를 사용하고 저장/운영 DB를 테스트하지 않는다. tmp/drone-warp/cinematic-v3/report.json에서 실제 canvas 1440×1000, 첫 60회 최대 2D 그리기 1.60ms, 지연 목적지 14.094초까지 실제 프레임을 기다림, 실패 후 재시도, Escape 취소, 모바일 조작 영역과 움직임 감소를 확인했다. 콘솔 오류는 0이다. 이 그리기 수치는 전체 비행 FPS나 로딩 3배 달성을 의미하지 않는다.

실제 검색→워프→도착 영상은 tmp/drone-warp/cinematic-video-v3/warp-preview.webm이다. 해당 실행에서는 목적지 프레임 뒤에 화면을 공개했고 워프는 12.516초, 첫 60회 최대 그리기는 1.30ms였다.

tmp/drone-performance-20261010/cinematic-warp-v3/report.json의 예열된 해운대 자동 비행 6초는 최저 1초 FPS 59.976, p95/p99 16.8ms, 최대 16.9ms였다. Ryzen 7 3700X/RTX 3070, Chrome 154, tidewater-webgpu, 1440×1000 viewport, 실제 2520×1750 canvas/DPR 1.75/high 조건이다. 수동 고도 1019.90m, 자동 속도 최대 200km/h·고도 10~1000m, 모바일 세로/가로 설정과 오류 0도 확인했다. 이 예열된 단일 구간 결과로 최초 로딩·전국·모든 장비의 50fps를 주장하지 않는다. 로딩 성능 변경은 별도 후속 배포로 진행한다.
