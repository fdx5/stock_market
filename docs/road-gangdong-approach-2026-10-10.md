# 강동대교 접속부 추가 수정과 배포 상태

2026-10-10. 운영 기준 main `78319dd33803a40208d0f89c4128fbfc235d64e2`.
배포 준비 브랜치: `release/road-common-20261010`. 운영 배포는 실행하지 않았다.

## 검토 화면에서 재현한 원인과 수정

강동대교의 약 54m 연결 조각(`osm:52874823`, `osm:206425138`)에 각 조각 길이의 1/3 이내에서 검토용 15m 상판을 지면으로 낮추는 처리가 적용돼 있었다. 접속점 높이만 확인하면 통과하지만, 그 앞에서 경사가 급하게 꺾였다.

검토용 높이는 전체 원본 OSM 공유 노드 그래프에서 지상 접속점까지의 도로 길이로 계산하도록 바꿨다. 짧은 조각·분기와 그 다음 교량이 같은 높이 흐름을 공유하고, 화면 경계에서 잘려도 경사를 다시 시작하지 않는다. 내부 노드로 합류하는 램프도 확인했다. XY 교차만으로는 연결하지 않는다. 입력에 실측 횡단보도·정지선 정보가 없으므로 램프 분기에 임의로 그리던 가로 줄도 제거했다.

이 화면의 15m 높이와 최대 약 10% 경사는 **미실측 시각 검증용 설정**이다. 실제 강동대교의 측량값이나 도로 설계 기준이 아니며 운영 코드에 이 높이를 넣지 않았다.

## 운영 기준 소스에 반영한 공통 접속 처리

`roadApproaches.ts`는 공급 자료가 교량·고가와 일반 도로로 확인한 구간이 1.5m 이내의 끝점에서 이어지고 진행 방향도 맞을 때만 접속 보정을 만든다.

- 접속점의 높이와 양쪽 도로 가장자리는 기존 지면 DEM을 따른다.
- 연결된 지상 도로에서 최대 5m 바깥을 읽어 접속 경사를 구한다. 교량 내부의 낮은 하상 DEM으로 상판을 내려 끌지 않는다.
- 최대 90m, 사용 가능한 동일 프로필 구간의 1/3 범위 안에서 경사를 부드럽게 연결한다. 이 길이는 렌더링 보간 범위이며 실측 접속부 길이라고 주장하지 않는다. 중간 상판의 기존 DEM 보간 높이는 유지한다.
- 같은 공식 링크의 짧은 조각은 동일한 접속 정보를 사용한다. 원본 좌표·차로·폭·공식 전체 프로필은 변경하지 않는다.
- 아스팔트·차선·차량 높이의 공통 지면과 교량 측면에 적용한다. 측면의 좌우 높이도 따로 계산해 지면 횡단 경사와 맞춘다.
- 내부 입체 교차, 구조 미확인 도로, 다른 교량 프로필은 접속 대상으로 삼지 않는다.

실측 상판 Z와 정밀도로지도는 여전히 필요하다. 운영 강동대교의 현재 공급 응답을 확보해 시각적으로 검증한 결과라고 보고하지 않는다. 전체 운영 장면·실측 구조 재현과 무영향의 절대 보증은 검증 범위에 포함되지 않는다.

## 확인 결과

기존 77개 검증에 접속부 8개를 추가해 **85개** 검증을 통과했다. 접속점·도로 양끝 가장자리의 높이, 지상 접속 경사, 내부 보간 복귀, 하상 높이 영향 배제, 짧은 조각·역방향·worker 복제, 다른 층·프로필, 양안 접속과 실제 측면 메시를 검사했다. TypeScript와 전체 Vite 빌드를 통과했다. 기존 대형 청크 경고는 남아 있다.

격리된 브라우저의 공통 4장면·교량 34곳을 다시 렌더링했다. 원본 공유 노드 및 지상 접속점의 높이 단차와 브라우저 오류는 0이었다. 강동대교는 표시 범위 650/1,200/1,800m에서도 확인했다. 운영 API나 DB에 연결하지 않았다. 남·북 접속부의 확대 사진은 갱신 PDF에 실었다.

## 배포가 보류된 구체적인 이유

읽기 전용 확인 시 운영 `/api/health`와 원격 main은 계속 `78319dd`였다. Dockerfile은 프런트엔드와 백엔드를 하나의 이미지에 담고, Render 설정은 자동 배포를 켠다. 별도의 프런트엔드만 교체하는 경로는 현재 저장소에 없다.

`backend/app/main.py`의 `_start_admin_retention()`은 재시작 직후 `_admin_retention_loop()`를 시작한다. 방문 기록·종목 검색·허브 이벤트·알림 통계·TOP100 순위를 삭제하는 기존 정리 작업과 집계 재생성이 호출된다. `_global_top100_refresh_loop()`도 재시작 직후 저장 결과를 교체한다.

AGENTS.md는 저장 데이터 삭제의 직접·간접 실행을 금지하며, “배포·테스트·정리라는 이유로 예외를 만들지 않는다”고 명시한다. 따라서 main push·병합·Render 배포 트리거는 실행하지 않았다. 삭제 작업을 다른 경로로 실행하거나 기존 저장 데이터·비밀 설정에 접근하지 않았다.

배포하려면 삭제·교체를 하지 않는 시작 및 저장 경로가 먼저 마련되고 검증돼야 한다. 도로 수정에 임의의 광범위한 백엔드 동작 변경을 섞어 이 조건을 해결했다고 주장하지 않는다.
