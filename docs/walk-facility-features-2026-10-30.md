초기 기능은 `85cfdfc7`로 운영 배포했고, 후속 카메라·눈부심 수정은 `84f0da32`로 배포했다.

## 사용자에게 보이는 변경

- 문패 네 가지와 픽토그램·영문 병기, 매장 간판 다섯 가지, 긴 복도의 양면 목적지 안내판,
  병원/매장의 포스터를 한 층의 기존 간판 아틀라스에 넣었다. 동일 문구의 슬롯 재사용과 6m 폭 제한을 유지한다.
- NPC 대화 말풍선을 확인했다. 앉아서 대화할 때 몸 전체가 돌아 의자와 어긋나는 문제는
  몸을 고정하고 목만 돌리도록 수정했다. 로비 연결 의자의 착석 위치/높이도 보정했다.
- 대형 층에 최대 세 대의 음료 자판기와 36종 메뉴, 캔 배출 애니메이션과 기존 효과음을 연결했다.
  칠성사이다·맥콜·펩시·코카콜라·환타 등 12개 탄산 제품의 브랜드별 색·문자·무늬를
  3D용 캔 라벨로 재구성했다. 메뉴 썸네일, 진열 캔, 배출 캔에 같은 디자인을 사용한다.
  캔 전체는 층당 아틀라스 하나를 공유하고, 선택 시 기존 캔 형상을 해제한 뒤 교체한다.
- 아파트를 제외한 시설의 컴퓨터 모니터에 E 상호작용을 등록했다. 접수대의 검은 모니터에도 화면을 넣었다.
  실제 홈페이지는 **사용자의 최종 지시대로 `https://kospimap.com/map`**이다.
  사용 중인 한 화면에만 iframe을 만들며, 유휴 화면은 공용 미리보기 텍스처를 사용한다.
- 주소/검색어 입력, 홈, 뒤로, 확대/축소, 새 탭, 닫기를 추가했다. 자사 사이트 내부 이동은
  검증한 프레임 메시지로 메모리의 방문 내역에 반영한다. 외부 사이트의 프레임 차단은 우회하지 않는다.
  외부 프레임 내부의 교차 출처 이동 내역은 브라우저 보안상 읽을 수 없다.
  열리지 않을 때 사용할 새 탭 링크는 항상 노출한다. 프레임에는 credentialless와 sandbox를 적용했다.
- 프레임 이름/`inframe=1`을 확인해 `/walk`, `/drive`, `/drone-explore`, `/realestate-map`은
  내부에서 3D를 중복 실행하지 않고 새 탭 안내를 보여 준다.
- 실내 평면도에 **2배 확대/원래 크기** 버튼을 추가했다. 데스크톱 300→600px,
  모바일 190→380px이며 화면 폭을 넘지 않도록 제한한다. 이전 건물 엔진의 층별 지도에도 버튼을 넣었다.
- 마우스가 잠긴 상태에서도 **Esc 한 번으로 나가기**를 실행한다.
  컴퓨터·자판기·층 선택·시야 설정이 열렸을 때는 해당 UI부터 닫는다.
  드론 전체화면에서 CSS가 이륙 버튼까지 숨기던 문제를 수정했다.

## 이동·시야 UI/UX 분석과 개선

| 발견한 불편 | 변경 |
|---|---|
| 실외/실내/드론의 시야각이 달라 전환 체감이 달랐다 | 공통 기본 시야각 70°, 사용자 설정 60~90°. 세로 화면은 자동으로 넓히되 슬라이더의 변화가 유지된다. 출력 해상도는 유지한다. |
| V 전환이 바라보던 방향·피치를 강제로 바꿨다 | 도보의 yaw/pitch를 보존한다. 차량의 정면 시점은 차량 방향을 유지한다. |
| 화면 확대를 닫으면 원래 바라보던 방향을 잃었다 | 컴퓨터·TV·노트북 확대 전의 yaw/pitch를 보존하고 복귀한다. |
| 실내 3인칭이 1.5m로 가까워 몸이 화면을 가렸다 | 기본 2.8m, 사용자 거리 배율 70~140%. 벽 앞에서는 짧게 당기며 아주 가까우면 몸을 숨긴다. |
| 코너에서 보간 중 카메라가 벽을 지날 수 있었다 | 최종 보간 위치도 충돌 검사한다. NPC가 카메라 자체를 밀어내지 않도록 했다. |
| 카메라를 멀리하면 E 도달 거리가 짧아졌다 | 카메라부터의 광선 길이와 플레이어부터의 실제 상호작용 범위를 분리했다. |
| 드론의 3인칭이 벽 앞에서 머리로 꽉 찼다 | 좁은 곳에서는 눈높이로 부드럽게 접고 아바타를 숨긴다. 공간이 확보되면 기존 6m 거리로 복귀한다. |
| 모바일 감도가 크고 작은 손 떨림도 이동했다 | 터치 감도를 낮추고 12% 데드존과 명확한 달리기 문턱을 둔다. 포인터 캡처/해제와 취소를 처리한다. |
| 화면에 이동 조작 위치가 보이지 않았다 | 터치 이동 안내를 노출했다. 시점 버튼은 전환할 모드를 명시한다. |
| 고정된 미니맵 위치가 줄바꿈한 헤더와 겹쳤다 | 헤더 높이를 관찰해 지도 위치를 자동으로 내린다. |
| 도보 달리기가 10.5m/s로 갑자기 빨랐다 | 별도 거리 걷기 엔진은 3.6m/s로 조정하고 발소리 간격을 맞췄다. |

`시야 · 조작 설정`에서 시야각, 감도, 3인칭 거리, 걷기 흔들림, Y축 반전을 조절한다.
설정 중 이동 입력을 멈춘다. C 또는 설정의 버튼으로 시선을 수평으로 돌린다.
설정창은 네이티브 dialog여서 전체화면과 다른 오버레이 위에서도 조작할 수 있다.
설정 값은 실행 중 메모리에만 존재한다.

## 로컬 검증

Chrome headful, `--mute-audio`, NVIDIA RTX 3070 / ANGLE D3D11, Vite 개발 서버.
그래픽 품질과 출력 픽셀 비율은 낮추지 않았다. 아래 결과는 이 환경의 해당 구간에 한정한다.

| 조건 | 출력 / DPR | 평균 FPS | 최저 1초 FPS | p95 / p99 | 최대 프레임 |
|---|---|---:|---:|---:|---:|
| 병원 단지 1층, 도보 6초 | 2514×1277 / 1 | 59.98 | 59.96 | 16.8 / 16.8ms | 16.9ms |
| 동일 장면 CPU 4배 감속 | 2514×1277 / 1 | 33.54 | 31.98 | 33.5 / 33.5ms | 33.6ms |
| 모바일 화면 모의, 도보 6초 | 824×1830 / 2 (뷰포트 412×915) | 59.98 | 59.97 | 16.8 / 16.8ms | 16.9ms |
| 의정부 3층, 도보/6곳 이동 | 2514×1277 / 1 | 59.78 | 56.97 | 16.8 / 16.8ms | 66.7ms |

**CPU 감속 조건은 50fps 목표 미달이다. 실제 휴대폰 검증은 하지 못했다.**
의정부 3층은 카메라 추가 변경 전 측정이며, 장면 점프 시 최대 66.7ms가 있었다.
CPU 감속은 이전 시선 방향의 회차에서 평균 18.57fps도 관측했다. 현재 수치를 고정된 성능 개선율로 보지 않는다.
전체 구간·전국·모든 기기의 성능 목표를 충족했다고 해석하지 않는다.

구조 형상/정점/UV를 바꾸지 않는 96개 제한 생성 중 캐시를 추가했다.
병원 가구 배치는 조건별 약 2.3~3.7초로 변동했다. 방별 `furn.roomTimings`에 시간을 남긴다.
로딩 전체 개선을 일정 비율로 단정하지 않는다. CPU 감속의 큰 병목은 렌더 제출에 남아 있다.
`stats()`의 기존 draw calls/triangles 값은 마지막 후처리 패스 값이므로 전체 장면 지표로 쓰지 않는다.

층 재입장에서 발견한 GPU 텍스처 누수도 수정했다. Three의 `RectAreaLightUniformsLib.init()`이
매번 공용 LTC 텍스처를 새로 만들어 이전 2개가 남았다. 예열과 층 로딩이 같은 초기화 가드를 공유하게 했다.
수정 후 같은 층을 연속 세 번 연 결과 텍스처는 **107→107→107**, 형상은 **2743→2743→2743**이었다.
이는 같은 페이지 안에서 해당 층을 반복 로드한 GPU 자원 검사 결과다.

원시 수치와 검증 결과는 [`walk-facility-features-measurements-20261030.json`](walk-facility-features-measurements-20261030.json)에 기록했다.

통과한 검증:

  문패/간판 변형, 캐시 전후 정확한 형상·normal·UV 일치, 사본 독립성.
