# 첫 차선 표시 대기 후속 수정

기존 47.632초 배포 결과에 대한 후속 수정이다. 차선 전체가 차량·교차로 준비와 상세 아스팔트 재생성을 기다리던 의존성을 제거했다. 기존 출발 지면에 실제 도로 폭의 중앙선·차선·가장자리 선을 먼저 표시하고, 횡단보도·정지선·교차로 상세는 기존 경로에서 준비해 GPU 준비 완료 후 교체한다.

지면 준비를 건물 외벽/돌출부 생성 이전에 요청하고, 첫 차선은 전용 module worker 하나에서 계산한다. 화면 범위와 주변 접속 맥락만 계산하며 원래 도로 고도 프로필과 점선 위상을 보존한다. 실측 건물 외곽 제외와 실제 지면 삼각형에 대한 높이 보정을 적용한다. 지하 도로에는 지상 선을 그리지 않는다. 작업자 기한은 15초이고 장면 종료·상세 표시 완료 시 종료한다. 원본 지면/DEM 버퍼를 전송해 분리하지 않는다. 실패 시 기존 상세 경로가 계속 동작한다.

PC Chrome, RTX 3070, 음소거, Tidewater WebGPU high, 뷰포트 1200×800, 실제 출력 2400×1600 / 2.00에서 새 브라우저 컨텍스트로 순차 측정했다. 출력 해상도와 품질 프리셋을 낮추지 않았다. 방문 기록 및 쓰기 요청은 테스트 브라우저/프록시에서 로컬 응답으로 처리했다.

| --- | ---: | ---: | ---: | ---: |

기존 운영 47.632초는 첫 차선이 상세 경로를 기다리던 결과다. 이제 일반 차선이 먼저 보이며 상세 횡단보도까지 9초에 끝났다는 의미는 아니다. 위 수치는 운영 배포 완료 수치와 구별한다.

최신 main 통합 후 재측정에서는 첫 화면 9.418초, 차선 13.807초(화면 후 4.389초)였다. 곧바로 12초 실제 비행을 실행한 경우 상세 교체는 75.419초에 완료됐고 첫 표시 그룹은 제거, 상세 그룹은 GPU 준비 상태였다. 첫 차선과 전체 상세 완성의 지표를 구분한다. 같은 실행의 실제 렌더 평균은 54.08fps, 최저 1초 40fps, p95 33.3ms / p99 50.2ms / 최대 133.5ms로 최소 50fps에는 미달했다. 오류는 없었다. 원본은 `drone-initial-lanes-release-qa-20261019.json`에 보존한다.

자동 검사 64개 통과: 차선 계산, 도로/지면/교량 경계, 상세 교체 전 첫 표시 보존, 장면 이탈·실패 정리, 작업자 취소/기한, 원본 버퍼 보존, 지하 도로 제외, 기존 상업시설 회귀. 기존 상세 빌더의 모든 차선 속성은 배포 기준과 바이트 비교했다. TypeScript와 전체 Vite 빌드도 확인한다. 실제 비행 FPS는 별도 측정하며 기존 최소 50fps 미달을 이 로딩 개선으로 해결됐다고 주장하지 않는다.

다른 세션의 교통 흐름 변경은 수정하지 않고 최신 main을 병합해 보존했다. 저장 데이터/DB/자격 증명은 읽거나 변경하지 않았다. 재현 스크립트는 `frontend/scripts/check-initial-lanes.py`; 작업 폴더의 `tmp/initial-lanes-qa/`에 원본 JSON/화면을 보존한다.
