# 글로벌 시세 배치 조회의 반복 실패 개선

기존 `global_top100_batch_quote: chunk fetch failed`는 청크 조회의 모든 예외를
같은 경고로 기록했다. 이후 제공된 `crumb handshake failed (_Throttled)`와
`Yahoo v7 quote host failed ... error=_Throttled`는 getcrumb의 HTTP 429가
호스트와 청크까지 중복 전파된 경로임을 확인했다. 공급자가 요청을 제한하는 원인이며,
호스트 경고가 별개의 v7 서버 장애를 증명하는 것은 아니다.
로컬의 실제 AAPL/MSFT/005930.KS 조회는 변경 전후 모두 3개 정상 응답을 확인했다.

반복을 유발하는 코드 경로는 다음과 같다.

- TOP 100은 query1만 조회하고 실패 시 query2로 전환하지 않았다.
- 유효한 인증값이 있어도 시세 서버의 타임아웃·401/403·429·5xx 실패에 대한 대기가 없어
  20초 갱신과 다음 청크에서 같은 실패를 반복했다. 다른 미국 시세 조회도 대기 상태를 공유하지 않았다.
- 30초 이내 인증 갱신 요청은 의도적으로 기존 인증값을 재사용하지만, 호출자는 그것을
  새 값으로 취급해 같은 거부된 인증값으로 다시 요청했다.
- 최초 인증 획득 실패는 원래 HTTP 예외로 전파되어 인증 모듈의 경고 외에 청크 경고를 추가했다.
- Retry-After보다 짧은 대기를 만들 수 있는 음수 지터가 적용되었다.

수정은 공통 `yahoo_batch_transport`를 TOP 100과 미국 지도·ETF 조회에 적용한다.
query1 실패 시 query2로 전환하고, 서버별 동시 요청을 4개로 제한한다.
네트워크/서버 실패는 60초부터 최대 900초, 인증 거부는 300초부터 최대 900초로
대기를 늘린다. Retry-After가 더 길면 그 시간을 준수한다. 대기 종료 후에는
하나의 복구 확인만 허용하며 이전 동시 요청의 성공으로 새 실패를 지우지 않는다.

인증이 실제로 교체된 경우에만 한 번 재시도한다. 최초 인증 실패도
`CrumbUnavailable` 계약으로 통일하여 다음 청크·갱신의 불필요한 요청을 중단한다.
정상적으로 복구된 대체 조회는 청크 경고를 만들지 않는다. 서버별 상태 전환은
호스트·실패 분류·HTTP 상태·다음 확인 시각만 INFO로 기록한다. URL/query/crumb/
쿠키/응답 본문/예외 메시지는 로그에 넣지 않는다. 예상하지 못한 코드 오류는
예외 종류를 경고로 남긴다.

429 인증/시세 실패는 최초부터 최소 15분을 기다리고 반복되면 최대 6시간까지
복구 확인 간격을 늘린다. 쿠키 요청 단계에서 429를 받아도 다음 인증 요청을 보내지 않는다.
한 번의 실제 인증 제한은 INFO 상태 전환으로 기록하고 이후 청크·갱신은 요청하지 않는다.
quoteSummary도 같은 거부된 인증값으로 재요청하지 않고, 401/403·429·5xx에는
엔드포인트 대기를 공유하여 회사 수만큼 같은 실패를 반복하지 않는다.
공급자의 제한 자체를 해제하거나 대체 조회의 성공까지 보장할 수는 없으므로
대체 조회 실패 시에도 마지막 정상 가격/기본정보를 보존한다.

두 서버가 응답하지 않으면 기존 1분 간격 chart 대체 조회와 마지막 정상값 보존을
유지한다. 일부 종목의 잘못된 응답이나 NaN 가격이 다른 정상 종목을 버리지 않도록 검증한다.
DB 스키마·저장·정리 로직은 변경하지 않는다. 테스트는 메모리와 독립 로컬 HTTP fixture만 사용한다.

검증: 실제 소켓 ReadTimeout에서 기본 서버는 첫 실패 1회만 호출하고 3회 갱신의
120개 종목 모두 대체 서버로 복구했다. 인증 거부·429·HTTP-date Retry-After·
복구 확인 동시성·부분 응답·최초 인증 실패·마지막 정상값 보존·ETF 대체 조회를 회귀 검증했다.
