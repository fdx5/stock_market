# SYNAPSE 모니터링 재구성

## 적용 화면

- `/admin/monitor`: 관리자 세션은 전체 관측 화면, 모니터 전용 세션은 기존 권한 범위의 새 3D 화면을 사용한다.
- `/admin/system-atlas`: 기본 보기를 `시냅스 관제`로 교체했다. 운영 요약·서비스·API 성능·외부 연동·요청 추적·DB/캐시·전체 구조·기술 스택 보기는 유지한다.
- 새 서버 API, DB 마이그레이션, 데이터 쓰기/삭제는 추가하지 않았다. 배포는 사용자의 명시적 지시에 따라 기존 main 자동 배포 절차로 진행한다.

## 화면과 상호작용

중앙 코어와 서비스별 색상의 성운을 중심으로 API·Python 모듈·외부 호스트를 입체 공간에 펼친다. 실제 소스의 의존성은 곡선으로, 수신한 완료 요청은 이동하는 광신호로 표현한다. 배경 별과 코어 궤도는 장식이며 구조/통신 수치에 포함하지 않는다.

드래그 회전, 확대/축소, 전체화면, 노드로 카메라 이동, 검색, 영역 필터, 인접 연결 분리, 오류 강조, 신호 속도, 그래픽 품질, 모션 정지, 표본 재생을 제공한다. 오른쪽 패널에서는 연결된 노드와 관측 수치를 탐색하고 하단 로그에서는 실제 API/HTTP 표본과 요청에 연결된 외부 호출을 확인한다. 로그 고정은 수신을 중단하지 않고 현재 목록을 읽는 데 사용한다.

후속 요청을 반영해 기본 3D 영역을 전폭으로 넓혔다. 데스크톱 높이는 기본 820~1,180px, 큰 화면에서는 900~1,250px, 모바일에서는 760px이다. 상세 패널은 검색 또는 노드 선택 때 화면 위에 열리므로 캔버스 폭을 줄이지 않는다. 기본 자동 회전과 정지/재개 버튼을 제공하며 직접 조작한 뒤에는 4초 동안 자동 회전을 유예한다. 모션 감소 설정에서는 자동 회전을 사용하지 않는다. 중심 코어의 반투명 플라즈마 광막, 다중 궤도, 전체 공간을 감싸는 천구 눈금과 성운 배경을 추가했고, 관측 신호가 도착하는 노드에 광반응을 적용했다.

기본 관측 갱신은 1초, 서버/DB 점검은 기존 15초다. 갱신 요청은 중첩하지 않으며 숨겨진 탭의 폴링과 렌더링을 중단한다. 모션 감소 설정, 모바일 배치, WebGL 실패 시 목록 탐색, 그래픽 재연결을 지원한다.

## 데이터 해석과 범위

- 신호는 완료된 요청을 수신 후 압축 재생한다. 전송 중인 패킷 자체 또는 실제 요청 소요 시간을 애니메이션으로 표시하는 것이 아니다.
- 정적 의존성이 존재한다고 그 요청에서 모든 모듈을 실행한 것으로 처리하지 않는다.
- 요청 문맥이 확인된 외부 HTTP만 API 경로와 연결한다. 문맥 없는 호출은 별도의 집계점으로 표시한다.
- SQL, SDK/httpx, SMTP, 브라우저 직접 통신 등 기존 수집 범위 밖의 통신을 관측했다고 표시하지 않는다.
- 모니터 전용 권한에서는 `/monitor/graph`, `/monitor/pulse`만 요청한다. 외부 HTTP/DB 점검은 `계측 미제공`으로 표시한다. 사용자 행동 기록은 API 호출과 분리한다.
- 계측 서버의 메모리 버퍼에 포함된 최근 60초 표본이다. 화면에서 추가로 보관하는 연결은 과거 관측 경로이며, 새로운 신호가 없는 연결에 가짜 통신을 생성하지 않는다.
- 인증 토큰 처리와 관리자/모니터 접근 제어는 기존 방식을 유지한다. 신규 개인정보 수집 또는 저장 기능은 추가하지 않았다.

## 렌더링

`synapseModel.ts`가 실제 구조 항목과 관측 경로를 정규화하고, `synapseScene.ts`가 Three.js/WebGL 버퍼로 렌더링한다. 전체 연결선·노드·신호는 각각 한 번의 배치 렌더링으로 처리하며, 곡선상의 이동은 GPU 셰이더에서 계산한다. 구조 선에는 알파 합성을 적용해 대규모 연결이 흰 덩어리로 포화되지 않게 한다. 광신호와 노드는 가산 합성을 사용한다.

연결 수에 따른 선 밝기와 곡선 세분화, DPR 제한, 30fps 절전 모드, 제한된 DOM 라벨 및 로그를 사용한다. 노드는 16,000개, 연결은 40,000개로 표시를 제한하고 초과 항목을 화면에 안내한다. 그래픽 갱신 시 카메라 위치와 수신 표본 중복 방지 상태를 보존한다. 리소스는 화면 종료 시 해제한다.

## 검증

- TypeScript 검사 및 Vite 운영용 빌드 성공. 기존 다른 기능의 500kB 초과 청크 경고는 남아 있다.
- `frontend/scripts/test-synapse-model.mjs`: 경로 중복 제거, 인접 목록, 관측된 HTTP 연결, 문맥 없는 호출, 신호 중복 제거, 메서드별 가중 평균, 빈 관측 상태 통과.
- `frontend/scripts/test-synapse-observatory.py`: 읽기 전용 소스 목록으로 만든 373개 노드·5,399개 연결, 검색/선택/인접 연결/오류 필터/추적/로그 고정/속도/모션 감소/품질/일시 정지/수신 실패/복구/빈 데이터/WebGL 손실/인증 만료 통과. 360, 390, 768, 1024, 1440, 1920px에서 가로 넘침 없음.
- `frontend/scripts/test-synapse-scale.py`: 합성 부하 데이터 6,085개 노드·33,110개 연결, 검색과 렌더링, 기존 모니터 진입 경로, 모니터 전용 접근과 잠금 화면 통과. 운영용 빌드의 로컬 headless Edge 검사에서 초기 준비 약 1.01초, 관측 52fps, DOM 1,103개. 이 값은 해당 테스트 실행의 측정이며 모든 GPU/기기에서의 성능 보장이 아니다.
- 브라우저 API는 전부 로컬 테스트 응답으로 대체했다. Python 앱 기동, 실제 관리자 인증, DB 연결, 운영 저장 데이터 접근을 하지 않았다.

최신 main과 합친 최종 확대/자동 회전 버전도 별도로 검증했다. 소스 구조 403개 노드·5,786개 연결, 합성 부하 6,096개 노드·33,124개 연결에서 통과했다. 로컬 운영 빌드의 부하 실행 표본은 준비 0.59초·58fps·DOM 1,112개였으며, 기본 자동 회전과 정지/재개, 800px 이상 데스크톱 높이, 1,200px 이상 캔버스 폭, 접이식 상세 패널을 추가 검사했다. 이는 특정 테스트 환경의 측정이다. 최종 검증 결과는 원 작업 폴더의 `tmp/synapse-20261019/release-qa/`에 보존한다.

결과 및 화면: `tmp/synapse-20261019/report.json`, `scale-report.json`, `synapse-desktop.png`, `synapse-390.png`, `synapse-scale.png`, `synapse-monitor-access.png`.

## 재실행

프런트엔드 디렉터리에서 `node scripts/test-synapse-model.mjs`를 실행한다. 브라우저 검사에는 로컬 Vite 또는 운영 빌드 미리보기 주소를 `TEST_BASE_URL`로 지정하고 저장소 루트에서 두 Python 스크립트를 실행한다. `frontend/vite.synapse-task.config.mjs`는 운영 API 프록시가 없는 격리 검사용 Vite 설정이다.
