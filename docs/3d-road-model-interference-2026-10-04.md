# 도로와 3D 건물 모델 간섭 긴급 수정

## 이전 검사에서 놓친 원인

등록 건물 경계와 도로를 비교하는 것만으로는 최종 3D 화면을 검증할 수 없었다. VWorld 3D 모델은 등록 경계와 별개 자료이며, 등록 건물에 매칭된 모델에 경계 밖 부속 구조물·돌출 부분이 포함될 수 있다. 가까운 건물 교체와 바깥 고리 아파트 교체가 각각 별도 경로였다. 경계 자료만으로 도로를 잘라 보호해도 교체 모델은 그 도로로 뻗을 수 있었다.

운영 `bc69b496` 신곡동 신동아파밀리에에서 실제 WebGPU 건물 메시를 도로 좌표로 변환해 검사했다. 등록 경계와 도로의 겹침은 거의 없었지만, **실제 렌더링된 건물 메시의 도로 겹침은 약 49.516㎡**였다. 따라서 이전의 등록 경계 검사 통과를 완료 기준으로 삼은 것은 부족했다.

같은 원본에는 층수 1, 높이 0, 건축면적·연면적·대지면적이 모두 명시적 0이며 용도·건물명이 없는 자료도 있었다. `dong_nm`의 `2004-1306` 같은 허가 식별자는 실재 건물의 근거가 아니다. 기존 0층 검사만으로는 이 자료가 건물 또는 도로 보호 장애물로 남았다.

## 수정

- 가까운 3D 모델과 바깥 고리 3D 모델 **두 교체 경로** 모두, 보정 이동량 적용 후 도로 범위 밖 등록 경계가 아닌 영역으로 침범하는지 검사한다. 침범하는 모델은 쓰지 않고 등록 경계 기반 기존 건물을 유지한다. 도로를 더 잘라 잘못된 모델을 보호하지 않는다.
- 모델 정점·모서리·삼각형 중앙을 검사한다. 모서리는 최대 0.5m 간격으로 검사하여 양 끝이 도로 밖이어도 중앙에서 교차하는 경우를 잡는다. 검사는 모델을 교체할 때 한 번 수행하며 프레임 루프에는 넣지 않는다.
- 명시적 면적 0인 위의 1층 불완전 자료를 프런트 로더, 도로 보호 경계, 바깥 고리 워커, 백엔드에서 같은 규칙으로 제외한다. 면적 누락, 측정 높이, 양의 면적, 실제 용도·건물명, 2층 이상 자료는 이 추가 조건으로 제외하지 않는다.
- 이전 추정 건물 응답을 읽지 않도록 브라우저 `buildings-v6` / IndexedDB 7, 서버 `bldg-v5`로 버전을 올린다. 설정·다른 종류의 저장소는 보존한다.

## 검증

실제 렌더 메시와 실제 아스팔트 삼각형의 수평 투영 겹침을 다시 검사했다. 0.01㎡ 초과는 실패로 처리한다. 원본 경계가 아니라 교체 완료 후 그려진 메시를 대상으로 한다.

| 로컬 실제 데이터 장면 | 검사한 건물 메시 | 도로 겹침 |
| --- | ---: | ---: |
| 신동아파밀리에 | 25 | 0건 |
| 강남데시앙포레 | 20 | 0건 |
| 설봉1차푸르지오 | 29 | 0건 |

관련 프런트 회귀 검사 36개, 백엔드 검사 22개 통과. 저비용 continuation을 같은 프레임의 남은 시간에 처리하는 기존 스케줄러 변경에 맞춰 오래된 테스트의 '프레임당 무조건 1개' 가정도 수정했다. 실제 메모리·GPU 성능 개선 수치로 도로 겹침 해소를 대신하지 않는다.

반복 검증 명령(저장소 루트, Playwright/Edge, Shapely 필요):

```powershell
python frontend/scripts/capture-road-building-geometry.py shindonga https://kospimap.com production-shindonga
python frontend/scripts/check-rendered-road-buildings.py production-shindonga
```

두 번째 스크립트는 `tmp/qa-geometry-python`에 설치한 Shapely도 사용할 수 있다. 원본 응답과 큰 메시 JSON은 tmp에만 보관하고 API 키가 포함된 요청 URL은 기록하지 않는다. 이 검사는 수평 투영 면적이 있는 건물 표면을 대상으로 하며, 전국 데이터 전체에 대한 무조건적인 보증은 아니다. 새 신고 위치는 CASES에 추가하여 동일 검사를 반복한다.
