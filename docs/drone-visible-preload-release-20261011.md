# 드론 이동 시 선행 상세 로딩 개선 결과 — 2026-10-11

현재 운영 버전 `0e05c14`와 이번 릴리스 후보 V15를 같은 경로에서 비교했다. 해운대에서 화면에 진입한 상세 건물의 미완성 대기량은 78.6% 줄었다. 출력 해상도, 픽셀 비율, 모델 형상, 재질, 차량 수를 낮추지 않았다. 전체 지역의 로딩 3배와 모든 구간 50fps 목표는 아직 달성하지 못했다.

## 측정 조건

- Ryzen 7 3700X / RTX 3070, Chrome 154.0.8037.98, `--mute-audio`, tidewater-webgpu.
- 뷰포트 1440×1000, 실제 캔버스 2520×1750, DPR 1.75, high 품질. 각각 새 브라우저에서 실행했다.
- 고도 300m AGL, 속도 200km/h, 12초 정지 후 북쪽·동쪽·남쪽 각 1km 이동, 총 66초 측정.
- 타일은 카메라 시야 1100m, 건물은 800m 안의 등록 건물 전체 층을 기준으로 측정했다. 실제 상세 모델의 GPU 버퍼와 소스 배열·버전이 준비된 경우만 완료로 인정했다.
- 건물·ms는 보이는 미완성 건물 수에 대기 시간을 곱해 누적한 값이다. 한 건물의 로딩 시간이나 페이지 전체 속도와 다르다. 원본 상세 데이터가 없는 건물도 미완성에 포함한다.
- 외부 GIS 응답과 브라우저 실행 편차가 있다. 배포 직전 재측정한 운영 기준과 최종 후보를 비교하고, 원래 기준 측정도 보존했다.

## 반영 내용

1. 상세 모델을 작은 증분 청크로 누적한다. 기존 전체 모델을 매번 복사·워커 재전송·GPU 재업로드하지 않고 변경된 정점과 인덱스 범위를 업로드한다. 모든 원본 정점·재질·형상을 보존한다.
2. 기존 워커에서 건물 색상과 정확한 경계 계산을 수행한다. 새 워커를 늘리지 않고 메인 스레드의 반복 계산을 줄인다.
3. 정적 지형·건물 GPU 준비 대기열에서 매 프레임 바뀌는 차량·배의 버퍼를 제외한다. 실제 화면 렌더링은 동적 버퍼를 계속 갱신한다. 상세 GPU 준비 실패·15초 기한 초과는 기본 건물을 유지하고 재시도한다.
4. 정적 모델의 버퍼·파이프라인·번들 캐시를 재사용한다. 입력 배열·버전·재질·그림자·그리기 범위가 달라지면 정확히 무효화한다. 준비 예산과 출력 품질을 유지한다.
5. 차량 경로 후보는 주변 교차로 변경에만 다시 계산한다. 기존 운영 코드와 900프레임의 실제 차량 행렬·색상·경로가 동일한지 검증했다. 차량 GPU 업로드는 현재 살아 있는 인스턴스 범위만 전송한다.
6. 장면 종료 시 상세 청크, GPU 버퍼, 워커와 차량 경로 캐시를 해제한다. 저장 데이터와 DB는 수정하거나 삭제하지 않았다.

## 검증 및 근거

- V15 TypeScript 검사와 독립된 출력 디렉터리의 프로덕션 빌드 통과.
- GPU 버퍼 변경·준비·번들 순서·재질 수명, 상세 증분 추가·취소·정확한 색상·경계, 차량 경로 동일성, 타일 우선순위·프레임 예산의 순수 테스트 123개 통과. 기존 DB를 사용하지 않았다.
- 최종 원본 측정: `tmp/drone-visible-loading-20261011/stage3-baseline-haeundae-repeat/report.json`, `stage3-v15-haeundae-gpu/report.json` 및 망미동 최종 비교 보고서.
- PC·모바일 부동산 지도 → 3D 건물뷰 → 드론 → IME 검색 → 워프 이동 검증 통과. 속도 200km/h·고도 1000m 설정, 이전 세션 종료·캔버스 분리 확인, 런타임 오류 0. 워프는 각각 6.09초·5.69초였다.
- 별도 반복 이동 검증은 최초 드론 장면 대기에서 90초 타임아웃이 발생했다(런타임 오류 0). 이 실행을 통과로 처리하지 않았다. 비행 비교와 지도 진입은 정상이며, 별도 반복 이동 검증은 운영 반영 후 재확인한다.
- 운영 배포 확인은 공개 health의 전체 커밋 SHA와 HTML·정적 파일만 사용한다.

전국 3배와 50fps 유지, 상세 원본이 없는 건물, 밀집 지역의 메모리 및 긴 프레임은 후속 개선 대상이다. 이번 배포는 검증된 선행 로딩 개선분이다.
