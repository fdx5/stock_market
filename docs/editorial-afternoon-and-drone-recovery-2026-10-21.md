# 오후 영상 갱신과 드론 렌더링 복구

## 영상 수집

- 한국시간 매일 08:00: 어제 00:00 이상 ~ 오늘 08:00 미만에 공개된 영상.
- 한국시간 매일 16:00: 오늘 00:00 이상 ~ 오늘 16:00 미만에 공개된 영상.
- 각 수집 시점의 누적 조회수로 한국/미국 후보를 별도로 정렬한다. 해당 시간대에
  발생한 조회수 증가량을 의미하지 않는다. 발견한 후보 내 상위 20개다.
- 서버는 30초마다 회차를 확인하며 실패는 1분 후 재시도한다. 독립 GitHub 수집기는
  23:00/07:00 UTC에 실행한다. GitHub 예약 실행은 지연될 수 있다.
- 날짜와 window_end를 함께 비교하여 오전 성공/실패 기록이 오후 갱신을 막지 않는다.
  브라우저는 기존 20초 자동 확인으로 새 회차를 표시한다.
- 기존 오전 아카이브 주소는 보존하고 오후는 날짜 아래 `16/` 경로에 추가한다.
  서버 파일도 독점 생성만 사용한다. 이전 회차를 삭제/교체하지 않는다.
- 오늘 실제 공개 영상 수집: 한국 후보 135개, 미국 후보 102개에서 각각 20개 확인.
  게시시각은 모두 2026-10-21 00:00~16:00 KST 범위다. 16:53경 수집한 누적 조회수다.
  두 새 번들을 추가하여 배포 직후에도 오늘 오후 회차를 바로 읽을 수 있게 한다.

## 드론 복구 결함

원래 WebGPU의 uncapturederror 처리는 로그만 남겼다. 비동기 검증 오류/거부된 GPU
작업은 render()의 try/catch로 잡히지 않아, CPU의 비행 좌표와 팻말이 움직여도
GPU가 제출을 거부하는 화면을 계속 정상으로 취급할 수 있었다. 이미 shown이 된 뒤의
GPU 진행 정지도 최초 프레임 watchdog의 감시 대상이 아니었다.

GPU 검증 오류를 실패로 전파하고, 초당 최대 한 번의 비동기 큐 완료 확인으로 8초를
넘긴 GPU 정지/작업 거부를 감지한다. 대기 작업은 하나만 유지한다. 해제 시 리스너도
제거한다. 오류 뒤 WebGL로 전환할 때 새 세션에 기존 비행 객체, 좌표/방향/시점/자동비행
설정을 연결한다. 이전 세션의 팻말/컨트롤은 제거하고 입력을 새 세션에 연결한다.
전환 시 자동 진입 effect가 다시 실행되지 않던 문제도 수정했다.

WebGL 프로그램 준비 확인 타이머에서 폐기된 프로그램이 예외를 내도 완료 Promise가
끝나도록 보완했다. 예외가 타이머 밖으로 빠져 전체 장면의 컴파일 대기 상태가 영구히
남는 경로를 막는다.

Windows Chrome의 실제 WebGPU 검증 오류(동일 GPU 버퍼 간 잘못된 복사)를 주입했다.
WebGL 자동 전환, 이전 세션 종료, 동일 비행 객체와 좌표 보존, 이후 키보드 이동에
따른 카메라/실제 배경/팻말 변화가 확인됐다. 복구 뒤 캔버스는 2520×1575로 유지됐다.
검증 중 API는 공개 설정 조회 외에는 로컬 응답으로 격리했으며 DB를 실행하지 않았다.

Windows에서 실행한 Playwright WebKit의 WebGL 경로에서도 실제 배경과 카메라 이동을
확인했다. 이것은 macOS Safari 실기 검증이 아니다. 실제 Mac 장치의 GPU/OS 버전에서
사용자가 겪은 원래 드라이버 오류 자체를 재현했다고 주장하지 않는다.

성능 한계: 개발 환경의 WebKit 실행에서는 약 8~11 FPS로 50 FPS 목표를 충족하지
못했다. Chrome의 복구 후 표시값 52.2 FPS는 특정 시점 값이며 전 구간 최저 FPS가
아니다. 모든 Mac/모든 지역에서 50 FPS가 검증됐다는 의미로 사용하지 않는다.

데이터 보호: DB 직접 접근, 기존 파일/테이블 삭제, 마이그레이션 없음.
