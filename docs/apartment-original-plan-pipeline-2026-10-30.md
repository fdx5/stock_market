# 아파트 원본 도면 기반 모듈 · 2026-10-30

## 사용자 요청과 동작

모든 아파트에 같은 경로를 적용한다. 특정 단지명으로 분기하지 않는다.
단지 상세 카드를 클릭하면 원본 도면 목록만 준비하고, 실내에서 주택형을 선택할 때
해당 기본형/확장형 이미지 한 장을 받아 숫자 평면 데이터로 해석한다.
실제 도면 분석 결과는 기존 가상 패턴보다 우선한다. 벽 위치를 템플릿으로 다시
만들거나, 외곽에 맞춰 늘리거나, 무작위로 반전하지 않는다.

1. 네이버 공개 검색 HTML에서 단지 ID를 읽는다. 단지명·법정동·지역 코드를 대조하고,
   직접 검색 결과는 위치도 대조한다. 동명이인·모호한 매칭은 실패로 남긴다.
2. 공개 `groundPlanGallery.naver`의 JSON에서 주택형 ID, A/B 타입명, 전용/공급면적,
   기본형/확장형, 원본 이미지 주소를 구분한다. 지도 URL의 압축 layer나 갤러리 썸네일
   선택 번호를 주택형 ID로 사용하지 않는다.
3. 선택 이미지의 픽셀을 무료 OpenCV와 로컬 Tesseract로 처리한다. 방 이름, 표기 치수,
   벽 중심선, 관측된 통로·문 틈·창호를 숫자로 전달한다. 비정형 공간은 직교 사각형으로
   분할하고 같은 공간의 내부 분할선은 개방한다. 가구는 큰 공간 조각을 기준으로 배치한다.
4. 숫자 OCR와 한국어 공간 이름 OCR를 분리한다. 워터마크 아래 회색 획을 별도로
   복구하고, 치수를 전체 이미지 폭이 아닌 해당 치수선 양 끝점에 연결한다. 두 축의
   구간 치수 사슬이 검증되면 구간별 좌표를 적용하고, 그렇지 않으면 검증된 전체 치수
   축척을 유지한다. 표기 치수를 읽지 못한 경우 전용면적 기준 보정임을 표시한다.
   방 구분, 통행 연결, 치수 충돌, 면적 검증 실패 시 `needs_review`로 구분한다.
5. 내부 실거래 단지 목록에 없는 아파트도 PNU의 주소·지역과 원본 주택형을 사용한다.
   원본에서 확인한 전용면적으로 세대를 선택할 수 있으며, 가짜 단지 ID를 `/units`에
   보내거나 84㎡를 기본값으로 만들지 않는다.

같은 면적의 여러 주택형은 사용자가 타입을 고른다. 면적은 0.005㎡ 이내 일치만 자동
매칭한다. 사용자의 후속 지시에 따라 원본 미확인·분석 실패 시에는 확인된 전용면적과
준공 시기의 구축 판상형/신형 3·4베이 평균 구조를 적용한다. 입장 전과 결과 화면 모두
평균 추정이며 실제 벽·문·창문과 다를 수 있음을 표시한다. 2/3/4베이를 직접 고를 수도
있다. 면적 자료가 없으면 임의 84㎡를 만들지 않는다. 별도 `가상 구조 비교`에서는
512개 케이스를 사용할 수 있다. 이 경로는 아파트에만 적용하며 일반 건물과 분리한다.

## 속도·자원

- 신도6차/강남데시앙포레/은마의 공개 원본 목록 조회를 실제 HTTP로 확인했다.
  로컬 첫 조회는 약 0.34/0.38/0.49초였다. 서버·네트워크별 보장은 아니다.
- 이미지·분석은 주택형별 single-flight로 중복 요청을 공유한다. 메타데이터 96개,
  이미지 24개/24MiB, 분석 48개, 브라우저 결과 32개로 메모리를 제한한다.
- 외부 다운로드 동시성은 2개이며 응답 크기와 연결·읽기 기한을 제한한다.
  분석은 4M픽셀 초과 원본을 임의 저해상도로 바꾸지 않고 검토 대상으로 남긴다.
- OCR 언어 모델은 빌드에 포함한다. 첫 사용 때 모델 다운로드, 유료 AI API 호출,
  로그인 세션·쿠키·외부 토큰 사용이 없다. 원본 이미지는 저장소에 일괄 수록하지 않는다.
- DB/회원 데이터 수정·삭제·마이그레이션이 없다. 프로세스 메모리 캐시는 재시작 시
  초기화된다. 신규 도면 분석과 GPU 실내 로딩은 별도이며 시간을 구분해 측정한다.

## 검증과 한계

신도6차 81B의 실제 주택형 ID는 6, 전용 59.90㎡/공급 81.19㎡이고,
81A는 ID 1, 전용 59.99㎡/공급 81.28㎡이다. 108형은 전용 84.92㎡, 154형은 127.07㎡다.
4개 주택형 원본의 한국어/숫자 OCR와 구조 검증을 통과했다. 로컬 첫 분석 요청은
81B 2.68초, 81A 2.65초, 108 2.63초, 154 4.06초였다. 이미지 분석 데이터→브라우저
실내 렌더링과 A/B 전환, 소파와 각 침실의 침대 배치도 확인했다.
현장 실측·인테리어 공사 후 상태를 인증하는 모델은 아니다. 가구·재질·일부 공간 용도는
추론과 연출이며 UI에서 구분한다. 전국 모든 단지의 원본 보유/자동 해석 성공을 검증한
것으로 보고하지 않는다. 사선 벽, 복층, 글자가 가려진 자료 등은 검토 대상일 수 있다.

해상도 2514×1277, DPR 1, 음소거 Chrome, 이미지 기반 실내의 5초 걷기 측정에서
81A 평균 59.98fps/최저 1초 59.96fps/p95·p99 16.8ms/최대 16.9ms,
81B 평균 58.59fps/최저 1초 54.97fps/p95 16.8ms/p99·최대 33.4ms였다.
Vite 개발 서버와 실제 로컬 원본 API 조건이다. 81B는 목표 60fps에 미달하며, 두 사례가
전국/모든 장비의 성능 보장은 아니다. 출력 해상도와 DPR은 낮추지 않았다.

백엔드 독립 테스트 11개는 원본 타입·면적 보존, 동명 단지 거부, 선택 이미지 중복 다운로드
방지, 임의 호스트 차단, 실제 픽셀 변경의 구조 반영, 잘못된 도면의 실패 처리를 검증한다.
프런트엔드는 원본 구조 보존·타입 불일치·NaN 거부와 5개 면적×512개 가상 구조의
면적/연결성/겹침/개구부 범위를 검증한다. 모든 테스트는 기존 DB를 사용하지 않는다.

## 원본 미보유 표본 조사

서울 강남·노원, 경기 의정부, 부산 해운대 4개 지역에서 최근 거래된 구축/신축 각
16개, 총 32개 단지의 공개 메타데이터를 조사했다. 단지 매칭 성공 17개 중 14개는
일부 이상 원본이 있었고 3개는 모든 주택형의 이미지가 없었다. 매칭된 79개 주택형 중
16개(20.3%)는 원본 이미지가 없었다. 별도 15개 단지는 이름/ID 매칭 실패로 원본의
실제 유무를 확인하지 못했다. 이들을 '네이버에 도면 없음'으로 집계하지 않는다.
전국 무작위 표본이 아니므로 전국 미보유율로 일반화하지 않는다. 광주 북구도 조회했으나
표본 거래 목록이 비어 실제 집계에서 제외했다. 원자료는 같은 디렉터리의
`apartment-drawing-coverage-sample-2026-10-30.json`이다.

## 함께 포함한 다양화

8개 구조 계열·512개 가상 구조, 12개 재질 팔레트, 64개 가구 구성 시드,
소파 10종·침대 12종·옷장 6종·책상 4종·미디어장 4종·세탁가전 4종·주방 소형가전
4종 등을 구성한다. 이 케이스를 실제 아파트 평면도 종류 수라고 표시하지 않는다.
LH 무료 원본 자료실은 252건/52개 사업지구로 제한된 별도 참고 자료이며 주소를 추정
매칭하지 않는다. 출처와 라이선스는 `frontend/public/3d/walk/SOURCES.md`에 기록한다.

원본 분석으로 나뉜 공간 조각에 조명이 중복 생기지 않도록 하고, 아파트의 낮 조명·
창밖·태양·노출을 함께 낮춰 벽과 바닥 재질이 과하게 날아가지 않도록 조정한다.

## 현장 테스트 후 구조·이동 보정

- 가구 배치가 끝난 뒤 벽·문·닫힌 가구 윤곽의 내부까지 검사하여 보행 여유가 있는
  바닥에 입장시킨다. 거실 중앙에 탁자/소파가 있어도 그 위에 생성하지 않는다.
  앉기/눕기에서 이동 키로 일어나며 복귀 위치가 가구 안쪽이면 빈 바닥으로 보정한다.
- 문 앞과 문 사이의 경로를 가구보다 먼저 확보한다. 탁자는 축소/옆 이동 후 배치하며
  통로가 없으면 생략한다. 작은 욕실의 통로를 막는 샤워 유리 칸막이는 설치하지 않는다.
- 벽은 영역마다 독립된 얇은 면을 만드는 대신 공통 좌표의 두께 있는 구조로 합친다.
  개방된 분할 경계에는 문설주를 만들지 않는다. 반올림으로 생긴 2 mm 미만 충돌
  선분은 제외한다. 매우 짧은 잔여 선도 사람 반경만큼 통로를 막던 원인이었다.
- 문은 여러 분할 영역에 걸친 실제 벽 개구부 전체에서 위치/너비를 구한다. 문짝
  선의 방향으로 경첩/열림 방향을 보조 추론한다. 넓은 주방 통로를 문 너비 상한으로
  버리지 않고 개방한다. 외곽의 관측된 문짝으로 현관문을 복구한다.
- 같은 구간의 문/창 중복을 제거하고 실제 창호 선이 없는 빈 외곽을 창으로 만들지
  않는다. 같은 방의 바닥 높이/재질을 통일하며 문턱은 바닥과 같은 면에 겹치지 않는다.
- 독립 회귀 검사는 탁자 내부 생성 금지, 보행 여유, 완전히 막힌 방 거부, 영역 분할선의
  기둥 없음, 외벽 코너 닫힘, 반올림 잔여 충돌선 제거를 확인한다. 실제 브라우저에서
  원본 4개 평형의 입장 직후 키 이동, 방문 연결과 가구 포함 통행도 별도로 검사한다.
- 주방은 냉장고와 싱크/인덕션 일체형 조리대를 함께 배치한 후 식탁·장식으로 넘어간다.
  소형 냉장고의 실제 모델 깊이와 충돌 크기도 함께 조정한다. 6개 원본 해석 사례와
  전용 39/59.97/84.97/114.9/135㎡×512개 가상 구조에서 필수 설비 배치 검사를 통과했다.
- 모든 아파트는 입장 전에 실제 벽·가구·완전히 열린 문짝을 포함한 0.08m 보행 격자에서
  사람 반경 0.24m로 거실→침실/주방/욕실/드레스룸 등의 연결을 확인한다. 실패 시 해당
  실내를 열지 않는다. 원본 자동 배치 실패는 면적이 확인된 평균 추정 구조와 별도로
  안내한다. 가상 가구 배치 실패는 구성을 바꿔 선택 화면에서 재검토하게 한다.
- 강남 데시앙 포레(네이버 107799)의 81A/114A 원본을 추가 검사했다. 전체 치수 없이
  구간 치수만 있는 도면의 축척, 침실 영역 병합, 얇은 욕실 문짝/창호 구분과 두 욕실
  인식을 보정했다. 두 주택형의 침실 3개와 욕실 2개 모두 가구 포함 통행 검사를 통과했다.
  56개 기본형/확장형 전체의 자동 인식 성공을 뜻하지 않는다. 116B 확장형은 현재 치수
  충돌로 검토 대상이며 평균 추정 안내 경로를 사용한다.

강남 데시앙 포레 최종 개발 서버 측정(2514×1277, DPR 1, 음소거 Chrome, 5초 걷기):
81A 평균 59.97fps/최저 1초 59.93fps/p95·p99 16.8ms/최대 17.5ms,
114A 평균 59.98fps/최저 1초 59.76fps/p95·p99 16.8ms/최대 20.3ms.
이는 두 사례의 제한된 검사이며 전국·모든 장비의 성능 보장이 아니다.
