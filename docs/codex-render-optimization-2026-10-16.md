## 변경 동작

셰이더 분석은 작업 종류·매크로·전체 소스가 같은 동시 요청에 하나의 Promise를
공유한다. 완성된 WGSL 문자열은 최대 64건·2MiB 예산의 메모리 캐시에서 재사용한다.
GPU 리소스와 재질별 바인딩은 공유하지 않는다. 실패한 요청은 재시도가 가능하며,
동기적 `postMessage` 실패도 대기 목록에 남지 않는다. 유휴 워커 종료는 유지했다.

장면 동기화는 매 프레임 큰 Set을 비우고 다시 채운 뒤 조회하던 처리를 재사용 목록과
네이티브 메시의 동기화 번호로 바꿨다. 보이지 않는 객체의 해제, 업로드 대기 중인
이전 형상의 보존, 다중 재질의 보존 규칙은 그대로다. 재질 사용 집계를 위한
`flatMap`의 임시 배열 생성도 줄였다. 여기서 다루는 해제는 메모리의 렌더 리소스이며,
저장 데이터·DB·브라우저의 기존 저장소를 삭제하는 처리는 추가하지 않았다.

## 진행·토큰 패널

`http://127.0.0.1:5475`. 코드·상태 파일은 원래 저장소의
`tmp/codex-perf-monitor-20261016/`에 있다. 2초 간격으로 작업 단계와 세션 로그의
숫자형 사용량만 보여준다. 입력에는 캐시 입력이 포함되며 결제 금액이나 잔여 한도가 아니다.
대화·토큰 원문·환경 설정·DB는 HTTP 응답에 노출하지 않는다.

PowerShell→Python 파이프로 한글을 갱신하면서 생긴 `???`는 UTF-8 파일 직접 수정으로
복구했다. 상태 파일·HTTP의 UTF-8 선언·모든 작업 기록에 정상 한글이 있고 `??`가
없는지 확인했다. 이후 상태 갱신에도 한글을 셸 파이프로 전달하지 않는다.
