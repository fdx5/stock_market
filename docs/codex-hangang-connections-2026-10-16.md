## 변경한 동작

- 공식 교량 링크의 확인된 상판 구간(`core`)을 연속해서 생성한다. 기초 도로 자료가 중간에 120m 넘게 누락되거나 타일에 도로 조각이 하나도 없어도 교량이 끊기지 않는다. 시작 장면과 이동 타일에 같은 규칙을 적용했다.
- 왕복 상판 병합 시 양 끝, 내부 다섯 지점, 폭과 높이를 확인한다. 중점이 가까운 것만으로 교차 교량·다른 높이의 교량·짧은 인접 교량을 합쳐 긴 상판 끝을 잃던 경우를 막았다.
- 곡선 상판의 오프셋에 실제 모서리 이음 계산을 적용했다. 단순 평균 법선으로 곡선 안쪽으로 폭이 수축하던 문제를 수정했다.
- 지상 도로 높이는 굽은 실제 도로선을 따라 계산하고 물리적인 끝 밖에서는 강바닥 대신 강둑의 진행 경사를 이어 계산한다. 시작 장면과 이동 워커가 같은 함수를 사용하며, 캐시는 도로의 거리 배열만 보관한다. 지형 높이를 오래 저장하지 않는다.
- 교량 진입부가 원래 지형 높이가 아니라 연결된 도로의 실제 평탄화된 표면과 만나게 했다. 도로 양 가장자리도 같은 높이 규칙을 사용한다.
- 행주대교 진입부에서 확인한 끝점 단차를 수정했다. 고정된 강둑 끝점 옆에서 잘린 평균 창을 쓰면 선형 경사에도 단차가 생겼다. 양 끝 경사를 반사해 평균을 계산하여 선형 경사와 끝 높이를 보존한다.

해상도·픽셀 비율·품질 프리셋·건물 재질·텍스처·셰이더 설정은 수정하지 않았다. 다른 콘솔의 `tmp/hangang-20261016`과 루트 작업 트리는 수정하지 않았다. 그 콘솔의 미완료 변경을 가져오지 않고 마지막 커밋된 main에서 분리했다.

## 형상 검증 방법과 한계

33개 교량 이름을 조사하고 위치 자료가 확보된 32개 주변을 각각 2,040m × 2,040m 범위로 비교했다. 실제 VWorld 도로·구조물 응답과 국토부 DEM을 같은 입력으로 보관해 기존/수정 워커에서 재생했다. 인증키·토큰은 자료에 보관하지 않았다. 최종 프로파일은 수정 코드로 다시 계산했고, 모든 지역의 511×511개 DEM 높이가 Float32 기준으로 원본과 같았다(변경 0개).

공식 상판 중심선을 3m 간격으로 검사한 수정 후 표본은 30,161개다. 타일 바깥 5m 경계는 제외한다. 이 검사는 모든 한강 교량의 모든 진입 램프·철도 모델·화면 각도를 증명하는 검사가 아니다. 특히 철교 이름의 주변 조사에는 인접 도로 교량도 포함된다. 마곡철교는 기존 위치 목록에 일치 자료가 없어 32곳 형상 비교에서 제외했다. [마곡대교 위치 참고](https://www.wikidata.org/wiki/Q12594489)만으로 도로 형상을 만들어 대체하지 않았다. 상판 높이는 DEM을 이용한 추정이며 실측 상판 높이가 아니다.

처음의 엄격한 점 검사는 누락 의심 표시가 **145 → 5**, 3m당 0.8m 초과 높이 변화 표시가 **97 → 2**로 줄었다. 남은 표시는 별도 정밀 조사했다.

- 잠실철교 주변 1점·월드컵대교 1점: Float32 삼각형 경계의 수치 오차. 상하좌우 1mm 지점 모두에 같은 높이의 상판이 존재했다. 정밀 검사 허용 오차를 1mm로 명시했다.
- 김포대교 3점: 검사 도구가 상판 오프셋 적용 전 좌표로 검사 범위를 잘못 판단했다. 오프셋 적용 후 범위를 검사하면 누락 0점이다. 앱 코드를 이 수치에 맞춰 바꾸지 않았다.
- 미사대교 높이 변화 2점: 겹치는 연속 상판 중 원본 프로파일에 가장 가까운 면을 선택하는 검사가 다른 면으로 바뀌었다. 실제 삼각형의 연속 높이 경로를 추적하면 단절 0점이다. 원본 방식의 2점 표시도 기록에 남겼다. 이것만으로 겹친 모든 상판과 램프가 시각적으로 완벽하다고 판정하지 않는다.
- 행주대교 진입부의 추가 1점은 실제 프로파일 평균 문제였다. 끝점 평균 수정 후 재계산한 자료에서는 누락·큰 높이 변화·연속 높이 경로 단절 모두 0점이다.

남은 표시를 확인한 정밀 검사에서 1mm보다 큰 상판 공백이나 연속 높이 경로 단절은 발견하지 못했다. 3m 사이의 더 작은 형상 문제와 실측 오차까지 없다고 보증하지 않는다.

## 실제 앱 비행

Chrome 실제 앱의 전후 배포 빌드를 같은 1920×1080 화면, 픽셀 비율 1.25, 2400×1350 캔버스, high, Tidewater WebGPU에서 비교한다. Chrome은 음소거했다. 실제 공식 한강대교 상판 좌표에서 남단 → 북단 경로를 추출해 비행하며 강 구간·교량·북측 도심을 측정한다. 비행의 최저 1초 FPS, p95/p99 및 최대 프레임 시간을 함께 기록한다. 이전 사각형 경로는 북측 진입부를 교량으로 잘못 이름 붙여 최종 비교에서 제외했다.

## 배포 상태와 저장 데이터 보호

**미배포.** 이번 변경으로 DB 데이터 삭제가 필요하지는 않지만 현재 배포는 단일 Docker 웹 서버를 재시작한다. `Dockerfile`의 CMD가 `app.main`을 시작하며 `backend/app/main.py:423`의 `_start_admin_retention`이 `_admin_retention_loop`를 즉시 실행한다. 이 경로는 `page_view_store.aggregate_closed_days()` 및 여러 저장소의 `purge_older_than()`을 호출한다. 예를 들어 `backend/app/services/page_view_store.py:534`는 기존 page_views를 DELETE한다. 별도 시작 작업의 글로벌 TOP100 갱신도 저장소에서 INSERT OR REPLACE를 사용한다.

이는 루트 `AGENTS.md`의 “배포 스크립트에도 동일하게 적용”, “간접 스크립트 등으로 같은 결과를 만들거나 우회하지 않는다”, “배포…라는 이유로 예외를 만들지 않는다”에 해당한다. 현재 세션에서 이 시작 경로를 실행하거나 자동 배포되는 main에 푸시하지 않았다. 데이터 삭제를 우회하는 명령/스크립트도 만들지 않았다.

소유자가 삭제를 실행하지 않는 배포 경로와 필요한 권한 분리를 마련해야 운영 반영을 진행할 수 있다. 이번 교량 수정에 섞어 unrelated 백엔드 수집·통계 기능을 일괄 끄는 변경은 만들지 않았다. 지침만으로 DB 삭제가 기술적으로 차단되었다고 주장하지 않는다.
