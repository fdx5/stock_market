# 3D 건물뷰 성능 개선 검증 (2026-09-28)

기준 커밋: `bbad857`. 건물·주변 건물 수, 지형 격자, 텍스처, 조경,
그림자 크기, 보행자 수와 기존 해상도 정책을 유지했다.

## 적용 내용

- WebGPU 색상 패스는 이미 불투명/투명 메시를 모두 그린다. 동일 장면을 다시
  그리던 두 번째 패스를 제거하고, 불투명 메시 → 배경 하늘 → 투명 메시 순으로
  한 번씩 그린다. 그림자와 최종 색 보정은 유지한다.
- 보행자의 포즈가 바뀐 인스턴스 범위만 GPU에 전송한다. 계속 화면 밖에 있는
  보행자는 전송하지 않는다. 아직 업로드하지 못한 범위는 합쳐 보존하며,
  WebGPU 버퍼의 부분 업로드 조건 오류도 수정했다.
- 단지를 바꿀 때 공유 차량 지오메트리에 남던 이전 인스턴스 버퍼를 해제한다.
  레이아웃 캐시는 메시 수명에 묶고, 렌더러 종료 시 공유 지오메트리의
  이벤트 리스너도 제거한다. CPU 에셋은 계속 재사용한다.
- 저장된 건물 윤곽이 있으면 도로와 지형 요청을 동시에 시작한다. 이전 선택의
  늦은 응답이 현재 지형 참조를 덮어쓰지 않도록 한다.
- 건물 생성 루프도 작업을 나눠 실행하고, 작업 조각의 목표 예산을 8ms로
  줄였다. 사용이 끝난 MessageChannel 포트도 닫는다. 단일 기하 연산의
  실행 시간을 8ms 이내로 보장하는 것은 아니다.

# 물 표현 · 로딩 랙 · 저사양 대응 (2026-09-28, 2차)

Tidewater(MIT) `ocean/WaterMaterial.js`의 방식을 단지뷰 규모로 옮겼다.

## 물 (WebGPU, `tidewater/ComplexWater.js`)

- 불투명 패스 → 하늘 → 장면 색·깊이 복사 → 물 패스 → 반투명. 물이 없으면 단일 패스 유지.
- 정확한 유전체 Fresnel, 구름 포함 하늘 반사, 화면공간 반사(SSR), 굴절 광선을 따라
  Beer-Lambert 흡수 + 단일산란(HG 위상) 수체, GGX 태양 반사(그림자 포함).
- 물결: FFT 대신 GPU로 한 번 만든 256² 기울기 타일(정수 파수 44개, 이음새 없음)을
  크기·회전·흐름 속도가 다른 3층으로 샘플. 밉맵에 기울기 제곱을 같이 저장(LEAN)해
  멀리서는 반짝임 대신 거칠기로 전환. 화면 미분 기반 스페큘러 AA(Kaplanyan).
- SSR은 평평한 수면 기준으로 추적하고 잔물결은 반사 이미지 왜곡(2·기울기·거리비)으로
  반영 — TAA 없이도 점묘 노이즈가 없음. 수면 높이의 지면 히트는 제외.
- 수심 실측이 없으므로 물가 거리 기반 가상 수심(1:3 경사, 최대 2.6m): 얕은 물가는
  바닥이 비치고 수로 중앙은 탁한 녹청색. 물가 1m는 지면으로 부드럽게 전환.
- 물 메시 생성: 필지 합집합 격자(스캔라인 채움 + 격자 최소 수위 + 챔퍼 거리변환).
  정점마다 다각형 판정 9회 → O(1) 조회. 인접 하천 필지 경계에 가짜 물가 없음.

## "3D를 표시할 수 없습니다"
WebGL 생성 실패(저사양 노트북의 드라이버 블록리스트 등)만으로 WebGPU가 가능해도 실패 처리했다.
- WebGL: high-performance → default → low-power 재시도.
- WebGL이 없으면 입력 전용 대체 렌더러로 조작만 받고 WebGPU로 그림.
- WebGPU 어댑터: 고성능 → 기본 → 소프트웨어 폴백.
- 15초 감시 타이머(WebGPU 미표시 → WebGL)는 WebGL이 있을 때만.
- 둘 다 불가/장치 유실 시 하드웨어 가속 안내 + 다시 시도 버튼.
검증: `--disable-webgl` 에서 WebGPU로 정상 표시, SwiftShader(소프트웨어 WebGPU)에서 표시 후
low·0.6x 로 즉시 조정.
