# 3D 건물뷰 성능 개선 검증 (2026-09-28)

기준 커밋: `bbad857`. 건물·주변 건물 수, 지형 격자, 텍스처, 조경,
그림자 크기, 보행자 수와 기존 해상도 정책을 유지했다.

## 적용 내용

- WebGPU 색상 패스는 이미 불투명/투명 메시를 모두 그린다. 동일 장면을 다시
  그리던 두 번째 패스를 제거하고, 불투명 메시 → 배경 하늘 → 투명 메시 순으로
  한 번씩 그린다. 그림자와 최종 색 보정은 유지한다.
- 보행자의 포즈가 바뀐 인스턴스 범위만 GPU에 전송한다. 계속 화면 밖에 있는
  보행자는 전송하지 않는다. 아직 업로드하지 못한 범위는 합쳐 보존하며,
  WebGPU 버퍼의 부분 업로드 조건 오류도 수정했다.
- 단지를 바꿀 때 공유 차량 지오메트리에 남던 이전 인스턴스 버퍼를 해제한다.
  레이아웃 캐시는 메시 수명에 묶고, 렌더러 종료 시 공유 지오메트리의
  이벤트 리스너도 제거한다. CPU 에셋은 계속 재사용한다.
- 저장된 건물 윤곽이 있으면 도로와 지형 요청을 동시에 시작한다. 이전 선택의
  늦은 응답이 현재 지형 참조를 덮어쓰지 않도록 한다.
- 건물 생성 루프도 작업을 나눠 실행하고, 작업 조각의 목표 예산을 8ms로
  줄였다. 사용이 끝난 MessageChannel 포트도 닫는다. 단일 기하 연산의
  실행 시간을 8ms 이내로 보장하는 것은 아니다.

## 전후 측정

Windows / Edge headless / NVIDIA Ampere / DPR 1. 합성 주동 9개,
주변 건물 255개, 도로·차량·보행자·조경. 내부 렌더링 배율 1.5 고정,
시나리오마다 180프레임. 변경 전 코드는 별도 worktree에서 실행했다.
CPU 시간은 `ComplexRenderer.render` 호출 시간이며 GPU 실행 시간이 아니다.

빠른 데스크톱에서는 양쪽 모두 60fps였다. 이 수치는 해당 합성 장면의
불필요한 작업 감소를 보여주며, 모든 사용자 기기의 FPS 상승률을 뜻하지 않는다.
네트워크·GPU 드라이버·초기 셰이더 컴파일 비용은 별도로 남는다.

## 품질 및 회귀 검증

- 같은 카메라·해상도·시각의 건물/지면/조경 스크린샷 1098×508:
  모든 RGB 픽셀이 일치했다. 움직이는 차량/보행자는 정지 비교에서 숨겼다.
- 낮/밤, 확대 후 닫기, 54개 동 합성 장면, 단지 반복 전환, 390px 폭,
  WebGPU 미지원 및 장치 유실 시 WebGL 복귀 검증 통과. JS/GPU 오류 없음.
  첫 실행의 모바일 스크린샷 캡처가 타임아웃되어 단독 재실행했고 전체 통과했다.
- 모의 도로 500ms / 지형 350ms 응답: 시작 시각 차이 0.2ms,
  건물 요청을 포함한 데이터 대기 536ms. 두 요청이 실제 겹치는 것을 단언했다.
- GPU 버퍼 회귀 테스트 4개, 기존 부동산 테스트 10개 통과.
