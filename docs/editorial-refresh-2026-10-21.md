# 투자 영상 오전 8시 갱신 보완

운영 조회에서 2026-10-21 08:03 KST에 국내·미국 영상 모두 10/20 회차,
`stale=true`, `refreshing=false`였다. 포트폴리오 10명은 08:00:09~12 KST에
10/21 회차로 정상 수집되어 있었다. 따라서 기존 08:00 KST 스케줄 자체는
실행되지만 영상 수집은 결과를 만들지 못하고 이전 회차를 유지하는 상태다.
기존 실패 로그에는 상세 수집 단계가 없어 제공처 실패의 구체 원인은 미확정이다.

- 서버 스케줄은 매일 08:00 KST, 주말 포함. 실패 재시도를 15분에서 1분으로
  줄이고 전날 회차 시도가 오늘 08시 실행을 지연시키지 않도록 회차를 구분한다.
- 별도 GitHub Actions 수집기도 매일 23:00 UTC = 다음날 08:00 KST에 실행한다.
  서버 스케줄과 독립된 환경에서 공개 영상의 게시시각·조회수를 확인한다.
  GitHub 예약은 플랫폼 사정으로 지연될 수 있으며 정각 보장은 서버 스케줄이 담당한다.
- 인증된 `POST /api/editorial/videos/edition`은 현재 회차만 허용한다.
  영상 20개 이하, 한국어/시장 일치, 게시시간 범위, 중복, 집계시간을 검사하며
  URL은 서버가 정규 YouTube 주소로 구성한다.
- `EDITORIAL_REFRESH_TOKEN`을 우선 사용하고 미설정이면 기존
  `PREDICTION_BATCH_TOKEN`을 사용한다. 토큰은 로그·결과·저장파일에 포함하지 않는다.
- 실패 상태에는 후보 수/확인 성공 수만 추가하며 외부 요청 URL이나 키는 노출하지 않는다.
- 오늘 실제 수집된 국내·미국 각 20개를 새 `editorial_editions` 파일로 추가한다.
  기존 seed·저장 회차는 그대로 보존하며, 시작 시 가장 최근 회차를 선택한다.

포트폴리오 상세 10개를 운영 API에서 확인했다. 종목 수 일치, 실제 매입단가를
임의로 표시하지 않음, 옵션 기초자산 가격을 옵션 가격으로 표시하지 않음이 확인됐다.
대부분의 보유내역 기준은 Q2 2026, 버리는 운용 종료 전 최종 Q3 2025 공시다.
수집일 갱신은 새 분기 공시나 실제 매매가 발생했다는 뜻이 아니다.

저장 데이터/DB 삭제·교체·직접 DB 접근 없음. 테스트는 메모리 및 새 pytest 임시
디렉터리만 사용한다. 기존 데이터 변경·마이그레이션 없이 추가 저장만 한다.
