# 드론 속도·고도 설정 긴급 배포

사용자의 “상승고도 1000m 제한 해제” 요청을 수동 고도 상한 제거로 적용한다. 오토파일럿에는 지면 기준 10~1,000m 목표 고도와 0~200km/h 속도 설정을 제공한다. 속도 0은 제자리 고도 조절이다. 설정은 해당 비행 세션 메모리에만 보관하며 저장 DB·회원 데이터·브라우저 영구 저장을 변경하지 않는다.

설정은 자동 비행 중과 로딩 대기 중에도 적용되고 재시작 시 유지된다. 설정하지 않았을 때는 기존 현재 속도 유지/정지 시 100km/h 항속을 유지하며 시작 고도를 10~1,000m 안에 맞춘다. 수동 조작은 자동 비행을 종료한다. 지형과 건물을 미리 검사해 안전 고도를 확보하고 1,000m 범위로 회피할 수 없는 장애물 앞에서는 대기한다. 10m 설정이 평지에서도 무조건 24m로 올라가던 지면/건물 판정도 구분했다.

모바일 가로 화면에서 하단 환경 패널이 설정 입력칸을 가리던 문제를 발견하여 설정창을 독립된 상단 레이어로 옮겼다. 숫자 입력·슬라이더와 휠이 비행 조작에 전달되지 않으며 Escape는 설정창을 먼저 닫는다. 수동으로 높이 올라가도 지상이 클리핑되지 않도록 카메라 가시 거리만 확장한다. 출력 해상도·품질·지형 데이터 해상도는 낮추지 않는다.

검증:

- 비행·회전·사진 선택 Node 테스트 23개, 사진 서버 AST 테스트 9개 통과. TypeScript와 새 디렉터리 프로덕션 빌드 통과.
- `qa-drone-flight-settings.py 5182 flight-settings-v2-20261011`: 실제 상승 버튼으로 1,019.8m 도달, 입력 350km/h→200km/h 및 1,200m→1,000m 제한, 자동 비행 중 10m 설정, 390×844/844×390 입력칸 가림 없음, 런타임 오류 없음.
- 순수 비행 테스트에서 10m/1,000m 양 끝 도달·유지, 600m 건물 넘기, 통과 불가 1,100m 건물 앞 대기, 로딩 대기 후 설정 속도 복귀, 키보드/터치/휠/상승 버튼으로 1,000m 초과 후 하강을 확인했다.
- Chrome 154.0.8037.98, 음소거, 해운대 단일 지역 자동 비행 6초: 실제 렌더 최저 1초 56.98fps, p95 16.8ms/p99 33.4ms/최대 33.5ms. 출력 2520×1750, 픽셀 비율 1.75, high 유지. 이 측정은 전국·모든 장비의 성능 보장이 아니다.

다음 배포는 화면에 보이는 영역 로딩 개선이다. 같은 장비·해상도·자료와 빈 메모리 캐시 조건에서 비교하고, 최소 3배 단축이 실제 측정되기 전 달성으로 보고하지 않는다.
# 2026-10-11 설정창 긴급 수정

운영에서 속도·고도 설정창이 빈 패널로 보인다는 보고를 우선 처리했다. 기존 배포의 JS·CSS를 새 Chrome 세션에서 검증했을 때는 입력란이 표시됐으므로, 모든 환경에서 같은 원인을 재현했다고 주장하지 않는다. 설정창을 네이티브 모달 대화상자의 최상위 레이어로 옮기고 크기·글자색·숫자 입력·슬라이더의 필수 스타일을 컴포넌트에 지정했다. 제목과 설정 범위도 명시한다.

격리된 로컬 공개 스냅샷 API로 실제 빌드를 검사했다. 1440×1000, 390×844, 844×390에서 두 숫자 입력과 완료 버튼의 화면 경계·클릭 가능 여부, 200km/h·1,000m 및 73km/h·10m 적용, 완료·Escape 닫기와 드론 유지가 통과했다. TypeScript, 릴리스 빌드, 오토파일럿 순수 테스트 15개도 통과했다. 브라우저는 음소거했다. 타일 로딩 개선 초안은 이 긴급 수정에 포함하지 않았다.
