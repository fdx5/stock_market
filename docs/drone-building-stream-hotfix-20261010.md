# 드론 이동 중 건물 상세 로딩 누락 수정

2026-10-10. 5층 이상 건물도 상세화되지 않는 현상을 대상으로 조사했다.
출력 해상도와 품질 프리셋을 낮추지 않고 로딩 경로와 반복 계산을 수정했다.

## 확인한 원인과 수정

| 확인한 문제 | 수정 후 동작 |
| --- | --- |
| 최초 진입 반경 600m의 건물이 이동 타일에서 제외되고 별도의 아파트 전용 1회 로딩에 의존 | 최초 영역도 같은 가까운 순서의 상세/색상 작업 대기열에 포함. 대상 기준인 5층 이상 및 큰 복합 건물은 유지 |
| 건물 중심 12m 및 등록 높이 65~135% 조건 때문에 실측 모델이 있어도 매칭 누락 | 모든 대상의 등록 외곽과 실측 외곽의 실제 겹침을 우선 비교. 오목한 외곽도 삼각형 단위로 비교. 기존 엄격한 중심/높이 조건은 보조 판정으로 유지 |
| 대단지 외곽에서 60m 이내인 다른 건물까지 가져올 수 있음 | 외곽 겹침과 단일 소유 판정 사용. 작은 옥탑만으로 전체 건물을 교체하지 않음 |
| 목록/모델 다운로드 실패가 빈 정상 결과로 처리 | 실패와 자료 없음 구분. 실패는 재시도하며 이미 적용한 모델은 중복 적용하지 않음 |
| 느린 모델 파일 하나가 전체 작업자 제한 시간을 넘기면 이미 받은 모델까지 미적용 | 상세 다운로드 묶음은 8초 안에 완료된 모델을 반환. 충분한 외곽과 높이가 확인된 건물부터 적용하고 남은 모델을 재시도. 일부 날개만 받은 복합 건물은 기본 형상을 유지 |
| 도로·토지 이용의 완료를 기다리는 동안 기본 건물은 이미 보이지만 상세화가 시작되지 않음 | 기본 건물이 GPU에 준비되면 상세 로딩 시작 |
| 항공 사진의 색상 분석이 상세 형상 작업자 슬롯을 점유 | 형상 작업자 2개(제한 장치 1개), 색상 작업자 1개로 분리. 항공 사진 다운로드 최대 4개 병렬 |
| 상세 모델 교체 뒤 도착한 색상이 기본 모델에만 적용 | 상세 형상에도 원래 건물별 벽/지붕/단부 색상을 적용. 지붕에 벽 창문 재질을 적용하지 않음. 등록 층 높이의 창문 간격 유지 |
| 큰 실측 모델 병합·범위 계산과 반복 작업 예약의 메모리 부담 | 범위 계산을 작업자로 이동하고 선형 배열 구성 사용. 작업 예약용 MessageChannel 재사용 및 짧은 로딩 실행 구간 사용 |
| 철도 검사와 정지 차량 계산이 새 모델 반영 때 중복 수행 | 위치가 변하지 않은 차량 높이 재사용, 도로 표면 변경 즉시 무효화. 철도 검사 범위는 선로 변경 시 다시 구성. 형상 범위와 교차 보정 결과 범위는 작업자 계산 사용 |
| 차량·바퀴·열차·사람·수목·물보라의 행렬을 매번 16개씩 JavaScript로 복사 | 동일한 Float32 결과를 한 번의 배열 복사로 반영. 기존 행렬과 바이트 단위 동일성 검증 |
| 차량 계산의 차선·교차로·충돌 후보 배열을 매 프레임 새로 생성 | 차량 수로 보관량을 제한한 배열 재사용. 기존 순서·대상·충돌 판정 유지 |

기본 건물은 상세 모델이 GPU에 준비된 뒤에만 교체한다. 드론 종료 시 최초 영역의
기본 형상 인덱스를 복원한다. 이는 장면 메모리의 처리이며 저장 DB 변경이 아니다.

## 검증

관련 회귀 검사 88개 및 TypeScript 검사를 수행했다. 새 독립 Chrome 세션과 읽기 전용
로컬 스냅샷 API만 사용하며 운영 지도 데이터 API를 시험 대상으로 사용하지 않는다.

최종 후보 v12의 창동 Chrome 비행 측정 결과는 다음과 같다. 모든 측정은
뷰포트 1440×1000, 출력 2520×1750, 픽셀 비율 1.75, 품질 high를 유지한다.
구간별 2.5초 정착 후 10초간 렌더 프레임과 최저 1초 FPS를 측정한다.
CPU 샘플링을 켠 진단 실행은 최종 FPS 합격 근거에 포함하지 않는다.

| --- | --- | --- | --- | --- |
| 최초 영역 | 59.82 | 57.98 | 16.8 / 16.9 ms | 50.1 ms |
| 도심 이동 | 54.34 | 45.98 | 33.4 / 33.5 ms | 66.7 ms |
| 복귀 | 59.89 | 58.98 | 16.8 / 16.8 ms | 33.4 ms |

Chrome 154.0.8037.98, NVIDIA Ampere, WebGPU, 독립 세션. 브라우저 오류 0개.
실제 상세 교체 건물은 최초 349개 → 이동 636개 → 복귀 730개로 증가했다.
비행 후 GC 잔류 JS 힙은 410.7 MiB다. 로딩/다운로드/사진 분석/교체가 계속
진행 중인 측정이며, 구간별 전체 건물 수는 1706 → 2431 → 3544개다.

최소 50 FPS 조건은 **미달**이다. 사용자가 이 최저 수치로 배포를 명시적으로
허용했으므로 이 수정본을 배포 대상으로 확정하며, 전 구간 최소 50 FPS는 남은
개선 과제로 유지한다. 해운대와 실제 키보드 이동의 추가 검증 결과 및 배포 확인은
최종 PDF에 기록한다. 근거: `tmp/drone-performance-20261010/building-release-changdong-v12/report.json`.

수정 도중 50fps에 미달한 실행도 보존한다. 49.98fps를 반올림하여 합격으로 처리하지
않으며, 이전 동적 해상도 실행의 FPS를 같은 해상도의 개선 근거로 사용하지 않는다.

## 자료와 검증 범위의 한계

실측 모델이 없거나 외곽 대응을 확인하지 못한 건물은 등록 외곽 기반의 기본 건물을
유지한다. 자료 미제공과 다운로드 실패는 별도의 상태로 표시한다. 모든 건물을 실측
상세 모델로 바꾸었다고 주장하지 않는다.

공유 외벽 재질을 사용하면서 실제 형상·등록 층 간격·건물별 항공 사진 색상을 반영한다.
모든 건물의 실제 외벽 사진이나 BIM 재질을 확보한 것은 아니다. 외벽 사진 기반의
재질 다양화, 전국 장시간 비행 및 다양한 사용자 GPU 검증은 남은 과제다.

JS 힙 측정은 GPU 전체 메모리 측정이나 장시간 누수 부재의 증명이 아니다.
일부 지역과 장비의 측정만으로 전국 모든 구간에서 50fps/60fps를 보장하지 않는다.

## 이번 배포의 데이터 보호 승인 범위

서버의 기존 `_start_admin_retention()`은 재시작 직후 통계 보관 기간 정리를
시작하므로 AGENTS.md의 간접 삭제 금지와 충돌한다. 이를 확인하고 배포 실행을
중단해 알렸으며, 사용자가 “삭제 해도 되니 배포해”라고 이번 배포를 명시적으로
승인했다. 이 승인은 이번 재시작에 따른 기존 통계 보관 기간 정리에 적용한다.
통계 보관 정책이나 백엔드 코드를 새로 변경하지 않으며, 별도의 DB 정리 명령,
DB 초기화, 테이블·파일·백업 삭제를 실행하지 않는다. 다른 저장 데이터 작업에는
기존 보호 지침을 계속 적용한다.
