# 드론 건물 재질·선행 로딩·성능 개선 - 배포 변경 기록

2026-10-11. 사용자가 평균 약 54fps와 최저 구간 미달을 보고받은 뒤 배포를 승인한 수정 범위다.
**모든 건물 선행 상세화와 전 구간 최소 50fps는 미완료다.** 이 배포를 전체 목표 달성으로 보고하지 않는다.

## 문제와 구현

이전 형상 매칭·작업 재개 개선만으로는 건물 재질의 획일성이 해결되지 않았다.
사진을 외벽에 씌우는 실험은 사용자의 요구와 맞지 않아 제거했다. 이번 구현은
등록 외곽·층수·용도·구조 정보와 대응되는 실측 3D 형상을 사용하고, 재질을 직접
구성한다. 실제 외벽 마감과 현재 도색이 조사된 데이터는 없으므로 추정한 외관을
정확한 실측 마감이라고 표시하지 않는다.

| 개선 | 결과 |
|---|---|
| 건물별 재질 | 도장, 벽돌, 석재 패널, 금속 패널, 유리 외벽; 호환되는 색상·창문·프레임 8종 |
| 보통 아파트와 고층 유리 타워 구분 | 보통 아파트의 도장 벽 유지; 등록 층수에 맞춰 창문 높이 배치 |
| 형상과 재질의 분리 | 원래 위치·법선·삼각형 보존; 재질 속성은 정점별로 전달 |
| 화면 이동 중 상세화 | 최초 주변과 이동 타일이 같은 근거리 우선 대기열 사용; 12개씩 부분 적용 |
| 부족한 자료 | 확정된 미제공과 일시 실패 구분; 실패는 재시도하고 기존 건물 유지 |
| GPU 교체 | 새 건물 묶음이 준비된 뒤 교체; 기존 건물을 먼저 없애는 공백 방지 |
| 시선 선행 로딩 | 현재 위치, 10초 후 이동 방향, 시선 방향을 함께 준비 |
| 멀어진 곳의 모델 요청 | 최초 출발점이 아닌 요청한 건물에 가까운 모델부터 처리 |

일반 건물은 직접 드론 진입과 단지뷰에서의 드론 전환 모두 같은 구성 재질을 사용한다.
비행을 나중에 시작하더라도 외벽 사진이나 사진을 가공한 지도 이미지를 다운로드하여
씌우는 이전 경로가 남지 않도록 초기 재질도 준비한다. 별도 구현된 기존 궁궐·경기장
랜드마크는 이번 일반 건물 재질 교체의 대상이 아니다. 항공색 분석은 지붕 색상에
한정하며 새 외벽 재질을 뒤늦게 흰색으로 덮지 않는다.

### 2026-10-11 옥상 연두색 편중 수정

- 공통 녹색 기본값과 외벽에서 파생된 지붕색을 분리했다. 건물의 고정 식별값으로
  회색·콘크리트 계열 8종을 선택하므로 단지 브랜드의 녹색 강조색이 옥상으로 번지지 않는다.
- 등록 외곽에서 추출한 항공색이 녹색·황록색이면 주변 식생/영상 위치 오차를 구분할
  근거가 부족하므로 건물별 중립 옥상색을 유지한다. 현재 실제 방수 도색의 실측값이라고
  주장하지 않는다. 신뢰 가능한 중립색과 붉은 기와색은 남긴다.
- 항공색의 sRGB를 선형 정점색으로 한 번 변환한다. 이전에는 영상 숫자를 선형값으로
  넣어 밝게 번졌다. 지연 색상과 다음 상세화 배치 모두 같은 옥상색을 사용한다.
- 수평 상판에는 외벽의 벽돌/금속 패널 무늬를 적용하지 않는다. 위치·높이·층수·법선·
  삼각형·외벽색은 보존한다. 추가 사진 텍스처, 건물별 GPU 재질, 프레임별 옥상 계산은 없다.
- V9 음소거 Chrome 검사: 창동 2023개/해운대 372개 옥상에서 녹색 편중 판정 0개,
  서로 다른 옥상색 62종/51종, 런타임·WGSL 오류 0개. 이전 V8에서 판정된 녹색은
  창동 1813개 중 384개/해운대 439개 중 28개였다. 로딩 수가 달라 개별 건물의 개선율로
  계산하지 않는다. 실제 출력 2520×1750, 픽셀 비율 1.75, high를 유지했다.

## 품질을 유지하는 성능 작업

- 상세화 배치를 타일의 동일 재질·속성 배치로 병합한다. 색상·창문 속성은 건물별로
  유지하고 모든 원래 삼각형을 보존한다. 사용이 끝난 이전 GPU 형상은 회수한다.
- 정적인 건물은 GPU 버퍼 참조를 재사용한다. 색상·형상·인스턴스·배열 교체 또는
  자원 회수 뒤에는 즉시 갱신한다.
- 그림자 대상 목록을 한 번 분류한다. 동일한 그림자·거리·레이어 검사를 유지하면서
  각 그림자 패스가 그림자를 만들지 않는 물체를 반복 순회하는 비용을 줄인다.
- 차량 경로의 불변 구간 길이·방향·곡선 반경을 미리 계산한다. 직선 구간의 충돌은
  같은 분리축 계산으로 후보 거리부터 구한 뒤 기존 실제 위치에서 확인한다.
  커브·교차로·고도 교차는 기존 정밀 검사를 유지한다.
- 곡선 경로는 차량이 지나갈 수 있는 범위를 먼저 계산한다. 그 범위 바깥의 차량만
  제외하고 실제 충돌 검사는 그대로 유지한다. 차의 수나 갱신 주기를 줄이지 않는다.
- 실제 도로 상판 높이 계산의 후보를 캐시한다. 밀집 셀은 캐시 내부에서만 세분화하여
  반복 BVH 질의를 피하고 원래 삼각형 순서·면 높이·교량 레벨 필터를 유지한다.
- 도로 모델 검사는 적용 가능한 후보를 한 워커 배치로 검사하고, 최대 두 문맥만
  보유한다. 워커 재시작 뒤 문맥 누락은 다시 전송한다.

출력 해상도와 품질을 FPS에 따라 낮추는 작업은 하지 않는다. 시험 조건은 Chrome,
1440×1000 뷰포트, 픽셀 비율 1.75, 실제 출력 2520×1750, high 고정이다.
모든 자동 브라우저 시험은 `--mute-audio`로 실행한다.

## 메모리와 저장 데이터

형상 워커 2개, 색상 워커 1개, 기본 타일 로딩 4개, 타일 90개 한도를 유지한다.
도로 계산 캐시는 부모·세부 셀 참조를 합쳐 262144개, 부모 셀 16384개, 삼각형 값
131072개로 제한한다. 차량이 같은 도로를 반복 방문할 때의 재계산을 줄이는 CPU 캐시이며
영구 저장 자료를 지우지 않는다. 구간 이탈 시 취소, 워커 기한, 배열·GPU 형상 회수가 적용된다.
저장된 운영·개발 DB, 파일, 백업을 삭제하거나 테스트 대상으로 사용하지 않는다.
로컬 API는 보존된 공개 GIS 스냅샷을 읽는 별도 서버다.

## 검증 근거와 미완료 조건

최종 수정본의 비교·회귀 테스트 214개(28개 스크립트), TypeScript 검사와 Vite 배포 빌드가 통과했다.
직선 차량 충돌 40000개 사례, 경로의 곡선·정확한
경계 좌표, GPU 버퍼 재사용·변경·회수, 전체 삼각형·재질 속성의 병합 보존을 검증했다.
운영 반영은 푸시 후 health의 커밋과 공개 정적 파일을 별도로 확인한다.

`constructed-ahead-v6` Chrome 실제 키보드 비행: 약 890m 이동, 입력 해제 정상,
외벽 사진 다운로드 0건, 브라우저 오류 0건. 비행 전 510m 앞 건물이 상세화되어
GPU에서 준비됐고, 비행 중 350m 앞 타일에서도 상세화가 계속 진행됐다.
재질 변형 0–7과 도장·벽돌·금속·유리가 화면 정점 속성에 적용된 것을 확인했다.
일부 모델의 원천 자료는 미제공이므로 등록 형상을 유지한다.

이전 초기 구간의 59 FPS는 차량 활성화 이후의 성능을 보장하지 않는다. 이번에는
`trafficArmedAt` 이후에도 따로 측정한다. 1초 최저 FPS, 평균, p95/p99 프레임 시간,
최악 프레임, 실제 출력 픽셀, 준비된 건물 수와 회수 뒤 힙을 함께 기록한다.
CPU 프로파일은 진단에만 사용한다. 건물 0개였던 초기 후보의 수치는 제외한다.

V8 창동 전체 동작 후보는 1초 최저 50.97 / 39.33 / 44.24 FPS였다.
V9는 32.45 / 35.39 / 34.99, V10은 39.32 / 28.99 / 35.39 FPS로 기준에 미달했다.
추가되는 건물 수와 외부 실행 상태가 달라 옥상 수정의 성능 회귀율로 계산하지 않는다.
V10은 5812개 건물, 상세 매칭 1394개, GC 후 JS 힙 약 647 MiB였다.
차량의 실제 짧은 이동 구간도 연속 경로 범위로 먼저 걸러내되 기존 정밀 충돌 검사를
유지했다. 무작위 3000개 회전·역방향 차선·고도 교차에서 안전 이동 거리가 동일했다.
이 초기 후보들은 합격 처리하거나 배포하지 않았다. 전체 동작 성능은 추가 개선 대상이다.
전체 50 FPS를 확인하기 전 완료나 전국 성능 보장을 보고하지 않는다.

## 2026-10-11 상세 중단과 로딩 지연의 후속 조사

사용자가 선덕중학교·서울신학초등학교에서 새로고침 후에도 확인한 문제를 전체 시야 기준으로
재현했다. 예전 검사에서 사용하던 '750m 이내 style=apt' 일부 목록은 전체 시야의 성공률을
대표하지 못한다. 후속 검사는 재질 종류에 관계없이 5층 이상이며 화면상 높이가 8픽셀 이상인
등록 건물을 조사한다. 이는 외곽의 카메라 투영 범위 검사이며 다른 건물에 가려지는지까지
판정하는 검사는 아니다.

| 확인한 원인 | 수정 |
|---|---|
| 미리 그려진 시야 앞쪽 건물이 드론 중심 상세 반경 밖이라는 이유로 제외됨 | 보유 타일의 시야 방향 건물도 상세 대기열에 진입 |
| 밀집 저층 건물이 보이는 아파트의 처리를 지연시킴 | 바로 주변을 우선 유지하며, 시야의 5층 이상 건물은 가까운 순서로 상세 처리 |
| 원본 모델과 등록 도로·건물의 좌표 환산법이 달라 1km 이동 시 남북 방향 약 7m 오차 | 원본 모델과 탐색 경계도 동일한 등록 좌표계로 환산; 정점·높이·삼각형 보존 |
| 오목한 건물 외곽의 정점 평균 차이를 좌표 오차로 취급 | 실제 외곽 경계의 크기·중심과 여러 건물의 일치 근거로만 추가 정렬 |
| 넓은 주변 탐색에서 무관한 모델까지 다운로드·도로 검사 | 원본 경계 상자를 이용한 보수적 제외, 대응 가능한 모델만 도로 검사 |
| 주변 목록 하나가 늦으면 모든 정상 모델의 다운로드까지 대기 | 목록이 도착하는 즉시 4개 한도 내에서 가까운 모델 다운로드 시작 |
| 작은 형상 캐시가 워커마다 반복 해독을 유발 | 24MiB 한도 내 1024개, 5분 TTL; 실패·원본 사진은 캐시하지 않음 |
| 큰 상세 모델 여러 개가 한 프레임에 GPU로 전송됨 | 개수·시간과 함께 새 형상 2MiB 전송 한도; 큰 모델도 최소 1개씩 진행 |

V26 음소거 Chrome 선덕중학교 최초 시야는 60초 시점에 399개 중 395개가 GPU 준비 후
상세 교체됐다. V20의 같은 시야는 399개 중 164개였다. 시선 동쪽 변경 후 15초는
800개 중 397개, 실제 W 키 비행 약 210m와 추가 15초 후는 720개 중 616개였다.
시선 변경 직후의 대기와 일부 원천 형상·등록 경계 불일치는 남아 있으므로 모두 완료라고
보고하지 않는다. 일반 건물 원본 사진 요청 0건, 브라우저·WGSL 오류 0건,
2520×1750·픽셀 비율 1.75·high를 확인했다. 서로 다른 시점의 보유 건물 수가 다른 검사를
개별 건물의 속도 개선율로 해석하지 않는다.

V25 선덕중학교 차량 활성화 이후 최초/이동/복귀 구간의 최저 1초 FPS는
57.98 / 50.97 / 41.99였다. 해상도 유지 조건은 통과했으나 전 구간 50fps 조건은 미달했다.
CPU 프로파일은 진단에만 사용했다. 배포 후보 V27의 처음 측정은 구간 평균
59.30 / 53.67 / 48.30fps, 최저 57.97 / 41.98 / 33.43fps였다. 같은 후보 재측정은
평균 56.09 / 50.70 / 53.66fps(전체 약 53.5), 최저 48.32 / 33.43 / 46.98fps였다.
모두 차량 활성화 후 각 10초, 출력 2520x1750 / 비율 1.75 / high 고정이다.
최종 V29는 이 후보의 동작을 유지하며 214개 테스트와 타입/빌드를 재검증했다.
V28의 프레임 내부 재검사 생략과 도로 캐시 교체 실험은 평균 약 37.7fps로 낮아
배포에서 제외했다. 원인 귀속이나 외부 실행 조건까지 완전히 통제한 실험으로 해석하지 않는다.

추가 품질 수정은 1–4층 건물의 약 절반에 구멍 창·쌍 창·띠 창·간격 창 형태를 구성하고,
옥상 기계실 높이 탐색을 12m로 넓혀 본체 창문과 분리했다. 전철역은 native renderer가
지원하지 않는 Sprite를 대신해 기존 건물 표지판 canvas 경로로 이름을 표시한다.
음소거 Chrome 창동 검증: 1-4층 1331개 중 기존 창 617개(46.4%), 나머지는
4개 새 배치 179/179/167/189개였다. 실제 GPU 속성에서 창 배치 0-4와 색상/변형
0-7을 확인했고, 옥상 1804개에서 녹색 편중 0개, 옥상색 54종이었다.
134개 외관 메시 모두 GPU 준비 상태였으며 본체 창문과 창문 없는 수직 설비 면을
각각 확인했다. 불암산역 표지판의 실제 canvas 글자 출력과 화면을 확인했다.
일반 건물 사진 요청 및 런타임/WGSL 오류는 0건이다.

## 남은 개선과 검증 범위

- 새 시선 방향의 전체 건물 상세화 대기, 일부 모델 미제공 및 등록 외곽/도로 충돌이 남아 있다.
  잘못된 모델을 도로 위에 강제로 놓거나 원래 건물을 없애지 않는다.
- 순간 프레임 저하와 반복 비행의 장시간 메모리 추세는 후속 개선 대상이다.
  제한된 캐시와 복귀 후 힙 확인을 전국 장시간 메모리 보장으로 표현하지 않는다.
- 의정부 단지뷰에서 수동 비행 시작 검사는 90초 초기 준비 대기로 끝나 재검증이 필요하다.
  해운대 최종 빌드의 직접 비행 진입은 정상이며 런타임/WGSL 오류 0건이다.
- 추정 외관의 재질과 창문 구성은 실제 외벽 마감/창문 실측 자료가 아니다.
- 공개 GIS 스냅샷으로 로컬 검증했다. 운영 DB와 데이터를 수정하거나 삭제하지 않았다.
  운영 확인은 health/HTML/정적 파일만 요청하며, 기록을 저장하는 map API는 호출하지 않는다.
