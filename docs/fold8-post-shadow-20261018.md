# 드론 그림자 캐시와 후처리 연산 재사용

기준 운영 커밋은 55993d54다. 이후 사용자가 전달한 실단말 수치는 1866×1408에서
18~30fps, GPU 약 35ms다. shadow 7, scene 9.7, plants 6.8, water 0.5,
post 8.4, other 1.0ms이며, 목표인 실단말 지속 60fps에는 미달한다.
앞선 57ms에서 감소한 사실과 목표 달성 여부를 구분한다.

## 모바일과 PC의 공통 변경

- 그림자 맵에 가장자리 64텍셀씩을 추가한다. high의 2048²는 2176²가 되며,
  커버 범위도 같은 비율로 늘려 기존 월드 공간 텍셀 밀도를 보존한다.
  광원 공간 중심을 64텍셀 격자에 맞춰 이동 중에도 같은 투영을 재사용한다.
  기존 그림자 체적 전체를 포함하도록 XY와 Z를 확장하고, 비교 바이어스의
  월드 공간 크기를 보정한다. 샘플 수, 필터와 캐스케이드 갱신 주기는 유지한다.
  기기 텍스처 한도로 확장할 수 없으면 요청 해상도의 기존 경로를 쓴다.
- 같은 투영에서는 고정 물체의 그림자를 캐시하고 움직이는 물체만 다시 그린다.
  고정 물체 목록/재질/형상 변경과 렌더 뷰 전환은 기존 무효화 경로를 따른다.
  모바일 2개와 PC 3개 캐스케이드 모두 적용한다. `shadowgrid=0`은 비교용 기존 경로다.
- AO의 기존 half-float 색/거리를 그대로 패킹하고, 이웃 깊이의 full-float 값을
  두 블러 사이에 전달한다. 같은 깊이를 다시 텍스처에서 읽고 변환하던 연산을
  줄인다. 원래 half-float 반올림, 이웃 좌표 계산과 12개 AO 샘플을 보존한다.
  중간 버퍼만 RG32float이며 최종 AO는 기존 RG16float다.
- 최종 1:1 출력의 중심과 네 이웃은 같은 정수 좌표에서 직접 읽는다.
  같은 다섯 픽셀을 사용하는 필터이며 화면 해상도와 가장자리 처리를 보존한다.
- TAA의 중심 색 변환을 재사용하고, 9개 이웃 통계의 합산 순서를 유지한다.
- 기존 진단 HUD에 AO / blur / TAA / bloom / finish와 캐스케이드별 시간을 추가한다.

AO 임시 메모리는 1866×1408에서 약 7.9MB 증가한다. 그림자 캐시는 이동 중에도
사용되며, high에서 캐시 레이어당 약 18.9MB다. 기존 맵 대비 패딩은 레이어당
약 2.2MB를 추가한다. 새 임시 AO 버퍼는 크기 변경, 일시 중지와 종료 시 기존
타깃과 함께 관리한다. 캐시는 재사용되지 않는 기간이 길어지거나 종료하면 해제한다.
해상도, 품질 프리셋, 나무/잎 수, 반사 품질을 낮추지 않는다.

## 검증과 한계

- 후처리 GPU 비교 12개: 1866×1408 / 1920×1080 / 홀수 1867×1409 및 네 지터.
  최종 AO RG16, TAA RGBA16, 최종 RGBA8의 바이트 차이 모두 0, GPU 오류 0.
- 405MHz RTX 3070 단독 패스 중앙값: 1866×1408의 AO 블러 합계
  0.197→0.131ms, 최종 출력 0.426→0.328ms. 1920×1080에서는 각각
  0.197→0.131ms, 0.328→0.262ms다. 실단말 개선율로 환산하지 않는다.
- 그림자 GPU 88개 비교에서 새 투영의 캐시 사용/미사용 출력 차이 0.
  카메라·이동 물체·캐스터 무효화를 포함하며 GPU 오류 0.
- 기존 투영과 패딩 투영 사이에는 D32 투영 반올림과 경계 커버리지 차이가 있다.
  동일 픽셀 출력이라고 주장하지 않는다. 비교 영상의 최대 평균 채널 차이는
  0.0143/255, 드문 그림자 경계의 최대 개별 채널 차이는 87/255였다.
  그림자 비교 이미지를 육안 확인했고, CPU 2개 회귀 검사에서 기존 전체 체적 포함,
  텍셀 밀도, 월드 기준 바이어스, 텍스처 한도와 이동 중 재사용을 검증했다.
- 선택한 Node 회귀 검사 90개 중 88개 통과. 나머지 2개는 55993d54에서도
  동일하게 실패하는 추출형 테스트의 외부 의존성 누락이다.
  `test-complex-frame-budget.mjs`는 BoundedCache import를 VM에 제공하지 않으며,
  `test-native-material-lifetime.mjs`는 leanUpdateMatrixWorld를 제공하지 않는다.
  이번 변경으로 생긴 실패로 분류하지 않고 원래 상태에서도 재현했다.
  TypeScript와 Vite 프로덕션 빌드는 통과했다.

음소거한 새 Chrome에서 실제 렌더 프레임을 측정했다. 모바일 제한 시뮬레이션은
CSS 933×704 / DPR 2.625 / 실제 1866×1408 / high / WebGPU다. RTX 3070의
그래픽 클럭 405MHz, CPU 제한 1배이며 실제 Fold8의 타일 GPU, 대역폭과 발열을
재현하지 못한다. PC에는 모바일 어댑터 제한을 적용하지 않았다.

모바일 180초 비행: 평균 59.76fps, 표본 최저 및 모든 렌더 프레임 끝점에서 검사한
최저 1초 FPS 모두 52, p95 19.2ms / p99 23.0ms / 최대 100.4ms, 오류 0.
일시적인 프레임 지연이 존재하므로 모든 프레임이 60fps라는 뜻은 아니다.
이 비행은 최종 HUD 추가 전 동일한 그림자·후처리 코드에서 측정했다.

PC 405MHz 스트레스 조건 180초: 실제 2400×1350 / high, 평균 41.71fps,
최저 1초 17fps, p95 41.7ms / p99 57.8ms / 최대 104.5ms, 오류 0.
해상도는 PC의 기존 렌더 배율 1.25가 적용된 값이다. 이 조건은 성능 목표 미달이다.
정상 클럭 PC 90초는 평균 53.2fps, 최저 1초 38fps, p95 27.6ms / p99 35.1ms /
최대 106.2ms, 오류 0이다. 정상 클럭에서도 전 구간 50fps에는 미달한다.
GPU 표본 중앙값은 JSON에 기록하며, PC의 상세 로딩 중 프레임 지연도 별도 과제로
남는다. 어떤 결과도 실단말 60fps 보증으로 바꾸지 않는다.
