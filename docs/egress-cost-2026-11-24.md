# 2026-11-24 외부 전송량 2차 절감

11월 Render 외부 전송량이 100 GB를 넘었다. Render API 키가 만료됐고 관리자 계측
(`/api/admin/atlas/snapshot`)은 관리자 로그인이 필요해서, 이번 분석은 운영 사이트를
브라우저에서 직접 측정해 진행했다. 서비스 화면과 데이터는 바꾸지 않는다.

## 측정(운영, 홈 화면 탭 하나를 열어 둔 상태)

- 원 서버(kospimap.com)에서 받는 양은 시간당 약 16 MB(10초 폴링 합계)였다.
- 그중 `/api/market/ticker`가 약 64%였다. 한 번에 gzip 약 22 KB(원문 72 KB)를 받는다.
  27개 종목의 1분 단위 스파크라인 점이 약 9,600개 들어 있는데, 10초 사이에 바뀌는 것은
  마지막 1~2분 구간뿐이다. 이 티커는 NeoShell 헤더에 있어서 모든 페이지가 10초마다 받는다.
- Render 앞단 Cloudflare 응답은 `cf-cache-status: DYNAMIC`이었다. 웹 서비스 응답은 엣지에
  캐시되지 않으므로 모든 바이트가 원 서버 전송량으로 집계된다.
- 11-08 이후 추가된 공개 파일 25개(약 6.1 MB)가 CDN 명세에 없어서 Render가 직접 제공하고
  있었다. 큰 것은 `3d/pipelines.json`(0.98 MB, 3D 뷰 진입마다), BGM 이퀄라이저
  `bgm/zXGb3k-A1Vo.json`(1.58 MB)·`bgm/2moWP_PSooE.json`(1.08 MB),
  `3d/pulse2/energy_human.glb`(0.93 MB), 공유 카드 PNG 3개(1.47 MB)다.
- 대형 3D 거래소 모델(22 MB GLB, HDR)은 이미 GitHub Pages로 리디렉션되고 있음을 확인했다.

## 조치

1. **티커 꼬리 전송**: `/api/market/ticker?tail=8`는 종목별로 마지막 8개 점과 전체 길이,
   첫 값, 왼쪽부터 더한 합계를 보낸다. `useMarketTicker`는 이미 가진 시계열에 꼬리를
   이어 붙이고 길이·첫 값·합계가 정확히 맞을 때만 쓴다. 하나라도 맞지 않으면 즉시 전체를
   다시 받고, 맞더라도 5분마다 전체를 받는다. 첫 조회는 항상 전체다.
   운영 데이터로 15초 간격 8회(216건)를 확인한 결과, 이어 붙인 시계열이 같은 시점의 전체
   응답과 모두 일치했고 원문 크기는 10.2%였다.
2. **CDN 누락분 게시**: 위 25개 파일을 `kospimap-assets`의 `objects/<sha256>`에 추가로 게시했다
   (기존 파일을 덮어쓰거나 삭제하지 않음). GitHub Pages에서 SHA-256과 CORS를 확인한 뒤 명세에
   반영했다. `ads.txt`는 광고 크롤러가 같은 도메인에서 읽어야 하므로 제외했고, `robots.txt`와
   HTML도 기존 규칙대로 제외했다.

## 예상 효과

- 홈 탭 하나 기준 시간당 약 16 MB → 약 6.5 MB(티커 10.3 MB/h → 약 1 MB/h). 모든 페이지가
  헤더 티커를 쓰므로 페이지별 절감량은 대략 같다(시간당 약 9 MB).
- 위 정적 파일은 첫 방문 때 원 서버에서 받던 양만큼 줄어든다.
- 실제 월 절감률은 방문량에 따라 달라서 배포 직후 짧은 관측으로 확정하지 않는다.

## 남은 후보(이번에는 적용하지 않음)

- 미국 지도 `sp500-map` 전체 목록 10초 폴링(gzip 약 31 KB/회)과 국내 지도 전체 목록 60초 폴링
  (약 20 KB/회): 종목 단위로 변경분만 보내려면 서버 상태와 병합 규칙이 필요해서 별도로 검증한다.
- CCTV 영상 중계(`/api/realestate/cctv/media`): 시청 중에만 발생하며, 기능을 바꾸지 않고는
  줄일 수 없다.
- 경로별 정확한 비율은 관리자 아틀라스의 `response_bandwidth`로 확인해야 한다.
  Render 지표를 다시 조회하려면 `render login`이 필요하다.

DB와 저장 데이터는 삭제·초기화·변경하지 않았다.
