# 드론 검색 결과 첫 선택 수정

결과 버튼으로 포커스가 넘어가면 입력창의 한글 조합이 확정되고 모바일 키보드가
닫힐 수 있다. 목록 위치가 mousedown과 click 사이에 바뀌면 첫 클릭의 대상이
달라져 선택되지 않는다. 기존 코드는 선택 후 입력창을 다시 포커스해 이 전환을
반복했다.

결과 버튼의 mousedown 기본 포커스 이동을 막고, 클릭을 처리하는 시점에 한글
입력을 먼저 확정한 뒤 선택값을 저장한다. 입력창 복귀는 preventScroll을 사용한다.
선택 한 번으로 표시명과 좌표가 확정되고 이동 버튼이 활성화된다. 기존 이동 버튼,
키보드 선택과 결과 목록의 터치 스크롤은 유지한다. 공유 검색 컴포넌트이므로
드론 탐험·건물 드론뷰의 모바일과 PC에 함께 적용된다.

검증:

- 실제 Chrome + React 컴포넌트, 검색 API만 고정 응답으로 격리했다.
- 키보드 닫힘에 따른 화면 이동을 blur 시점에 재현한 검사에서 운영 기준
  74a6776a는 마우스와 터치의 첫 선택이 모두 실패했다. 나머지 7개는 통과했다.
- 수정 후 9개 모두 통과: 마우스/터치 선택, 한글 조합 중 선택, 키보드 선택,
  blur에 따른 화면 이동, 선택을 발생시키지 않는 터치 스크롤.
- 장소 좌표·중복 제거 등의 기존 Node 검사 7개와 TypeScript/프로덕션 빌드 통과.
- 드론 전체 화면에서도 한글 조합 중 결과를 한 번 선택하고 이동을 누르면
  해당 좌표의 장면이 열리는 흐름을 모바일·PC에서 확인했다.
- 정상 클럭 RTX 3070의 이동 후 10초 검사: 모바일 시뮬레이션 1866×1408/high는
  평균 59.03fps / 최저 1초 54 / p95 22.4ms / p99 40.3ms / 최대 83.9ms,
  PC 2400×1350/high는 평균 59.00fps / 최저 1초 56 / p95 22.8ms /
  p99 35.5ms / 최대 69.5ms였다. 렌더 failed=false이며 짧은 동작 회귀 검사다.
  Fold8의 물리 성능이나 장시간 지속 60fps 달성으로 해석하지 않는다.
- GPU 렌더러·엔진·프레임 예산 모듈의 빌드는 기존 운영과 파일명 해시 참조를
  정규화한 뒤 동일했다. 출력 해상도와 품질 설정을 변경하지 않는다.

재실행: `cd frontend` 후 `python scripts/test-drone-place-selection.py`.
기준 버그 재현: 같은 명령에 `--source-ref=74a6776a`를 추가하면 해당 두 검사가 실패한다.
Chrome은 항상 `--mute-audio`이며 테스트 검색은 외부 서버·DB에 저장하지 않는다.
