# 렌더러 최적화 병합·배포 변경 기록

사용자는 최적화 변경의 병합·배포와 개선 내용 보고를 요청했다. 배포 전 기존 서버가
재시작할 때 통계 집계의 교체 및 오래된 기록 정리 작업을 시작한다는 사실을 설명했고,
사용자는 “허용할테니 배포해”라고 답했다. 이 허용은 **이번 배포에서 기존 서버의
자동 정리·집계 작업이 실행되는 범위**에 한한다. AGENTS.md의 일반 원칙과 DB 권한을
변경하거나 새 삭제 작업을 추가하는 허용으로 해석하지 않는다.

원격 main 및 운영 기준은 `3e71dc0`이다. `perf/codex-render-20261016`의
최적화 커밋 `cb25cdc`와 검증 기록 `6097ab8`을 전용 릴리스 브랜치에 병합했다.
병합 커밋은 `88e6407`이다. 도로·다리 작업 폴더의 미완료 변경은 배포에 포함하지 않았다.

## 개선 내용

| 항목 | 이전 처리 | 적용한 처리 | 근거 |
|---|---|---|---|
| 셰이더 분석 | 같은 소스·매크로의 분석 요청도 워커로 반복 전달 | 동일한 동시 요청을 하나로 합치고 완성 WGSL을 제한된 메모리 캐시에서 재사용 | 합성 도시에서 분석 요청 135→22건, 83.7% 감소 |
| 매 프레임 동기화 | 큰 Set을 다시 구성하고 각 객체의 포함 여부 조회 | 재사용 목록과 메시의 동기화 번호로 현재 장면 판정 | 3,000/12,000객체 CPU 중앙값 10.2%/5.1% 감소 |
| 재질 집계 | flatMap과 단일 재질 임시 배열 생성 | 직접 순회하며 사용 중인 재질 집계 | 기존 재질·텍스처 수명 규칙 유지 |
| 실패 복구 | postMessage가 동기 실패하면 대기 항목 잔류 가능 | 실패 항목을 메모리 대기 목록에서 해제하고 재시도 허용 | 워커 실패·재시도 회귀 검사 통과 |

변경한 런타임 파일은 `frontend/src/components/tidewater/ComplexRenderer.js`와
`frontend/src/vendor/tidewater/engine/gpu/ShaderAnalysis.js` 두 개다. 재질별 GPU 바인딩,
화면 해상도, 그림자·PCSS·AO·TAA·블룸·구름 설정은 유지했다.

## 확인된 효과와 한계

Edge 156 / NVIDIA Ampere / 실제 캔버스 2400×1350 / high / 합성 도시 1,601객체에서
후보 두 회의 평균은 59.54/59.76 FPS, 1초 구간 최저는 57.67/58.78 FPS였다.
고정 카메라의 후보·기준 이미지 한 쌍은 픽셀 단위로 동일했다. 생산 셰이더의 워커
분석 결과도 동기 분석 결과와 일치했다. 회귀 검사 78개, TypeScript와 앱 전체 빌드를
선행 검증했다. 릴리스 폴더에서 병합 후 검사와 배포용 빌드를 다시 확인한다.

기존 합성 단지의 첫 표시는 기준 2,250ms에서 후보 1,607/1,572ms였다. 반면 로딩 중
최대 간격은 기준 199.6ms에서 후보 250.2/316.8ms였다. 반복 수와 시스템 부하 편차가
있으므로 로딩 끊김 개선은 확인되지 않았고 악화 가능성도 남아 있다.

**실제 한강·도심 전체 경로에서 50 FPS를 계속 유지한다는 목표는 미검증이다.**
합성 비행에서도 개별 20ms 초과 프레임은 남아 있다. 이 배포는 검증한 계산·자원 재사용
최적화를 적용하는 것이며 목표 전체 달성을 뜻하지 않는다.

상세 측정·재현 방법: [최적화 검증 기록](codex-render-optimization-2026-10-16.md).
실제 배포 완료 여부는 새 main 커밋이 운영 `/api/health`에 표시되는지, 드론 HTML과
배포 정적 파일이 정상 제공되는지 별도로 확인해 로컬 결과 보고서에 기록한다.
