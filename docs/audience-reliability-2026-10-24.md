# 최근 24시간 접속 지도 수집 누락과 0건 표시 보완

작업 기준은 실제 운영 커밋 `9c05f18e`다. 원래 작업 폴더는 이전 버전이어서
최신 main의 별도 worktree `audience-reliability-20261024`에서 수정했다.

## 확인한 결함과 변경

- 운영의 직접 원인은 Turso HTTP 전송 계층의 BLOB 형식 오류였다. 관리자 시스템
  화면의 `audience_live` 오류는 `JSON parse error: missing field base64`였으며,
  일별 지역 집계는 쌓이는 반면 지도용 암호화 저장은 실패가 누적되고 있었다.
  바이너리 nonce/암호문을 보낼 때 잘못 쓰던 `value` 필드를 `base64`로 고치고,
  DB가 돌려주는 BLOB도 `base64`에서 복원하도록 송수신을 모두 수정했다.
  [공식 Hrana Value 규격](https://github.com/tursodatabase/libsql/blob/main/docs/HRANA_3_SPEC.md#values)과 대조했다.
- 페이지 접속 이벤트의 세션 ID가 유효해도 `browser_id`가 없으면 지도 수집까지
  생략했다. 설정 조회 지연·실패, 브라우저 저장소 제한, 이전 클라이언트에 해당한다.
  이제 이런 공개 페이지 접속도 세션 ID를 HMAC으로 가명화해 암호화 지도 저장소에
  기록한다. 지속 브라우저 ID를 지어내지 않으므로 재방문 지표에는 넣지 않는다.
- 관리자·봇·DNT/GPC 제외를 유지한다. 새 클라이언트는 WebDriver 여부도 전송해,
  브라우저 ID 없는 접속을 받는 경로로 알려진 자동화가 들어오는 것을 방지한다.
  신뢰할 수 있는 프록시를 통과한 IP만 기존 로컬 GeoIP 조회에 사용한다.
- 잘못된 IP 좌표 때문에 유효한 접속까지 사라지던 경로를 수정했다. 이 경우 좌표를
  붙이지 않고 위치 미확인으로 저장한다. 임의 좌표나 과거 접속 시각을 만들지 않는다.
- 암호화 실패가 저장 실패 집계 밖에서 발생하던 문제를 수정했다. 준비되지 않은
  저장소에 들어온 요청도 수신·실패 횟수와 안전한 상태 코드로 드러난다.
- 시작 시 일시적인 DB 실패로 수집이 계속 꺼져 있는 경우를 줄이기 위해 기존의
  추가 전용 초기화를 5회 재시도한다. 관리자의 조회 요청은 DDL을 실행하지 않는다.
- 지도 준비 실패·저장 전부 실패·조회 실패는 정상적인 0건과 구분한다. 확인할 수
  없는 숫자는 `—`로 표시하고, 원인·프로세스 시작 이후 수신/저장/실패 횟수와
  마지막 저장 시각을 안내한다. 국가 필터가 원인이면 전체 국가의 세션 수도 안내한다.
- 재방문 집계 조회가 실패해도 별도 지도와 상태 안내는 표시한다.
- BLOB 수정 배포 후에도 운영 지도는 수집 요청/성공/실패가 모두 0회였다.
  별도 지도 presence 요청이 foreground 타이머와 지속 브라우저 ID에 의존하는
  반면, 기존 방문 heartbeat는 background에서도 동작해 두 수집 경로가 달랐다.
  이제 기존 공개 페이지의 실제 heartbeat에서도 HMAC 세션을 암호화 지도에 기록한다.
  같은 사이트의 공개 페이지 referrer가 있는 요청만 받고 관리자·봇·DNT/GPC를
  계속 제외한다. 새 합성 방문을 만들거나 위치를 임의로 생성하지 않는다.
- 수집 이전에 제외된 요청도 사유별 집계 횟수로 확인한다. 개인정보 보호 설정,
  봇, 설정 미완료, 브라우저 ID 누락, 잘못된 ID를 구분하며 원문 요청 헤더·UA·ID·위치는
  진단에 포함하지 않는다. 관리자 화면에도 대상/개인정보 보호/봇 제외 횟수를 표시한다.

## 보존 범위

기존 DB 자료 수정·삭제·초기화·복원과 키 교체는 수행하지 않았다. 새 테이블이나
삭제 작업은 추가하지 않았다. 과거 일별 통계는 정확한 시각 정보가 없으므로
24시간 세션으로 소급 생성하지 않는다. 기존 HMAC/AES-GCM 보호를 유지한다.

## 검증 및 운영 확인의 한계

- `backend/tests/test_audience_live.py`, `test_audience_analytics.py`, `test_turso_blobs.py`: 새 임시
  SQLite DB만 사용한다. 브라우저 ID 없는 접속의 미확인 집계와 실제 IP 마커 생성,
  개인정보 신호·봇 제외, 암호화 실패, 잘못된 좌표, 국가 필터를 포함해 61개 검사 통과.
  추가한 HTTP 규격 검사 9개는 수정 전 모두 실패하고, 송수신 수정 후 모두 통과했다.
  가짜 Hrana 서버와 새 임시 SQLite를 연결해 실제 전송 계층을 통한 암호화 저장,
  BLOB 조회, 복호화, 지도 세션 생성까지 검증한다. 운영 자격 증명은 사용하지 않는다.
  heartbeat 검사에서는 기존 방문 저장 함수를 stub으로 교체하고 새로운 임시 DB에서만
  지도 저장을 검증한다. 관리자/다른 사이트/누락된 referrer 및 개인정보 보호·봇 제외를 검사한다.
- `frontend/scripts/test-audience-country.py`: 합성 API만 사용한다. 1440/1024/390/320px,
  실제 Leaflet 마커 개수, 전체/국가/미확인 필터, 준비/저장/조회 실패 안내를 검증한다.
- TypeScript 및 전체 Vite 운영 빌드. 운영 API/DB에 합성 접속을 넣지 않는다.
- 공개 `/api/health`에서 운영 커밋, `/api/activity/audience-config`에서
  `enabled`, `location_enabled`, `presence_enabled`가 모두 true인 것을 확인했다.
- 사용자가 확인한 `stock_market` 워크스페이스에서 운영 요청 로그를 조회했다.
  별도 접속 수집 POST는 도착하고 있었으며 지도 조회에는 503도 반복됐다.
  사용자가 로그인한 관리자 시스템 화면에서 위 BLOB 오류를 직접 확인했다.
- DB 쓰기 자격 증명을 AI 환경으로 가져오지 않았고, 운영에 합성 접속을 넣지 않는다.
  저장 실패로 원래 생성되지 않은 과거 위치를 임의로 복원하지 않는다.
