# 360도 회전 버튼과 로딩 대기 개선

2026-10-11 오전 작업을 `feature/surface-rail-20261010` 작업 폴더에서 이어서 진행했다.
별도의 수정사항이 많은 원래 `drive-streaming` 폴더는 덮어쓰지 않았다.

## 반영 내용

- 상승·하강 버튼 아래의 회전 버튼을 누르면 현재 위치에서 약 90초마다 한 바퀴씩
  계속 회전한다. 다시 누르면 마지막 방향에서 멈춘다. 현재 시야 기울기는 유지한다.
- 수동 키보드·스틱·고도·휠·드래그 입력, 착륙·위치 재설정 시 자동 회전을 해제한다.
  오토 파일럿과 동시에 켜지지 않으며 기존 높이 안전 검사를 유지한다.
- 모바일 가로·세로 배치와 버튼의 시작·정지 이름, `aria-pressed`, 활성 색상을 포함한다.
- 공개 GIS 파일을 같이 쓰는 요청은 다운로드 한 개를 공유한다. 마지막 사용자가
  취소하면 대기 요청을 제거하고 진행 중인 다운로드도 취소하여 새 시야의 슬롯을 확보한다.
  다른 사용자가 남아 있는 공유 다운로드는 계속된다.
- 최초 미리 읽기와 실제 선택이 같은 도로 준비 작업을 다시 요청할 때, 기존 작업을
  먼저 확인하도록 수정했다. 결과가 사용되지 않는 건물 외곽 전체 페이지의 조회와
  해석을 중복 시작하지 않는다. 하위 JSONP 캐시가 남아 있으면 이미 공유되던 요청이며,
  해당 캐시가 밀려난 경우의 추가 요청도 예방한다. 필요한 외곽·도로 구조 정보는 유지한다.
- 동시에 진행하는 다운로드 6개, 메모리 캐시 32MiB/512개 한도와 복사본 소유권을 유지한다.
  실패한 다운로드는 캐시하지 않아 재시도할 수 있다.
- 기존 브라우저 GIS 저장소는 읽기 전용으로 조회한다. 저장소 생성·갱신·자동 정리·
  삭제를 실행하지 않는다. 만료 기록도 남겨둔다. 새로 다운로드한 바이트는 메모리에만
  보관하므로, 새 파일의 캐시는 페이지를 다시 열면 다시 받아야 한다.

## 검증

관련 Node 테스트 70개, TypeScript 검사, 독립된 새 출력 폴더의 Vite 운영 빌드가 통과했다.
브라우저 검증은 Chrome 154.0.8037.98, `--mute-audio`, 별도 공개 스냅샷 API를 사용했다.
테스트 브라우저에서는 IndexedDB를 비활성화해 기존 저장 자료를 열거나 정리하지 않았다.
운영·개발 DB, 앱 서버와 데이터 수집 작업은 실행하지 않았다.

해운대 94초 회전: 위치/기울기 불변, 회전각 6.567라디안, 수동 전환·정지·착륙 시 해제,
390×844 및 844×390 배치와 가림 여부를 확인했다. 런타임/WGSL 오류는 0건이다.

| 회전 렌더링 지표 | 결과 |
|---|---:|
| 평균 FPS | 59.87 |
| 최저 1초 렌더 FPS | 56.98 |
| p95 / p99 프레임 시간 | 16.8 / 16.8ms |
| 최악 프레임 | 33.4ms |
| 실제 렌더 프레임 수 | 5629 |
| 출력 / 픽셀 비율 / 품질 | 2520×1750 / 1.75 / high |

고립된 VM에서 250ms짜리 이전 다운로드 6개를 모두 취소한 후 새 요청을 실행한
통제 실험은 이전 254.575/249.464/251.537ms, 수정 후 0.648/0.335/0.318ms였다.
이는 취소된 다운로드가 슬롯을 막는 지연의 비교이며 전체 페이지 로딩 개선율을 의미하지 않는다.
실제 첫 화면과 건물 상세화 속도에는 외부 GIS 응답과 GPU 준비 시간이 함께 영향을 준다.

## 최종 빌드의 밀집 지역 검사

선덕중학교 주변, NVIDIA Ampere WebGPU, 1440×1000 뷰포트, 출력 2520×1750 /
픽셀 비율 1.75 / high 고정, 차량 활성화 후 각 10초 구간을 측정했다.
Chrome의 실제 장면 렌더 프레임 수를 rAF 표본과 함께 기록했다.

| 구간 | 평균 FPS | 최저 1초 FPS | p95 / p99 | 최대 멈춤 |
|---|---:|---:|---:|---:|
| 최초 위치 | 59.72 | 57.98 | 16.8 / 16.9ms | 33.4ms |
| 이동 | 57.39 | 51.98 | 16.8 / 33.4ms | 50.0ms |
| 복귀 | 56.98 | 47.72 | 33.2 / 33.4ms | 50.1ms |

복귀 구간은 최소 50fps 조건에 미달한다. 전 구간 성능 목표 달성으로 보고하지 않는다.
처음 화면은 이전 3892ms, 바이트 대기 개선만 적용한 V1 3872ms, 최종 V2 3860ms로
비슷했다. 각 한 번의 외부 GIS 측정이고 표시 건물 수도 달라 유의한 전체 로딩 개선율이나
프레임 개선율을 산출하지 않는다. 최종 복귀 후 GC를 거친 JS 힙은 약 632MiB였으며
오류는 0건이다. 장시간 비행의 메모리 안정성을 확인한 결과는 아니다.

회전의 94초 측정은 V1이며 V2는 도로 준비 중복 시작을 추가로 막은 동일 회전 구현이다.
터치 입력은 실제 Chrome 터치 에뮬레이션에서 상승·하강 아래 배치, 시작·정지,
수동 전환, 착륙을 별도로 검증했다. 모바일 출력은 780×1688 / 픽셀 비율 2 / high이며,
이 검사는 이 PC의 에뮬레이션 결과로 실제 휴대전화의 성능 보장이 아니다.
