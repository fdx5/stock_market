# 드론뷰 성능·상세 로딩 긴급 수정

요구 기준: Chrome 실제 비행에서 전 구간 최소 50fps, 목표 60fps; 가까운 건물부터 상세 준비; 작업자·타일·GPU·CPU 메모리의 제한과 회수. `frontend/AGENTS.md`에 이후 작업 기준을 기록했다.

## 확인된 결함과 수정

- 건물 상세 작업자의 오류 처리가 비어 있었고 기한이 없었다. 오류·무응답이 상세 대기 슬롯을 영구 점유할 수 있었다. 작업자당 하나의 작업, 우선순위 큐, 45초 기한, 오류 시 교체, 취소 시 회수, 종료 시 전체 대기 정리를 적용했다. 상세 모델 요청을 색상 요청보다 우선한다.
- 상세/색상 작업 실패도 완료 상태가 되어 재시도되지 않았다. 실패는 다시 대기 상태로 되돌리고 2.5~30초 점증 대기를 적용했다. 상세 준비는 현재 카메라와 가까운 타일 순서로 예약한다. 상세 모델이 실제 그려지기 전에는 기존 건물을 유지한다.
- 도로·기본 건물·토지 작업자도 무응답 시 타일 슬롯을 점유할 수 있었다. 같은 취소/기한/정리 규칙을 적용했다. 기존 타일 재시도가 대기 슬롯을 다시 사용할 수 있다.
- 최초 도로의 교차로·차선 준비가 차량 모델/텍스처 다운로드 뒤에 있었다. 도로 연결 계산과 콜백을 차량 다운로드 앞에 배치했다. 차량 파일이 무응답이어도 도로 준비가 진행되는 실제 함수 회귀 검사를 추가했다.
- 철도 건물 겹침 보정은 교차하지 않는 건물의 음성 결과를 기록하지 않아 750ms마다 모든 선로를 재검사하고 벡터를 생성했다. 선로 공간 인덱스, 건물 경계 캐시와 음성 결과 캐시를 적용했다. 카메라가 400m 경계를 통과했다는 이유만으로 같은 건물을 다시 절단하지 않는다. 모델 전송 복사는 8,192 정점 단위로 프레임 사이에 나누고 건물에 관련된 선로만 전달한다.
- 철도/보정 완료 콜백의 `resume()`가 정규 표시 프레임 사이에서 즉시 렌더링하고 다음 프레임을 취소했다. 예약된 표시 프레임은 유지하며 새 프레임을 중복 예약하지 않는다. 실제 렌더를 시도한 프레임만 FPS 계측에 포함하고 숨김/재개 때 측정 구간을 초기화한다.
- 데스크톱 해상도 제어는 GPU 여유만 보면 픽셀 수를 올렸고 감소 경로가 없었다. 모든 장치에 60fps 목표/50fps 하한의 프레임 압력 제어를 적용했다. 연속 19ms 초과 시 픽셀 수를 줄이고, 지속적인 CPU/GPU 여유가 있을 때 천천히 복원한다. 건물·도로·물·열차 모델 및 텍스처 내용을 생략하지 않는다. 화면 픽셀 비율은 0.8~2 범위에서 변할 수 있어 기존 2배 슈퍼샘플링보다 화면 선명도가 낮아질 수 있다.
- 지형 스트리밍의 예약·회수 판단은 매 프레임 대신 80ms 간격으로 진행하고 20m 이상 이동/시점 점프 시 즉시 재평가한다. 비행·차량 애니메이션은 매 표시 프레임 진행한다. 동시 타일은 데스크톱 8→4, 제한 장치 3→2, 상세 작업은 4→2/2→1로 제한한다. 일반 실행의 무제한 성능 마크 누적을 없애고 `dtrace=1`에서만 남긴다.

## 화면 FPS

최종 CPU 구간 계측에서 최근 추가한 바다 경계 절단에 196.1ms, 지면 보정에 160.9ms가 확인됐다. 정확한 경계 절단과 지면 법선 재구축을 별도 작업자에 옮겼다. 물 영역 판정은 1,024 정점마다 표시 프레임에 양보하고 결과가 완성된 뒤 한 번에 교체한다. 이전 바다는 준비 완료 전까지 유지한다. 늦은 결과는 취소·폐기하며 착륙 시 원본을 복원한다. 기존 경계/속성 보간 알고리즘은 동일하다.

가까운 초기 장면의 교통 시뮬레이션은 고도 60m를 넘었다는 이유로 2~3 프레임 분량을 한 번에 수행하지 않고 매 표시 프레임에 분산한다. 차량 충돌·신호 규칙과 시간 총량을 유지한다. 실패 타일은 형제 작업자를 취소하고 텍스처로 인계하지 못한 비트맵을 닫는다. 타일 회수 시 대형 건물·보행 경로 배열과 상세 상태도 해제한다. 추가 회귀를 포함해 109개 순수 검사가 통과했다.

URL에 `fps=1`을 추가하면 실제 장면 렌더 루프의 최근 측정 FPS를 표시한다. 예: `/drone-explore?fps=1`; 기존 파라미터가 있으면 `&fps=1`. 숨김/멈춤 뒤 오래된 값은 측정 대기로 전환한다. 기본 실행에는 별도 FPS 타이머가 없다.

## 검증 범위와 한계

독립 로컬 읽기용 스냅샷 API만 사용한다. 운영 데이터 API나 DB를 시험 대상으로 사용하지 않는다. Chrome 1440×1000, 기존 배포와 수정 빌드에서 같은 해운대 도심·해안·광안대교·복귀 시나리오를 비교한다. 원시 자료는 `tmp/drone-performance-20261010/`에 보존한다. 네트워크 지연과 GPU 드라이버/사용자 동시 작업은 측정 변동 요인이다.

초기 비교(양쪽 Chrome CPU 샘플러 사용): 도시 비행 평균 43.42→51.21fps, 최저 1초 25.99→44.72fps. 이 중간 결과는 최소 50fps 합격이 아니었다. 아래 최종 측정에는 CPU 샘플러를 사용하지 않고 구간 계측만 적용했다. 전국/모든 장치 성능을 보장하지 않는다.

타입 검사와 최종 순수 회귀 123개 통과: 작업자 오류·무응답·취소·종료, 도로 준비와 차량 의존성, 표시 프레임 중복 방지, 공간 인덱스/음성 결과 재사용, 해안선·교량·철도·역사 통과 공간·오토파일럿·메모리 회수, 도로/건물 검사 작업자의 원본과 결과 일치, 네이티브 새/교체 형상의 프레임 분산과 기존 형상 유지.

## 최초 진입과 새 건물 반영의 후속 수정

긴급 배포 `67f7ace`의 운영 상태와 배포 파일을 확인했다. 이 빌드는 해안 비행 중 메인 스레드 바다 절단/지면 보정의 최대 시간을 각각 0.6ms로 줄였지만, 최초 진입 측정에서는 최대 265.1ms의 프레임이 남았다.

초기 실측 모델이 도로를 침범하는지 확인하는 함수는 모든 삼각형 변을 0.5m 간격으로 동기 검사했다. 같은 판정을 별도 작업자로 옮기고, 도로/건물 경계 인덱스를 작업자 안에서 재사용했다. 현재 사용하는 형상 배열은 분리하지 않는다. 실패/취소/30초 기한 시 등록 대장 기반 건물을 유지한다. 임의 표본으로 검사를 축소하지 않았으며, 원본 함수와 100개 형상/오프셋 조합의 판정 일치를 검증했다.

네이티브 렌더러의 기존 3ms 제한은 새 재질 수만 세었다. 같은 재질을 공유하는 새 형상은 제한을 건너뛰었다. 이제 새/교체 형상도 표시 프레임당 최대 4개 및 같은 시간 제한 안에서 반영한다. 큰 작업 하나의 진행은 허용해 상세 로딩이 영구 대기하지 않게 한다. 교체가 대기 중이면 이전 형상을 유지하고, GPU 준비 확인 뒤 상세 건물을 표시하는 기존 규칙을 유지한다.

후속 작업자 적용 중간 빌드의 해운대 5개 구간 최저 1초 FPS는 53.10~55.26, 최초 진입 최대 프레임은 35.9ms였다. 마지막 네이티브 분산 보완 이후 창동의 최초 진입/420m 이동/복귀 최저 1초 FPS는 54.20/50.28/50.28, 평균은 55.66/55.18/54.15였다. 네이티브 동기 반영 최대 구간은 4.7ms, 전체 렌더 호출 최대는 22.1ms였다. 창동 상세 완료 타일은 18→24→26으로 진행했고 작업자 대기 슬롯은 복귀 시 0이었다. 오류 목록은 비어 있었다.

측정 조건은 Chrome 154.0.8037.98, 1440×1000, 새 독립 세션, 로컬 보존 스냅샷 API 및 공개 GIS, 구간별 2.5초 정착+10초 비행이다. 한 번의 비교 결과이며 외부 자료 도착 시점은 같지 않을 수 있다. 이 시험은 전국 장시간 비행이나 사용자의 미확인 장비/해상도에서의 50fps 보증이 아니다. 건물/물/열차/도로 세부 형상은 생략하지 않았지만 프레임 압력에 따라 출력 픽셀 수가 낮아질 수 있다.

8개 측정 구간의 최저 1초 FPS가 모두 50 이상이었다. 단일 프레임은 여전히 20ms를 넘는 경우가 있다. 창동의 최초 진입 최대 71.7ms도 남아 있다. 따라서 순간 프레임까지 항상 50fps 이상이거나 전 구간 60fps를 달성했다고 표현하지 않는다. 최종 해안선 절단 호출은 최대 0.8ms, 지면 보정 호출은 최대 0.6ms, 네이티브 동기 반영은 최대 4.5ms였다. 브라우저 오류는 두 실행 모두 0개였다.

비행 후 GC 잔류 JS 힙은 해운대 449.7MiB, 창동 423.2MiB였다. 해운대 해안 작업자는 4개 작업 완료/실패 0, 바다 형상 교체 대기 0을 기록했다. 이 값은 JS 힙이며 GPU 메모리 전체가 아니다. 기존 원본 형상 보존/종료 회수, 타일 수와 작업자 동시성 제한 회귀도 통과했지만 장시간 메모리 누수 부재를 보증하는 시험은 아니다.

원시 결과: `tmp/drone-performance-20261010/final-haeundae-v2/report.json`, `final-changdong-v2/report.json`. 같은 조건의 이전 운영 빌드 도심 이동은 평균 46.20/최저 27.10fps였다. 외부 데이터 도착 차이가 있으므로 정확한 성능 개선 배율이나 사용자가 경험한 20fps 재현으로 취급하지 않는다.

## 잔여 과제

역 팻말의 네이티브 렌더 호환성, 초기 도로의 4초 부분 데이터 fallback, 전국 장시간 비행과 반복 장면 종료/재개 검증은 별도 잔여 작업이다. 이번 긴급 수정으로 모두 완료했다고 보고하지 않는다.
