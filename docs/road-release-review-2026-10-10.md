# 도로 공통 개선 배포 준비 및 교량 재검토

작성일: 2026-10-10. 기준: 운영 중인 main 커밋 `78319dd33803a40208d0f89c4128fbfc235d64e2`.
작업 브랜치: `release/road-common-20261010`. 현재 운영 배포는 실행하지 않았다.

## 최신 운영 코드에 반영한 내용

기존 로컬 브랜치는 운영보다 오래된 상태였다. 운영의 공식 VWorld 구조 정보, DEM 기반 교량 높이, 도로 BVH, 드론 및 장면 전환 처리를 유지하면서 필요한 변경만 별도 작업 트리에 통합했다.

1. 화면 경계를 통과하는 선분의 정확한 교점을 유지한다. 양 끝이 밖에 있는 긴 도로도 보존하며, 밖으로 나갔다 돌아오는 경로를 직선으로 잇지 않는다.
2. 가까운 끝점은 인접 격자까지 실제 1.5m 거리로 확인한다. 분기, 층, 차로, 폭 및 고가 도로 프로필 소유자가 다른 구간을 합치지 않는다. 원본 좌표와 공식 전체 교량 프로필을 보존한다.
3. 프런트엔드·백엔드에 등록된 1차로 진입·연결 도로도 포함한다. VWorld 다중 선형 및 클리핑 결과에는 구분되는 ID를 부여한다.
4. 교량 높이 질의는 링크 ID가 없더라도 도로의 고유 프로필에 제한한다. 소유 도로가 없는 질의는 가까운 중심선을 선택한다.
5. 실제 주행 그래프의 끝점 및 T 연결, 주행 타일의 교차로·보도·차선 절단에 높이 차이 검사를 추가한다. 부동산 3D 교통 연결에도 높이를 검사한다.
6. 공식 교량·고가 도로를 평면 건물·교각 외곽선만으로 잘라내지 않는다. 지상 도로의 건물 충돌 제외는 유지한다. 고가 도로와 실제 건물의 3D 충돌 판정에는 건물 높이 범위가 필요하다.

## 사용자 점검으로 발견한 검토 화면의 오류

고덕토평·김포·방화·성산·서강·한강대교 단절 신고를 추가 조사했다. 다음 두 원인은 앞서 제공한 격리된 로컬 검토 화면에서 확인했다. 운영 화면에도 같은 원인이 있다고 단정하지 않는다.

- 검토 화면이 OSM의 상대 층 `layer`를 미터 높이로 환산해 연결된 조각 사이에 6m 단차를 만들었다. 이 환산을 제거하고, 지상 연결점까지 연속적인 검증용 높이 프로필을 적용했다.
- 자료가 교량 구간 중심으로 구성되어 진입부·일반 연결 도로가 누락되었다. 특히 한강대교의 노들섬 연결 도로 `osm:65370728`, `osm:65370731`이 빠져 있었다. 실제 OSM 공유 노드로 연결되는 도로 264구간을 추가해 검토 입력은 270구간에서 534구간이 되었다. 임의 직선은 생성하지 않았다.

비교 화면의 기존 처리는 초기 자료·기존 처리이며, 개선 화면은 연결 자료 보강까지 포함한다. 도로 폭 일부, 지형, 상판 높이 및 상세 구조는 미실측이다. 소스별 도로 ID·상대 층 정보가 동일한 좌표에서 교차한다는 이유만으로 실제 도로 연결을 뜻하지 않는다.

## 검증 및 한계

- 공통 도로·높이·교차로·건물 제외 검사 63개 통과.
- 지역 전환 중 도로·차선 교체 검사 2개 통과.
- 기존 부동산 UI 검사 12개 통과. 합계 77개.
- TypeScript 검사 및 Vite 전체 빌드 통과. 기존 큰 청크 및 테스트 환경의 경고는 남아 있다.
- 서버 변경 파일은 AST 구문 검사만 수행했다. 백엔드 실행, DB 접속 및 데이터 수정은 하지 않았다.
- 격리된 새 브라우저에서 공통 4장면·교량 34곳을 렌더링했다. 확인한 교량 접속점의 높이 단차 및 오류 로그는 0이었다.
- 한강대교는 실제 OSM 노드 그래프에서 초기 4개로 나뉜 입력이 연결 도로 보강 후 한 네트워크로 연결된다. 반대 방향 차로 등은 별개 연결 요소일 수 있으므로 모든 교량의 요소 수를 1로 강제하지 않는다.

초기 보고서의 WebGPU/WebGL 전체 장면 검사는 이전 로컬 구현의 결과다. 이번 운영 기준 통합본에서 그 검사를 다시 수행했다고 보고하지 않는다. 운영 드론/부동산 화면의 해당 위치, 외부 API 지연, 기존 보존 캐시 및 실제 높이는 추가 확인이 필요하다. 배포 후 무영향을 절대 보증하지 않는다.

## 운영 배포가 보류된 이유

저장소 `AGENTS.md`는 배포 스크립트를 포함해 AI가 저장 데이터 삭제를 직접·간접 실행하는 것을 금지한다.

읽기 전용 소스 조사에서 `backend/app/main.py`의 시작 이벤트가 `_admin_retention_loop`를 즉시 실행하고, 방문 기록·종목 검색·허브 이벤트·알림 통계·글로벌 TOP100 순위 저장소의 삭제 함수를 호출하는 것을 확인했다. 집계 재생성에도 삭제 및 `INSERT OR REPLACE`가 있으며, TOP100 시작 작업도 같은 종류의 교체 저장을 사용한다.

Render의 현재 자동 배포는 서버 재시작을 수반한다. 따라서 main 병합·push 또는 운영 배포 API를 AI가 실행하면 금지된 저장 데이터 삭제를 간접 실행할 수 있다. 운영 배포 트리거는 실행하지 않았으며, 관리자·DB 비밀 설정은 읽거나 출력하지 않았다.

소유자 측에서 데이터 보존을 전제로 시작 작업 전체와 요청 경로의 삭제·교체 저장을 정리하고, AI 자격 증명의 읽기 전용 권한을 실제 검증해야 한다. 보존 방식은 기존 정보를 덮어쓰지 않는 추가 이력과 읽기 전환을 검토해야 하며, 이 문서에는 삭제 명령이나 우회 실행 절차를 제공하지 않는다. 현재 권한 분리가 검증되었다고 주장하지 않는다.

## 남은 개선 순서

| 우선순위 | 과제 | 진행 조건 |
|---|---|---|
| 높음 | 데이터 보존을 충족하는 배포 경로 | 소유자가 시작 작업·저장 권한 및 보존 방식 검증 |
| 높음 | 신고 교량의 운영 화면 재현 | 드론/부동산 화면 구분, 선택 위치·주소와 공급 자료 확인 |
| 높음 | 교량 상판 실측 Z·접속부 경사 | 정밀도로지도 좌표계·수직 기준 확인 후 적용 |
| 높음 | IC 진입·진출·일방통행·회전 제한 | 공식 연결 정보와 방향을 전체 주행 경로에 반영 |
| 중간 | 고가 도로와 건물의 실제 3D 충돌 | 높이 범위를 포함한 입체 판정 |
| 중간 | 원천 누락·부분 응답·보존 캐시 | 기존 저장 자료를 지우지 않는 보강·버전 선택 |
