# 단지 기준 원본 도면 검색과 즉시 적용

`삼익 403동` 등 개별 동 이름이 원본 도면 검색에 섞이고, 원본을 찾은 뒤에도
면적 표기 차이와 주택형 선택 대기·판독 실패가 같은 경고로 표시되던 문제를 수정했다.
사용자의 최신 지시에 따라 완전한 치수 일치와 95% 지표는 진입 필수 조건이 아니다.

## 적용 방식

- 검색은 대표 단지명 + 법정동 + 지역으로 한다. `수서동 + 삼익`의 원본은
  네이버 단지 668이며 도곡동의 동명 삼익과 구분한다. 동 번호는 `/units`와 층·세대
  선택에만 사용한다. 건축물대장이 `404동`만 반환해도 외곽 정보의 부모 단지명을 보존한다.
- 단지 확인을 마친 뒤 도면을 검색한다. 같은 단지의 다른 동·좌표는 같은 목록과
  진행 중 검색을 공유한다. 다른 단지로 이동하면 이전 요청의 결과를 적용하지 않는다.
- 전용면적의 작은 기록 차이는 같은 원본 주택형으로 연결한다(최대 0.15㎡).
  같은 면적의 다른 A/B 타입은 자동으로 하나를 단정하지 않는다. 세대 면적이 없으면
  확보된 첫 원본 주택형을 기본 선택해 인테리어를 구성하고 다른 주택형도 선택할 수 있다.
- 방별 면적 표기와 인식 구획의 차이는 전용면적과 실제 실내 영역으로 축척을 보정한다.
  방 좌표·벽·비율을 유지하고 평균 도면·템플릿으로 대체하지 않는다.
- 공간별 치수·문 폭·보행 연결은 진단 정보다. 구조가 대체로 일치하면 인테리어로
  진입한다. 보행 연결이 부족한 구조도 가구를 배치한 3D 공간별 검토로 열 수 있다.
  해석할 수 없는 이미지와 손상된 좌표를 임의 구조로 생성하지 않는다.
- 원본 미발견·주택형 선택·분석 통신 오류·공간 판독 실패를 구분해 표시하고,
  `검증된 원본 도면을 아직 적용하지 못했습니다`라는 포괄 경고는 제거했다.

## 수서 삼익 검증

배포 전 운영 API에서 `삼익 403동`은 `not_found`, `삼익`은 원본 3종을 반환했다.
확보된 원본 3종은 모두 버전 7의 방별 면적 검사(`room_area_conflict`)에서 차단됐다.
버전 8에서는 원본 구조를 유지해 다음과 같이 적용했다.

| 원본 주택형 | 전용면적 | 적용 | 원본 벽 경계 F1 |
| --- | ---: | --- | ---: |
| 68 | 49.20㎡ | ready | 90.91% |
| 86 | 60.00㎡ | ready | 99.73% |
| 115 | 84.48㎡ | ready | 98.68% |

위 점수는 벽 경계 일치 지표이며 실측·용도 판독 정확도 인증값이 아니다.
68형은 95% 미만이어도 요청대로 구조를 적용해 진입한다.

로컬 실제 Chrome에서 403·404·405동 각각 대표 단지 `삼익`, 법정동 `수서동`,
내부 단지 ID `11680:수서동:708:삼익`으로 검색되는지 검사했다. 404동은 대장 이름이
동 번호만 있는 조건이다. 49.06㎡ 기록과 49.20㎡ 원본의 연결도 검사했다.
3종 모두 필수 주방 설비가 있는 원본 인테리어로 진입했고, 68형은 보행,
86/115형은 공간별 3D 검토로 확인했다. 원본 미발견과 판독 실패의 서로 다른 안내도 확인했다.

원본 17종의 자동 구조 검증과 인테리어 변환, 주방 설비 배치, 남은 벽 2,695개
광선 검사를 통과했다. 독립 백엔드 테스트 45개와 프런트엔드 단지·도면·벽·보행
회귀 검사, TypeScript 검사를 통과했다. 테스트는 메모리와 이미지 자료만 사용했다.

Chrome/RTX 3070 ANGLE D3D11, viewport 1440×1000, 실제 출력 1425×1000,
DPR 1에서 각 5초 구간 평균 59.58~59.98fps, 최저 1초 58.97~59.96fps,
p95 16.8ms, p99 최대 16.9ms, 최대 프레임 33.4ms였다. 공간 전환 준비에는
최대 117ms 기록이 있어 전 구간 50fps 달성으로 보고하지 않는다. 해상도를 낮추지 않았다.

재현: `backend/tests/test_floorplan_pipeline.py`, `backend/tests/test_floorplan_area_geometry.py`,
`frontend/scripts/test-apartment-drawings.ts`, `frontend/scripts/test-floorplan-sources.ts`.
로컬 상세: `tmp/floorplan-complex-20261101/`.

## 데이터 보존과 배포

운영 DB 쓰기·삭제·초기화·마이그레이션이 없다. 공개 단지 정보와 공개 도면 API만
읽었고 기존 저장 데이터와 별도 작업 중인 inventory 변경은 배포 커밋에 포함하지 않는다.
운영 배포 후 원본 검색·분석과 실제 운영 렌더러의 진입 결과를 추가 기록한다.

배포 커밋 `631f5208e81af4aea216d126edd9efe5eb10fc70`은 Render
`dep-dbjaas6q1p3s73aiq8v0`에서 2026-11-01 02:37:58 UTC에 live가 됐고,
운영 health가 같은 커밋을 반환했다. 운영 API에서 `삼익`, `삼익 403동`,
`삼익아파트404동`, `수서동 삼익 405동`의 원본 ID·주택형 키가 모두 같았다.
세 원본의 이미지 해시가 일치했고 native Tesseract 분석도 버전 8 ready였다.
운영의 벽 F1은 68형 90.91%, 86형 99.72%, 115형 98.68%이며 평균 도면을 쓰지 않았다.
native 분석으로 다시 검사한 주방 설비와 벽 광선 421개도 통과했다.

운영 Chrome 검사에서는 지도·대장·세대 입력만 고정 fixture로 격리했다.
원본 검색·이미지·분석은 운영 API를 직접 호출했고 실제 운영 JS로 세 인테리어에
진입했다. 이는 실제 드론에서 모든 동을 클릭하는 전체 지도 여정의 검증과 구분한다.
같은 출력/GPU 조건의 각 5초 구간 평균 59.98fps, 최저 1초 59.96~59.97fps,
p95/p99 16.8ms, 최대 프레임 16.9ms였다. 공간 전환 준비에는 최대 117ms 기록이 있다.
상세 결과는 동명의 JSON과 `tmp/floorplan-complex-20261101/production-browser/`에 기록했다.
